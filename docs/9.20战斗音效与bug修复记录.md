## 二、行为改动 A：战场四星技音归属「仅自身」→「自身 + 友军」

用户口径：3v3 里**队友的四星技能音自己也要听得到**。

`scenes/battle/BattleVfx.gd` 里**两个归属判据并存**（混用就是 bug）：

| 判据 | 位置 | 含义 |
|---|---|---|
| `_is_local_owned_unit(sim_uid)` | :1387 | **仅自身**，`owner_slot == local_slot` |
| `_is_own_or_ally_unit(sim_uid)` | :1426 | **自身 + 友军**，`GameConstants.team_of_slot(owner) == team_of_slot(local_slot)` |

- `_is_own_or_ally_unit()` 在 `team_mode` / `team_active` 为假（单人局）时**直接回落**到前者，
  所以单人玩法行为不变。
- 本批把**普通四星战斗技音**（施法型 / 攻击型 / 佣兵 / 三个非施法型）统一改走
  `_is_own_or_ally_unit()`；判定点共 6 处（施法派发 :413、四条 :930/:971/:980/:988、母灵 :1013）。
- `_is_star4()` 从 **`_state`** 取 `star == MAX_STAR`（`GameConstants.MAX_STAR` 即 4），不看 `_config`。
- `enemy_formation_hit`（己方法阵受击）沿用同一 gate。

### ★ 人王相关**刻意不跟着放宽**（用户 9.20 明确反悔）

`_play_human_king_reward()`（:1328-1344）与「人王阵亡音」（:1277）**仍然只用
`_is_local_owned_unit()`**。理由两条：

1. 用户明确要求人王那套仍是**只有自己看得到/听得到**；
2. 技术上也拿不到 —— 人王的成长层数存在 `king_growth_stacks`，**它根本不在棋盘上报的 payload 里**，
   队友端无从知道对方人王涨了几层。

## 三、行为改动 B：三条「非施法型」技能音的触发点

寄生灵 / 自爆灵 / 死侍这三家的技能在模拟器里**不产生 `skill_ready` 上升沿**，所以进不了
`_play_skill_cast_vfx()` 那条统一派发路径，各自挂在自己的**真事件**上：

| 棋子 | 挂在哪儿 | 关键坑 |
|---|---|---|
| 寄生灵 `undead_parasite` | `_refresh_battle_vfx()` 的**「新 uid 出现」分支**（`prev.is_empty()` 且 `id.contains("_parasite_")`） | ★★ **不能拿分身自己判归属/星级**：分身是死者的 `duplicate(true)`（`BattleSimulator._maybe_spawn_parasite_clone`），它的 `id` / `owner_slot` / `star` **全是死者的**（`id` 甚至是死者的**单位 id**，不是 `undead_parasite`），只有 `team` 被改写成击杀方。→ 必须按 `team` 回头扫 `_state` 找**本体**（`id == "undead_parasite"` 且 `alive`），拿本体的 `uid` 过 gate；**找不到就一声不响**（宁可少响，也不要把音算到别人头上）。 |
| 自爆灵 `undead_bomb` | `_refresh_battle_vfx()` 的**死亡分支** → `_maybe_play_bomb_skill_sfx(id)` | `id` 就是这只自爆灵自己的 sim uid（此刻它还在 `current` 里）。 |
| 死侍 `human_death_servant` | `_play_opening_unit_vfx()` 里 `left_neighbor_sacrifice` **且 `_exact_skill_target()` 解析出目标**的那一支 | ★ **绑到人才响，没绑到不响** —— 所以挂在「目标已解析」分支里，不是无条件播。★ 绑定发生在开战首帧**之前**（`BattleSimulator._apply_opening_unit_skills`），而**首帧是「播种帧」、正常 diff 整段被跳过** → 只能在这个补建分支里补，普通 diff 根本挂不上。 |

三家都只做「归属 + `star == 4`」两道门，取值入口仍是 `SfxService.star4_cue_for(uid, true)`。

## 五、bug 文档第 1 条：设置页改成英文必须**当场**变英文

**现象**：设置页里把语言切成 English，页面文案不变英文，要退出重进设置页才生效。

**根因**（★ 不是「没人听信号」）：`SettingsScreen._build()` 里每一处都是 `text = tr("settings_xxx")`。
`tr()` 返回的是**已经翻译好的字符串**，**键名在这一步就丢了**；Godot 的自动翻译只会拿节点上现存文本
去查表，键名丢了就再也查不回去 —— 于是 `locale_changed` 之后这些 `Label` 原样停在中文。
此前 `_on_locale_changed()` 只刷了语言按钮的选中态，没管其余文案。

**修法**（沿用本仓既有约定 `CarrotCampPanelV3._on_locale_changed()`）：**整个 `_build()` 重建**。
页面本来就没有需要保留的瞬时状态（各开关值都存在 `PlayerProfile` 里），重建是安全的。

★ 重建时 `_build()` 开头必须**先 `remove_child(child)` 再 `queue_free()`**：
只 `queue_free()` 的话旧节点要到**帧末**才真离树，同一帧里新旧两套内容会并存。

**新门禁** `tools/settings_locale_live_check.tscn`（4 项）：

| 断言 | 内容 |
|---|---|
| 中文态下页面应有中文 | 切到 zh 后页面里必须有 CJK |
| 切到英文后不应残留中文 | 切到 en 后 CJK 条数 = 0（排除语种名 `中文` / `English` / `✓ …`） |
| 英文态不应出现未翻译的键名 | 不出现 `settings_*` / `menu_*` 字面键 |
| 切回中文后应立刻显示中文 | 切回 zh 中文必须回来 |

**变异验证**：修复前跑 → **FAIL（残留 16 条中文）**；应用修复 → PASS（`checked=4 failures=0`）；
把 `_on_locale_changed()` 改回 `_refresh_lang_buttons()` → **又 FAIL**（证明门禁真的抓得住）。
最后已把文件还原成修复版，sha256 `d3c5934fdc02a68b5b409072c0208c14283f2eaaa46a58dc422b3dd2aa5bfe1d`。

### 7.6 如实认领：`asset_delivery` 本批 +2（卡图被重编码）

`tools/asset_delivery_check` 是**唯一被本批推动**的计数型门禁：11 → **13**，
多出来的 2 条正是本批补过字的 `assets/ui/treasure_cards/哀鸣共鸣.png` 与 `哀鸣共鸣_en.png`。

**归属证明（拿改前备份逐条对，不是猜的）**：

| 文件 | 改前字节 | bundle 期望 | 改后字节 | 结论 |
|---|---|---|---|---|
| `哀鸣共鸣.png` | **2526982** | 2526982 | 1972958 | 改前**完全吻合** → **本批新引入** |
| `哀鸣共鸣_en.png` | **2535168** | 2535168 | 1982950 | 同上 |
| `打断锁链.png` | 2066721 | 2568275 | 2066721 | 改前就**已经不符** → 既存（9.13 那批的同类残留） |

**为什么差这么多**：PIL 重存整张 PNG 时用了与原图不同的 zlib 压缩策略，文件小了约 22%。
**但这不是画质损失** —— 逐像素核对过：

- 尺寸 `1086×1448`、模式 `RGBA`、像素缓冲长度 `6290112` **三项完全一致**；
- 真正变化的像素只有 **623 / 1572528（0.0396%，中文）** 与 **443（0.0282%，英文）**，即补上去的那个「5」；
- PNG 是**无损**格式 → 压缩率变好 ≠ 画面变差。

**唯一副作用**：原图带 `dpi` / `gamma` 两个元数据块，重存后没了。Godot 的 PNG 导入器不读这两个块
（也不会进 `.ctex`），**对渲染无影响**。**下次重打包（重建 `assets.bundle.json`）这条红自动消失**，
与 9.17 那 5 条 BGM 的处置方式相同。

## 十、第三批：寄生灵分身音时机 + 死侍开局绑定音（用户实测反馈）

用户从**真机试玩**报回两条，表面上一个是「音**多**响了」、一个是「音**不**响了」，
其实是**同一处缓存没重播种**加上**一条判据写错**。

### 10.1 现象

| # | 现象 | 用户口径 |
|---|---|---|
| 1 | 寄生灵（`undead_parasite`）的技能音**开局就响** | 应该只在「**召唤出敌方分身**」那一刻响 |
| 2 | 死侍（`human_death_servant`）**开局绑定音不响** | 要判定是「死侍根本没绑人」还是「绑了但音没响」 |

### 10.2 根因（两条，第一条是共因）

**(1) VFX 差分缓存是实例字段、一局只播种一次 → 再开一局整段播种帧演出静默。**

`_vfx_seeded` / `_vfx_prev_units` 挂在 BattleVfx 实例上，只在 `_vfx_seeded == false`
的那一帧走一遍 `_play_opening_unit_vfx()` 然后置真。同一个 BattleScreen 实例上**再开一局**
（或切看另一队回放）若不重播种，**播种帧专用分支整场不会再跑** ——
凡是「开局就发生」的演出全部静默：死侍开场绑定音 / 绑定特效、血契连线、护盾嘲讽。

officetest 的**编辑态预览**先占掉了播种帧，于是真正开演示时播种帧已经用掉 → **死侍绑定音不响**。
→ 结论：**不是「死侍没绑人」**，模拟器侧绑定照常发生（`_apply_opening_unit_skills`），
纯粹是演出端漏播。

**(2) 寄生灵分身按「新 uid」（`prev.is_empty()`）判 → 回放的 roster 会提前把分身塞进 `_state`。**

回放的第一帧 roster 会把**战斗中段才出生**的分身**提前**放进 `_state`（`alive=false`），
于是「进演示的第一帧」prev 为空 → 被误判成**召唤时刻**（**开局就响**，用户报的现象）。
反过来在**真 3v3**路径上，分身早在 prev 里了 → 真正出生那一帧 prev 非空 → 按此判**整场不响**。

> ★ 正确判据是「**首次活着出现**」，与「新 uid」不是一回事。

### 10.3 修改

`scenes/battle/BattleVfx.gd`

| 改动 | 说明 |
|---|---|
| 新增字段 `_parasite_spawn_announced: Dictionary` | 按 uid 记「这一局已经报过」，每局清空 |

### 10.6 ★★ 事故与教训：变异体是**解析期错误**时 Godot 会**静默挂死**

**经过**：第一次跑变异脚本，卡在 M0 很久没输出，被当成卡死 SIGTERM 掉；
而脚本是**先把变异体写盘、再跑探针、`finally` 里还原** —— 进程被硬杀时 `finally` 不执行，
于是**磁盘上留下了变异体**（两个源文件一度回到修复前状态）。

**根因**：M0 / M2 把 `_reseat_vfx_diff_for_new_battle()` 的函数体替换成**空串** ——
GDScript 的**空函数体是解析期错误**，而**解析期错误让 Godot 不打印、不退出**
（本仓既定坑：门禁脚本解析期报错 = 进程静默挂死，只能 taskkill）。
所以「跑很久」不是慢，是**挂住了**；两次都死在同一条 M0。

**三条修法**（已固化进脚本）：

1. **变异体不许产生空函数体** —— 改成 `pass`：语义等价（什么都不清），但能被解析。
2. **探针调用加硬超时**（`PROBE_TIMEOUT_SEC = 180`），超时记为一行 `TIMEOUT` 并按「变红」处理；
   基线若 TIMEOUT 直接判「无法判定」中止 —— 不会再把整套测试拖死。
3. **动盘前先落 `<file>.mutbak`**，脚本**启动时先检查残留并自动还原**，另注册
   `SIGINT` / `SIGTERM` 处理器做还原。于是**即使整棵进程树被硬杀，下一次运行也会自动回到干净态**，
   并且启动时会打印当前 sha256 与 known-good 的比对（不一致就直接中止，拒绝在脏基线上跑变异）。

> 教训一句话：**变异测试的风险不是「没变红」，是「把工作树弄脏还看不出来」。**
> 硬杀安全网（备份 + 启动自愈 + 信号处理）+ 超时，比变异覆盖率更先要有。
