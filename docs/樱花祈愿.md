# 皮肤祈愿（樱花 / 夜荧光）

商城里用钻石抽碎片，集满 10 片自动解锁那张棋盘皮肤。2026-10-31 拍板并实现，两张同一套规则：

| 皮肤 | 商城标签 | 碎片 | 刷新特效 |
|---|---|---|---|
| 樱花 `prep_skin_sakura` | 樱花祈愿 | 樱花瓣 | `petal` 花瓣吹散 |
| 夜荧光 `prep_skin_nightwisp` | 夜荧光 | 发光黄星星 | `wisp` 发白的荧光飞散（加亮混合，用户定的，别改成浓黄） |

加第三张：图放 `assets/skins/prep/<id>/`、`data/prep_skins.json` 登记、`data/shop.json` 加一条 `enabled=false`、`skin_draw.SKIN_IDS` 加 id、`SkinWishDialog._themes()` 和 `ShopScreen.WISH_CATEGORIES / WISH_BANNERS` 各加一段、背景图放 `assets/ui/shop/<名>_wish_bg.png`。

## 规则（拍板）

| 项 | 定下来的 |
|---|---|
| 每抽 | 100 钻石 |
| 出碎片 | 60%：1 片 30% / 2 片 21% / 3 片 9%（出碎片时 1:2:3 片按 50:35:15） |
| 没出碎片 | 游戏币（账号 `coin`，不是局内金币）200～300，按 10 一档随机，40% |
| 保底 | 第 10 抽碎片不够 10 片就直接补满 ⇒ **一张皮肤最多 1000 钻石** |
| 集满 | 同一笔事务里发皮肤归属，自动解锁，不用手动合成 |
| 已拥有 | 不能再抽（不卖没用的碎片），按钮变「立即使用」 |
| 十连 | 不做 |

模拟（10 万次）：平均约 904 钻石集齐，41% 的人不到 10 抽集齐。

「1000 钻保底」曾有两种理解：A 每 10 抽保底 1 片（集齐平均 6500、最多 10000 钻）、
B 1000 钻封顶集齐。按 B 做 —— 和抽宠物（最多 750 钻一只）价位相当。

## 谁说了算

全部在账号服务器（`backend/app/skin_draw.py`），客户端只发「抽一次」+ 防重复扣费的 `client_draw_id`：

- 钱包行锁 → 查 `client_draw_id`（重发原样回上次结果，不重复扣钱）→ 扣钻石 → 发碎片或游戏币 → 集满发归属 → 写进度和回执，**同一个事务**；
- 随机数用 `secrets`（加密随机）；
- 表：`database/042_skin_draw.sql`（`skin_draw_progress` 碎片 / 抽数，`skin_draws` 每抽回执）。碎片是数量，不进 `player_entitlements`；
- 接口：`GET / POST /v1/me/skins/{skin_id}/draw`，`skin_id` 走路径，以后别的皮肤祈愿不改接口（加进 `skin_draw.SKIN_IDS` 即可）；
- 流水名目 `skin_draw`（`shop.SOURCES`）。

🔴 每张祈愿皮肤都必须在 `data/shop.json` 登记成 `enabled=false`（`shop_prep_skin_sakura`、`shop_prep_skin_nightwisp`）：不在目录里的内容免费，
删掉那一条樱花就变成谁都能用，而抽奖接口会直接报错拒绝（不收钱卖空气）。

## 客户端

| 文件 | 干什么 |
|---|---|
| `scenes/menu/ShopScreen.gd` | 分类「樱花祈愿」「夜荧光」（宠物后面）：祭坛横幅 + 浮动卷轴 + 碎片进度 + 「进入祈愿」/「立即使用」 |
| `scenes/menu/SkinWishDialog.gd` | 全屏祈愿（按 `skin_id` 换主题）：祭坛背景，皮肤卷轴悬在祭坛上方浮动（Sprite2D，小数像素才浮得顺），十片碎片围成花冠；左卡预览、右卡概率公示 |
| `scripts/autoload/AccountManager.gd` | `fetch_skin_draw_state` / `draw_skin_shard` |
| `scenes/main/Main.gd` | 商城页的 `wish_requested(skin_id)` → 打开对应主题的弹窗，抽完刷新商城 |
| `assets/ui/shop/sakura_wish_bg.png`、`nightwisp_wish_bg.png` | 祭坛背景（用户出的图，`assets/` 不进 git，美术包里交付） |

演出按分量分三档：等结果时卷轴蓄力（抖、发亮，至少 0.5 秒）；没出碎片 = 游戏币数字从卷轴前升起；
出碎片 = 卷轴被顶一下、迸出花瓣，花瓣一片片飞进花冠；集满 = 白光 + 满屏花瓣 + 解锁卡片（可当场装上）。
动画从来不决定奖励。

**概率公示**写死在 `SkinWishDialog.gd`（两张共用）（Google / Apple 要求付款前可见），
`backend/tests/test_skin_draw.py::test_odds_shown_to_players_match_the_server` 钉着它和服务端常量一致。改概率两边一起改。

## 已知局限

- 备战页的皮肤列表只认商城目录里「在卖」的皮肤，樱花（和冰雪一样 `enabled=false`）在拉到 403 之前会显示成可用，
  点「使用」才被服务器挡回、改成「去商店」。冰雪皮肤一直是这样，没在这次改。
- 后端测试在本机没有 pytest 环境，`test_skin_draw.py` 用桩脚本跑过逻辑（8 条全过），没连真库。
