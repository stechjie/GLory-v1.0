## §1 设计决策：为什么每只宠物一个独立播放器，而不是走 SfxService 的共享池

`SfxService` 的播放器池（`VOICE_COUNT=8` + `RETRIGGER_GUARD_MSEC=40`）是给「UI 反馈 / 战斗技能」这类「同一时刻最多几声、且 40ms 内同 cue 只响一次」的场景设计的。脚步声的需求正好相反：

- **所有宠物独立播放**：大厅里最多 `MAX_PETS=5` 只宠物，它们各自在 SubViewport 里独立走动，迈步时刻彼此不同步。若都走 `SfxService.play(CUE_PET_FOOTSTEP)`，40ms 全局重触发保护会在「多只同帧迈步」时只保留第一声、吞掉其余 —— 直接破坏「独立播放」。
- **停下即静默**：脚步是短促一次性音（0.18s），只有行走时按步频触发；不走路就不触发，声音自然结束，不需要循环音那条路。

因此做法：每只宠物在 `_spawn_pet()` 里挂一个**自己的** `AudioStreamPlayer`（`PetFootstepPlayer`，挂在 pet Node3D 下，**不是** root 的子节点，名字也刻意避开 `GlorySfxVoice*` / `GlorySfxLoopVoice`），脚步音直接播在这个私有播放器上。`Cue_PET_FOOTSTEP` 只用作「素材文件路径的来源」（`SfxService.cue_path()` 取路径），真正播放不经过共享池。

这样也**不会污染** `audio_sfx_check` 的「播放器池 == 8」断言：那条门禁数的是 root 下以 `GlorySfxVoice` 开头的节点，私有播放器既不在 root 下、名字也不撞前缀，计数稳稳保持 8。

## §2 步频与触发点

- `FOOTSTEP_INTERVAL := 0.36` 秒/步，与 `MOVE_SPEED=1.15` 单位/秒对齐，避免脚底打滑（每秒约 3.2 步，对小型宠物合理）。
- 纯静态函数 `advance_footstep(entry, delta)` 负责「这一个帧该不该响」：只在 `entry.state == "walk"` 时累加 delta，跨过阈值返回 `true` 并**取模**复位（避免长帧把一步拆成偏移）；非 walk 状态直接清零累计并返回 `false`。
- 把它抽成**静态纯函数**是为了让门禁不经过实例化整棵 `MainMenuPet`（那只为了出 3D 舞台要加载宠物模型，headless 太重且易失败）就能直接驱动验证步频与独立性。
- 触发点在 `_step_pet()` 的 `"walk"` 分支里：每次 `_process` 推进位移后调用 `advance_footstep`，返回 `true` 就 `_play_footstep(entry)`。
- `_play_footstep` 先过 `Presentation.ui_sound_allowed()`（与全局静音门同源：关掉「界面音效」或 Master 总线静音时一声不响、也不记账），再在私有播放器上 `play()`；要求播放器已在树里、流非空才播。

## §3 素材：一只「软质爪步」

`assets/audio/sfx/lobby/pet_footstep.wav`（44.1kHz / 单声道 / 16-bit PCM，0.18s）是**以用户提供的真实现场素材重设计的**：`C:\Users\WINDOWS\Desktop\音效｜草地雪地脚步声｜音频.mp3`（草地 / 雪地脚步声）。脚本 `work/_qa_922/gen_pet_footstep_from_mp3.py` 负责解码 + 切片 + 柔化（见 §7）。

设计要点（与该 MP3 源一致，比 9.26 首版合成的「偏嘈杂」版本更自然）：

- 取素材里**最孤立、最干净的一段单步**：以全曲振幅峰值为落地冲击点，向前 0.03s、向后 0.15s 切出 0.18s 窗口；
- 柔化去刺：两级 2 阶低通 @ 7kHz（biquad，Q=0.707）—— 去掉 MP3 高频压缩噪声与任何「沙沙」的刺耳感；首尾 5ms 淡入淡出避免爆音；
- 整体峰值压到 0.5，坐到 UI 音效之下，不抢其它提示音；
- 短促无尾音，避免「停下还在响」的错觉。

各宠物在代码里随机微调 `pitch_scale`（0.92~1.08），避免多只同帧迈步听起来像同一次机械复读。素材本身只这一份。

## §4 门禁 `pet_footstep_check`（22 项，先红后绿）

新建 `tools/pet_footstep_check.gd` + `.tscn`，验证「独立播放 + 移动发声 + 停下静默」会被静默写错的那几件事：

1. cue 登记 + 素材文件存在 + 能被 `load` 成 `AudioStream`；整张 cue 表 75→76。
2. 生产调用点：`MainMenuPet` 必须引用 `SfxService.CUE_PET_FOOTSTEP`（否则死登记）；且不得出现 `SfxService.play(`（否则又接回共享池）。
3. 结构：播放器命名不撞 `GlorySfxVoice*` / `GlorySfxLoopVoice`，且挂在 pet Node3D 下（不污染 `audio_sfx_check` 的「播放器池 == 8」断言）；每只宠物各一个。
4. 步频行为：行走约 3 个步频区间响约 3 声（2~4 容浮点），且远少于帧数（不是每帧都响）；idle 状态零发声、累计清零。
5. **独立性行为**：5 只宠物在同一个「帧」里同时跨过步频阈值，应当各自响一声（5/5）—— 这正是共享池做不到的。
6. 静音门：关掉「界面音效」时 `_play_footstep` 一声不响、也不记账（收尾还原 profile 磁盘，不污染下一跑）。

## §7 二次修订：改用真实现场素材重设计（覆盖首版合成音）

用户反馈首版「合成的脚步声偏嘈杂、刺耳」，要求改用其提供的草地 / 雪地脚步声 MP3 作为原材料重新设计，并重跑交付（覆盖桌面 `9.26交付_*` 三个夹）。

### 7.1 解码路径（本机关键约束）

本机**没有** ffmpeg / ffprobe / pydub / scipy，只有 Python 3.13 + numpy 2.5.3。可用的纯原生解码方案：

- `pip install miniaudio`（v1.71，自带 libminiaudio，无需系统 ffmpeg），装进隔离 venv：`C:\Users\WINDOWS\.workbuddy\binaries\python\envs\default`。
- 该 MP3 带 ID3v2.4 标签（FFmpeg/Lavf 写入），而 miniaudio 的 dr_libs 后端对这条标签解码返回 -1 失败；**先剥离 ID3 标签再对裸帧 `miniaudio.decode(...)` 即可正常解出 44.1kHz 单声道 1.0s PCM**（44100 样本）。

### 7.2 切片与柔化（`gen_pet_footstep_from_mp3.py`）

1. 找全曲振幅峰值（落地冲击，t≈0.232s），切 `[峰值-0.03s, 峰值+0.15s]` 共 0.18s；
2. 两级 2 阶低通 biquad @ 7kHz（Q=0.707）柔化去刺；
3. 首尾 5ms 线性淡入淡出防爆音；
4. 峰值归一化到 0.5，写 16-bit PCM 单声道 WAV。

最终 10ms-RMS 包络（attack→decay，无尾爆）：`0.09 0.20 0.29 0.29 0.16 0.06 0.09 0.04 0.04 0.03 0.08 0.09 0.12 0.05 0.01 0.02 0.01 0.03` —— 起音 ~40ms 到峰、随后自然衰减到近静音，中途一段草地 / 雪地的轻微二次质感（远低于主冲击），整体自然不刺耳。
