**修法**

### 第 3 条：手机切后台回来已进备战，且没拿到回合战斗金

### 第 5 条：手机对局卡屏，要重启重连

两条同一个根因链（详见 `scenes/battle/BattleScreen.gd` 头部注释）：

1. 本场景所有 deadline 走**墙钟** `Time.get_ticks_msec()`；切后台再回来墙钟一次跳几分钟
   ⇒ 每个 deadline 瞬间过期 ⇒ 回放被判 `battle_playback_timeout`、准备被判 `battle_prepare_timeout`。
2. `_fail_team_replay(...)` 发出 `{"kind":"team","player_wins":false,"error":...}`；
   `Main._on_team_battle_finished` 走到 `if result.has("error")` ⇒ `_show_menu()`，
   **没人去要权威结算**，回合战斗金永不发放。
3. 另一条并行路径：重连握手期间收到服务器新回合 payload ⇒ `_begin_resume_identity_wait` 把 payload 挂起 ⇒
   重连成功后协程不回来认领 ⇒ `_on_team_battle_finished` 开篇早退 ⇒ 直接落备战，同样跳过结算。
4. 卡屏：恢复帧 `delta` 是积压值，回放在单帧里补几十帧、每帧还要起特效。

**修法（四层，任一层单独生效都不会再丢金币）**

- `BattleScreen.gd`
  - 自攒**只在前台推进**的单调毫秒表 `_mono_msec`；`NOTIFICATION_APPLICATION_PAUSED` 时 `_mono_frozen = true`
    （`_tick_monotonic_clock` 见冻结即 return —— 即便平台在后台仍投帧也一格不走），
    `NOTIFICATION_APPLICATION_RESUMED` 时解冻 + `_drop_resume_frame()`。
  - 恢复帧 `delta` 夹到 `RESUME_DELTA_CLAMP_SEC = 0.25`；回放补帧加 `MAX_REPLAY_FRAMES_PER_FRAME = 6`
    + 被砍时把 `_sim_accumulator` 夹回 `SIM_TICK_SEC`（防死亡螺旋）。`_advance_spectate` 同样加。
  - 所有 deadline 的写入 / 比对改单调表；`Time.get_ticks_msec()` 只留在**纯统计**处。
- `scenes/main/Main.gd`
  - 新增 `_commit_prep_round_locally(payload)`：服务器已推进到本回合（`completed_round` 对上、
    协议版本对上）时，本地直接认领权威结算并进备战。
  - `_finish_server_authoritative_team_battle()` 的 `if result.has("error")` 分支加兜底：
    权威 state 已含本回合 ⇒ 不报错、继续玩。
  - `_on_battle_finished()` 开篇加第二道兜底：`battle_*` 类错误在组队模式下**不作为结果相信**，
    转 `_on_team_battle_finished` 要权威结算。

### 第 4 条：对局头像改上下两行；羁绊/宝藏下移

### 第 6 条：手机背包点第一个「人王」头像跳到最后一个

- **根因**（★ 只在 Android 双路投递下发生，headless 单路测不出来）：
  `BagScreen._select_avatar()` 走 `_render()` **整体重建**网格 ——
  把**正在处理这次点击**的瓦片 `remove_child` + `queue_free`，再补一批新控件；
  新控件这一帧**还没布局**，全部堆在第一个格子上。
  Android 的 `emulate_mouse_from_touch` 会把同一次触摸**再投一路模拟鼠标**事件，
  它命中的是这批未布局控件里**最上层的那个**（子节点逆序 ⇒ 最后一个）⇒「点第一个，跳到最后一个」。
- **修法**（`scenes/menu/BagScreen.gd`）：把「选中」和「重建」拆开 ——
  - 新增 `_avatar_tiles` / `_pet_tiles`（id → 瓦片 Control）、`_apply_avatar_style` / `_apply_pet_style`。
  - `_select_avatar` → 只调 `_refresh_avatar_selection()`（重新上色 + 重画右侧详情），**不重建**；
    `_select_pet` 同理走 `_refresh_pet_selection()`。
  - `_render()` 仍在「切页签 / 重新拉数据」时重建，只是同时刷新两张索引表。

### 第 7 条：手机好友码输入框呼出键盘后自动隐藏

- **根因**：`FriendsScreen` 有 `REFRESH_SEC = 5.0` 定时 `_render()`，无条件 `queue_free` 重建列表

- **修法**：`_render()` 开头加 `if _list_box == null: return` + `if _is_editing_code(): return`；
  新增 `_is_editing_code()`（`_tab != Tab.ADD` → false；`_code_input` 无效 → false；
  否则 `_code_input.has_focus()`）。

## 方法学教训（本轮新增）

1. **`push_input` 收的是窗口坐标**：`stretch=canvas_items` 会按拉伸系数换算成画布坐标再命中测试。
   探针直接拿 `get_global_rect().get_center()`（画布坐标）去 push 会整体偏移 ——
   实测 1280×720（画布 1600×900，scale_y 1.25）时点第一个会点中**第九个**，看起来像产品缺陷。★ 必须先换算。
2. **「重建列表」不得发生在处理点击的那条路径上**：Android `emulate_mouse_from_touch` 会把一次触摸
   投成两路事件；第一路触发重建后，第二路命中的是**尚未布局**的新控件（全部堆在第一个格子，逆序命中 ⇒ 最后那个）。
   这是「点第一个跳到最后一个」的真机制，headless 单路测不出来。
3. **结构断言必须先剥注释**：本轮门禁自己的注释里就写了被禁用的 `_render()`，
   不剥注释会把说明当违规（假红）。
4. **变异只在「整条防线都拆掉」时才会红**，这是纵深防御的正常表现 ——
   要把它记成「redundant layer」并另设一条覆盖完整形态的变异，**不能**记成判据失效。
