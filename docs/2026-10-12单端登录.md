# 单端登录（本地待用户验收）

## 行为

新登录替换同账号旧会话。旧端收到 `kicked` / 4001，或 HTTP `409 session_replaced` 后，立即清除内存访问权限、关闭战斗连接和语音、停止自动重连并返回启动入口，显示账号在其他设备登录。当前为匿名账号体系，没有账号密码页面；保留本地匿名账号凭证和对局恢复记录，不自动注册新号。用户主动点击「在这台设备上继续」才重新登录。

后台续期携带原 `session_id`，不抢占新登录；旧会话续期在调用 Supabase 之前被拒绝。HTTP 和 WebSocket 均校验会话编号，旧端不能继续领取出战名片。房间使用已验签名片中的 `pid` 校验账号，不信任客户端自行填写的账号 ID；仍在线的重复账号请求被拒绝，入座函数也在修改房间前再次检查。

`login_sessions` 为持久化的账号会话代次表；在线连接仍由现有 `realtime.Hub` 管理。断线清理在线连接，保留会话代次以支持正常切网重连；退出房间只释放房间关系，不登出账号。明确登出才撤销会话，按账号与会话编号同时匹配删除，旧端迟到的退出不能删除新会话。应用被强杀时依赖连接关闭及已有 95 秒心跳超时清理，不依赖退出通知必达。

当前账号服务仍要求单进程单实例（已有 single_instance 约束）。数据库保存会话代次，重启不会恢复被撤销的旧会话。账号服务与战斗服务仍是两个进程：正常客户端收到顶号后立即断开战斗连接，战斗服务按既有掉线/恢复机制处理；此改动没有新增跨服务踢人 RPC。

## 测试和验收

自动检查覆盖登录替换、同会话续期、旧会话 HTTP/WS 拒绝、并发连接登记、旧连接 finally、条件登出、房间账号重复、客户端停止连接与自动重连，以及凭证/对局恢复记录保留。数据库单元用例使用替身，未连接生产 Supabase；SQL 迁移和双手机联网验收尚未执行。

用户测试建议：

1. A 端登录并停在大厅，B 端登录同一账号：A 端立即回启动页，B 端正常使用。
2. A 端在备战或战斗中重复以上操作：A 端退出画面并停止语音、无法再操作；不会自动重新抢登。
3. A 端停留一分钟，不点击继续：B 不被踢。A 主动点击继续后，B 被踢。
4. 同一端切后台、切网和恢复：不应被误提示其他设备登录。
5. 重复同账号入房、旧端迟到断连/登出：不能出现两个同账号席位，也不能使新端失效。
