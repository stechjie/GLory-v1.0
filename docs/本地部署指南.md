# Glory 本地测试服 · 部署与联机指南

一套**完全离线**的测试环境：账号后端 + 战斗服 + 游戏客户端，全部跑在局域网内，  
不连线上服务（Supabase、线上域名一概不碰）。适合多人联调、功能验证、给同事分发。

> 文档对应环境：Windows 10/11、Godot 4.7.2、Python 3.13、PostgreSQL 16。  
> 2026-10-13 版。

---

## 1. 架构

```
                局域网（同一网段，如 192.168.2.x）
 ┌──────────┐   HTTP  TCP 8099   ┌─────────────────────┐        ┌──────────────────┐
 │ 客机 A   │ ──────────────────> │  账号后端 (FastAPI)  │ ─────> │ PostgreSQL 55432 │
 │ 客机 B   │                     │  uvicorn, 0.0.0.0   │        │  仅监听 127.0.0.1│
 └──────────┘                     └─────────────────────┘        └──────────────────┘
 ┌──────────┐   ENet+DTLS UDP 8080  ┌──────────────┐
 │ 客机 A   │ ─────────────────────> │   战斗服      │
 │ 客机 B   │                        │ (Godot headless)│
 └──────────┘                        └──────────────┘
```

三个服务**只跑在主机上**；客机是纯客户端。主机同时也可以自己跑一个客户端。

| 服务         | 端口        | 监听             | 客机需要吗           |
| ---------- | --------- | -------------- | --------------- |
| PostgreSQL | TCP 55432 | 127.0.0.1（仅本机） | ❌               |
| 账号后端       | TCP 8099  | 0.0.0.0        | ✅ 登录/名片/道具都走它   |
| 战斗服        | UDP 8080  | 0.0.0.0        | ✅ 对局链路（DTLS 加密） |

## 3. 部署步骤（主机）

### 3.1 拿工程

拿到 `GLory-codex` 整个工程（git 或共享文件夹拷贝均可）。  
工程里的 `_local_test_server\` 是本地测试服的脚本目录，启动器、密钥、Godot 都在里面。

### 3.2 建数据库（首次才需要）

便携版 PostgreSQL 解压到纯 ASCII 路径（**中文路径会 initdb 失败**）：

```bat
pgsql\bin\initdb.exe -D pgdata -E UTF8 -U postgres
pgsql\bin\pg_ctl.exe -D pgdata -o "-p 55432 -c listen_addresses=127.0.0.1" -l ..\logs\pg.log start
pgsql\bin\createdb.exe -h 127.0.0.1 -p 55432 -U postgres glory
```

确保 `pg_hba.conf` 对本机连接是 `trust`（后端连接串不带密码）：

```
GLORY_DATABASE_URL=postgresql://postgres@127.0.0.1:55432/glory
```

然后**按编号顺序**把 `backend\database\001_*.sql` → `036_*.sql` 全跑一遍  
（psql 逐个执行；编号只增不改，加结构就加新文件，别改老文件）：

```bat
for %f in (backend\database\0*.sql) do pgsql\bin\psql.exe -h 127.0.0.1 -p 55432 -U postgres -d glory -f "%f"
REM 注意：这段写进 .bat 文件时，%f 要写成 %%f；直接贴在 cmd 窗口里用 %f
```

跑完全部 **35 个迁移文件**（001–036，中间 022 空号），最终约 **47 张表**，  
与线上结构一致。

### 3.3 建 Python 环境

```bat
cd backend
python -m venv ..\.venv         REM 或任意位置，下面路径跟着改
..\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3.4 放后端 + 配 .env

后端用 `GLory-v1.0`（正式服仓库）里的 `backend\` 整份拷过来，再打**离线补丁**：  
本地 httpx transport 拦截 Supabase Auth（`app\local_auth.py`），全部认证在进程内完成。  
最省事的办法：**直接找一台已经跑起来的主机，把它的整个 `backend\` 目录拷走**  
（补丁和 `.env` 都在里面）。

`.env` 放 `backend\.env`，本地版只要 6 个变量：

```ini
GLORY_SUPABASE_URL=http://127.0.0.1:59999
GLORY_SUPABASE_PUBLISHABLE_KEY=local-test-publishable-placeholder
GLORY_SUPABASE_SECRET_KEY=local-test-secret-placeholder
GLORY_DATABASE_URL=postgresql://postgres@127.0.0.1:55432/glory
GLORY_ENVIRONMENT=local
GLORY_BATTLE_CARD_KEY_FILE=<运行时目录>\keys\battle_card_key.pem
```

> 前三个 Supabase 值是**占位符**，永远不会被访问（离线补丁把请求全拦在进程内），  
> 非空只是因为 `config.py` 把它们列为必填。

### 3.5 生成密钥

全部放在**主机运行时目录**（如 `E:\GLory-server-runtime\keys\`，不要在共享目录里）：

```bash
# DTLS 自签证书（CN 必须是 glory-battle，客户端 pin 的就是这张）
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 ^
  -subj "/CN=glory-battle/O=Glory/OU=BattleServer" ^
  -keyout local_server_key.pem -out local_server_cert.pem

# 出战名片密钥对（后端用私钥签名片，战斗服用公钥验章）
python backend\deploy\make_battle_card_key.py     # 会打印出公钥
```

JWT 签名钥（`local_jwt_key.pem`）不用手动生成——后端首次运行自动造，  
删掉下次会重签（已发出的令牌全部失效）。

**只有 `local_server_cert.pem`（公钥证书）需要复制一份到共享目录的  
`_local_test_server\keys\`**，客机 DTLS 握手握要用它。私钥一概不进共享目录。

### 3.6 放 Godot 进工程

把 Godot 4.7.2 的两个可执行文件放进 `_local_test_server\godot\`：

```
_local_test_server\godot\Godot_v4.7.2-stable_win64.exe          （主程序，180MB）
_local_test_server\godot\Godot_v4.7.2-stable_win64_console.exe  （控制台版）
```

主机客机共用这一份，保证版本一致（版本不一致会静默联机错位，见 §7）。

### 3.7 启动与防火墙

**首次先放行防火墙**（Windows 默认阻止入站，不放行客机连不进来）：

```
双击桌面「放行Glory局域网.bat」→ UAC 弹窗点【是】→ 显示 [完成]
```

它做两件事（仅限局域网段，跑一次永久有效）：  
`TCP 8099 入站放行`、`UDP 8080 入站放行`。

然后**双击 `_local_test_server\一键启动_本地测试服.bat`**，一条龙做五步：

| 步骤  | 内容                                      |
| --- | --------------------------------------- |
| 1/5 | 启动 PostgreSQL（已在跑则跳过）                   |
| 2/5 | 启动账号后端，等 `/health` 返回 `configured:true` |
| 3/5 | 启动战斗服（UDP 8080 + DTLS）                  |
| 4/5 | 图鉴全解锁（写客户端 profile）                     |
| 5/5 | 拉起游戏客户端（自动连本机测试服）                       |

启动完**任务栏会有 3 个最小化控制台窗口**（GloryPG / GloryBackend / GloryBattle），  
那是三个服务，**关掉任何一个 = 停服**。想停服用 `一键停止_本地测试服.bat`。

## 4. 客机接入（局域网其他设备）

两种方式都可以，联机效果完全一样：

| 方式           | 做法                                  | 更新              |
| ------------ | ----------------------------------- | --------------- |
| **从共享跑**（推荐） | 共享文件夹里双击 `一键启动_客户端_联机.bat`          | 主机更新后客机下次启动就是新版 |
| **拷到本地跑**    | 把整个 `GLory-codex` 拷到客机，双击里面的同一个 bat | 主机更新后要重新拷       |

客机**不用装任何东西**：Godot 在工程里自带（§3.6），证书在 `_local_test_server\keys\`。

客机启动器会自动做：找 Godot → 写联机覆写配置（`user://local_test_override.cfg`）  
→ ping + `/health` 预检 → 带参拉起客户端连主机。

默认连 `192.168.2.100`。主机换机器/换网络后，改两个地方：  
`一键启动_本地测试服.bat` 里的 `SERVER_IP=` 和 `一键启动_客户端_联机.bat` 里的 `HOST_IP=`  
（主机上跑 `ipconfig` 看当前 IPv4）。

## 5. 日常使用

| 场景          | 操作                                 |
| ----------- | ---------------------------------- |
| 开服          | 主机双击 `一键启动_本地测试服.bat`，等五步就绪        |
| 停服          | 主机双击 `一键停止_本地测试服.bat`（按端口杀，干净）     |
| 客机进游戏       | 双击 `一键启动_客户端_联机.bat`               |
| 编辑器里按 F5 调试 | 覆写配置已写好，F5 同样连本地测试服                |
| 客机连不上       | 见 §8                               |
| 换主机 IP      | 改两个 bat 里的 `SERVER_IP` / `HOST_IP` |

**账号是全自动的**：每个客机首次进游戏自动注册匿名账号，并拿到全道具 + 满货币 +  
全图鉴（登录时由后端幂等补发，不用记 player_id、不用跑 SQL）。  
想测商城购买流程，把启动器里 `set "GLORY_TEST_UNLOCK=1"` 那行删掉再重启后端。

## 7. 注意事项（都是踩过的坑）

1. **三把私钥绝不进共享目录**：DTLS 私钥、JWT 签名钥、名片私钥。  
   共享目录里只放公钥证书。被拷贝出去等于别人能自己签名片、能解密战斗链路。
2. **改 bat 必须守 GBK + CRLF**：bat 文件用记事本另存为 ANSI；不要用会转 UTF-8 的编辑器，  
   不要加 `chcp` 行。LF 行尾会让 cmd 把多行命令粘成一行随机乱执行。
3. **bat 里不能出现中文路径**：`user://` 目录名是中文（`测试服`），GBK 字节在代码页  
   不一致时会被按 UTF-8 解释、写进乱码目录，而且报错被 `2>nul` 吞掉看不出异常。  
   所以联机覆写配置由 Godot 自己写（`write_override.tscn`）。
4. **Godot 版本必须两端一致**：主机客机都用工程里自带的那份 4.7.2。  
   版本不一致时协议校验会静默错位（症状是联机行为诡异但不报错）。
5. **后端启动后有 45 秒排队预热**：这期间客机登录会被挡在启动画面，等一会就好，  
   不是故障。
6. **别关那 3 个最小化窗口**：GloryPG / GloryBackend / GloryBattle，关一个就停服。
7. **主机开 Godot 编辑器时，客机别同时跑**：两边共用工程里的 `.godot` 导入缓存，  
   同时写会互相干扰。
8. **测试服没有局内语音**（语音走 LiveKit，本地没装），不影响其他联机功能。
9. **匹配（排位）不可用**：离线环境只适合自定房间 / 组队房。
10. **后端重启后所有人要重新登录**：refresh token 存内存。客户端会自愈  
    （自动重签 player_id 再登），图鉴和道具不受影响。

## 8. 排错

客机卡在登录画面（`BOOT-ENTRY-LOGIN`）时，按顺序查：

| # | 查什么            | 方法                                                                       |
| - | -------------- | ------------------------------------------------------------------------ |
| 0 | **主机服务还活着吗**   | 任务栏有没有那 3 个窗口；`netstat -an \| findstr :8099` 有没有 LISTENING               |
| 1 | **IP 对不对**     | 主机 `ipconfig` 看 IPv4，和两个 bat 里的 IP 是否一致                                  |
| 2 | **网络通不通（决定性）** | **客机浏览器打开 `http://<主机IP>:8099/health`**：出 JSON = 网络通、问题在游戏端；打不开 = 防火墙/网络 |
| 3 | **45 秒预热**     | 后端刚起 45 秒内挡登录，等一会                                                        |
| 4 | **Godot 版本**   | 客机若自己装了 Godot，必须是 4.7.2 stable                                           |

常用日志：`E:\GLory-server-runtime\logs\backend.log`（登录、名片、道具发放都在里面）。

## 9. 关键设计（为什么这么设计）

- **测试服从不改源码里的线上地址**：靠 `user://local_test_override.cfg` 覆写  
  （命令行参数 > 覆写文件 > 源码线上默认值）。  所以测试服的源码改动可以整份同步进正式服仓库而不用回退——正式服的  
  `user://` 下没有这份文件，自动回落线上。
- **账号后端是唯一权威**：金币/道具/名片只能由后端改，客户端和数据库直连都不是权威。
- **战斗链路 DTLS + 证书 pin**：客户端 pin 服务端那张自签证书，换证书两端必须一起换，  
  否则是干净的握手失败（拒绝连接），不会静默退化成明文。
