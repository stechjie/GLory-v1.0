# Android 语音与包体修复（2026-09-30）

## 本次根因

用户手机截图仍显示“语音组件需要更新”。检查桌面测试0930.apk 的 DEX，GloryVoicePlugin 实际声明 hasRecordPermission、joinRoom、leaveRoom、setMicrophoneEnabled、setParticipantVolume、setAudience、getStatus、getCapabilities 八个方法。

VoiceService 却使用 Object.has_method 查询 Java/Kotlin 方法，Android 的 JNISingleton 不使用普通 Object 方法表。这解释了为何只重建 AAR 后仍误报旧组件。新增 _bridge_has_method：具备 has_java_method 的对象走 JNI 查询，其余桥接走普通 has_method。setAudience、权限请求及前后台通知全部共用此逻辑。真正缺少 setAudience 的旧插件仍拒绝启用，未绕过版本检查。

Godot 官方接口说明：https://docs.godotengine.org/en/stable/classes/class_jnisingleton.html

新增回归使用有 Java 方法表、没有同名 GDScript 方法的桥接，重现平台差异；Windows 原有状态机回归仍保留。本次无需再次改 Kotlin 或重建已更新的 AAR。

## 包体与目录

原 APK 1038109480 字节（约 990 MiB），包含 ARM32、ARM64、x86、x86_64 四套库以及历史 QA 资源。新 Android 包保留 ARM32/ARM64，不面向 x86 模拟器。实际包约 724 MiB，最终精确字节数、SHA-256 见桌面 verification/package_summary.json。

预设启用 Gradle，并补齐导出排除项：work、reports、captures、历史备份/QA、文档、开发工具、调试场景等。Effekseer 只见于实验预览内容，缺少 Android 二进制；将其与对应实验场景一起排除 Android 导出，保留本地编辑源文件。GloryVoice 的 GDExtension 是 Windows/iOS 用途，Android 排除该描述文件，继续通过导出插件打入 AAR、LiveKit 与 WebRTC。

对照 C:/Users/WINDOWS/Desktop/GLory-v1.0 和 \\192.168.31.8\GLory\res\assets，记录路径与大小差异。参考代码仓库 assets 仅 777 文件，而本地 2913、共享资源 2878（包含导入元数据差异）。因此没有以“代码仓库里不存在”为依据删除素材。大体积正式模型、纹理仍保留，未做降采样或有损优化。

33 个未跟踪的历史产物和旧 Android 构建输出目录移至桌面 archived，共约 4.32 GiB、18463 文件。cleanup_plan.json 逐目录记录源位置、归档位置、文件数和字节数；全部是移动归档，没有永久删除。构建过程会重新产生必要缓存，项目净减少量小于归档总量；整个磁盘占用不会因为同盘归档等量减少。

## 验证与复测

- voice_check：416 项通过，包括 JNI 检测与真正缺接口时的拒绝。
- export_presets_check：本地和共享模板一致。
- main_screen_scenes_check：60 项通过；resource_case_check：3913 项通过。
- 使用 Godot 4.7.2 实际导出 Debug APK，核查 DEX 方法、ARM 架构、LiveKit/WebRTC、录音权限和构建身份；结果与导出日志保存在桌面 verification。
- 新增 tools/apk_voice_size_audit.py 可检查后续 APK：`python tools/apk_voice_size_audit.py game.apk --report audit.json`。它检测声明的方法，不会被 DEX 中偶然出现的同名字符串骗过。
- adb 当前未连接设备，未验证真实手机启动、音频采集与跨设备通话。修复解决已定位的接口误判，不能代替生产语音服务器/手机联调。

在手机安装桌面提供的新 APK（Debug，应用 ID com.yourname.glory），进入房间确认旧更新弹窗消失，授予录音权限。电脑/另一台手机进入同房间，分别验证麦克风、扬声器、队友/所有人范围。若出现其他错误，记录原文和客户端日志继续检查令牌签发、LiveKit 连接或系统权限。安装签名冲突时应使用与原包一致的签名重新导出，避免为测试盲目卸载造成数据丢失。

## 备份与恢复

桌面交付目录 files/ 保存变更后的源码、预设、README 和说明，before/ 保存修改前版本；均保持项目路径。archived/ 保存被清出的原文件，包含过去的修复备份。manifest.json 记录变更文件 SHA-256。

关闭编辑器/游戏后可用 before/ 覆盖回项目对应位置，新增审计脚本与本文可按需保留。恢复历史产物可运行桌面 Restore-Archived.ps1：已有目标目录会跳过并打印提示，不覆盖新生成的内容。没有修改参考仓库或共享资源，也没有上传 GitHub。
