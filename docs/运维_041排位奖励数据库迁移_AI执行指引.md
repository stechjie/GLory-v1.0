# 041 排位全场奖励未到账：服务端 AI 执行指引

将本文件和 `database/041_ranked_reward_coin_limit.sql` 一起交给能访问服务器的 AI，并要求：“按此文档完成041迁移和验证，返回执行结果。”

本指引只授权处理041奖励回执约束。不要重置仓库、自动更新整套服务、重启战斗服、生成或轮换密钥、修改玩家余额、构造战报补发，或运行会建库删库的测试脚本。连接路径与本机默认部署不同的，先核对实际服务配置，再调整以下路径。

## 1. 故障与目标

排位胜利奖励15～20金币，而027迁移的回执约束仍为3～15。任意胜方抽到16～20金币，`ranked_reward_receipts_coin_check` 就会拒绝写入。战报、积分、钱包、经验处于同一事务，因此整场回滚，六名玩家的界面都可能显示“正在确认到账”。

目标是把 `public.ranked_reward_receipts` 上的该约束改为 `CHECK (coin BETWEEN 3 AND 20)`，并确认它已验证、已提交。保留旧027和所有历史数据，只执行新增041。新的后台自检会检查该约束，但**同步代码或更新客户端不会自动执行迁移**。

本地已验证13/21回合各六人的签名战报入库、12份实际奖励回执、重复提交不重复发奖；真实PostgreSQL38项测试通过。本文件不代表线上迁移已经执行。

## 3. 执行迁移

下面是一条完整命令。若第2步确认的路径不同，仅替换命令中的三个路径；不要改变数据库连接来源或脚本里的迁移内容。

它会记录旧约束、验证状态、回执行数和迁移指纹到权限受限的备份目录；不会备份或输出密钥。此迁移只修改约束，不改账户数据，因此这份结构审计记录和原027足以说明变更前状态。若团队另有数据库快照要求，应先完成已有备份流程。

迁移使用单一事务、5秒锁等待上限和30秒语句上限。若线上忙碌导致锁超时，事务会回滚，停止并报告，选择合适时机重试；不要强行断开玩家连接。重复执行会识别已有20上限并仅验证。

```bash
sudo /opt/glory/venv/bin/python - \
  --env-file /opt/glory/backend.env \
  --migration-file /opt/glory/src/database/041_ranked_reward_coin_limit.sql \
  --backup-dir /opt/glory/migration-backups/041 <<'PY'
import argparse
import asyncio
import datetime as dt
import hashlib
import json
import os
from pathlib import Path
import re
import sys

import asyncpg
from dotenv import dotenv_values

EXPECTED_SHA256 = "1cb965dd847ddc0e6fc2608229077d99f29ae318f553a3b71862f4853c6bedc7"
READ_CONSTRAINT = """
select pg_get_constraintdef(c.oid) as definition, c.convalidated as validated
from pg_constraint c
where c.conrelid = to_regclass('public.ranked_reward_receipts')
  and c.conname = 'ranked_reward_receipts_coin_check'
"""


def cap(definition):
    compact = re.sub(r"[\s()]", "", definition).lower()
    expected = re.fullmatch(r"checkcoin>=3andcoin<=(15|20)", compact)
    if not expected:
        raise RuntimeError("Unexpected existing constraint; inspect its definition before changing it")
    return int(expected.group(1))


async def migrate(args):
    os.umask(0o077)
    config = dotenv_values(args.env_file)
    if config.get('GLORY_ENVIRONMENT', '').strip() != 'prod':
        raise RuntimeError('The selected environment file is not marked prod')
    dsn = config.get('GLORY_DATABASE_URL', '').strip()
    if not dsn:
        raise RuntimeError('GLORY_DATABASE_URL is missing from the selected service environment file')
    sql = Path(args.migration_file).read_text(encoding='utf-8-sig')
    digest = hashlib.sha256(sql.encode('utf-8')).hexdigest()
    if digest != EXPECTED_SHA256:
        raise RuntimeError('041 file checksum does not match this reviewed migration')
    body = '\n'.join(line for line in sql.splitlines()
                     if line.strip().lower() not in ('begin;', 'commit;'))
    stamp = dt.datetime.now(dt.timezone.utc).strftime('%Y%m%dT%H%M%S%fZ')
    backup = Path(args.backup_dir) / stamp
    backup.mkdir(parents=True, mode=0o700)
    conn = await asyncpg.connect(dsn, timeout=10, command_timeout=35, statement_cache_size=0)
    try:
        async with conn.transaction():
            # SET LOCAL also works with transaction-pooling connections.
            await conn.execute("set local search_path = public;"
                               "set local lock_timeout = '5s';"
                               "set local statement_timeout = '30s'")
            before = await conn.fetchrow(READ_CONSTRAINT)
            if before is None:
                raise RuntimeError('Expected 027 receipt table/constraint is missing; do not guess prerequisites')
            old_cap = cap(before['definition'])
            metadata = {
                'started_utc': stamp,
                'database': await conn.fetchval('select current_database()'),
                'migration_sha256': digest,
                'old_definition': before['definition'],
                'old_validated': before['validated'],
                'receipt_rows_before': await conn.fetchval('select count(*) from public.ranked_reward_receipts'),
            }
            (backup / 'before.json').write_text(json.dumps(metadata, ensure_ascii=False, indent=2), encoding='utf-8')
            already_applied = old_cap == 20 and before['validated']
            if not already_applied:
                await conn.execute(body)
            after = await conn.fetchrow(READ_CONSTRAINT)
            if after is None or cap(after['definition']) != 20 or not after['validated']:
                raise RuntimeError('041 postcondition failed; rolling back this transaction')
            metadata.update(new_definition=after['definition'], new_validated=after['validated'],
                            already_applied=bool(already_applied))
        # Verify committed state in a new transaction, not just inside the DDL transaction.
        committed = await conn.fetchrow(READ_CONSTRAINT)
        if committed is None or cap(committed['definition']) != 20 or not committed['validated']:
            raise RuntimeError('Committed constraint verification failed')
        metadata.update(status='PASS', completed_utc=dt.datetime.now(dt.timezone.utc).isoformat())
        (backup / 'result.json').write_text(json.dumps(metadata, ensure_ascii=False, indent=2), encoding='utf-8')
        print('041_MIGRATION_PASS already_applied=' + str(bool(already_applied)))
        print('constraint=' + committed['definition'])
        print('audit_directory=' + str(backup))
        print('No balances, scores, XP, receipts or historical reports were rewritten.')
    finally:
        await conn.close()


parser = argparse.ArgumentParser()
parser.add_argument('--env-file', required=True)
parser.add_argument('--migration-file', required=True)
parser.add_argument('--backup-dir', required=True)
args = parser.parse_args()
try:
    asyncio.run(migrate(args))
except Exception as exc:
    # Do not echo connection strings or credentials from the environment file.
    if type(exc) is RuntimeError:
        print('reason=' + str(exc), file=sys.stderr)
    print('041_MIGRATION_FAILED type=' + type(exc).__name__
          + ' sqlstate=' + str(getattr(exc, 'sqlstate', 'none')), file=sys.stderr)
    sys.exit(1)
PY
```

成功必须同时满足：命令退出码0，出现 `041_MIGRATION_PASS`，输出约束包含 `coin >= 3` 和 `coin <= 20`，审计目录内 `result.json` 为PASS且 `new_validated` 为true。`already_applied=True` 表示之前已经执行过，仍然是成功。

失败会返回非0，仅打印预先定义的诊断原因、异常类型和SQLSTATE，避免泄露连接信息。失败时不能宣称完成。DDL事务失败会恢复旧约束；若已经成功，不要再改回15，否则会阻断后续合法奖励，且已有16～20金币回执可能使降级失败。

## 5. 历史失败对局
