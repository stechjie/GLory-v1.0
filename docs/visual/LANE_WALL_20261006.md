# 战斗光墙与分路边界（2026-10-06）

## 最终布局

按树林、石头内侧的可战斗区域分路，撤销整屏 1/3、2/3 的视觉偏移。
模拟与显示共同读取 BattleSimShared.PLAYABLE_MIN=(95,68)、PLAYABLE_MAX=(905,452)。
三条路线横向范围为 95–365、365–635、635–905；中心为 230、500、770。
BattleUI 引用这组常量；BattleArena 将同一范围投影到正式相机，因此角色、怪物和光墙没有两套边界。

光墙没有柱子、水晶或石座，宽度为 0.30 世界单位，每条仅一个网格、768 三角形。
固定横向轮廓，仅改变亮度；曲面的纵向补偿使用正式相机 Z/Y=7/7.4，避免屏幕端部斜切。
两条墙在正式相机里保持垂直、平行。视觉端部延伸 0.75 单位并淡出，衔接场地边缘。

## 角色与怪物约束

原有强制位移使用全模拟画布的 333.33/666.67 边界，与可战斗区域的 365/635 光墙不一致。
新规则统一使用可战斗区，并预留 max(身体半径,28)+3 模拟单位的身体/显示空间。

- 出场、复活/召唤、技能位移、普通行走、恐惧、碰撞推挤和每帧结束均纳入约束。
- 仍关闭的光墙阻止跨区；沿途光墙解除后，允许进入连通区域支援。
- 显示层复用同一位置约束；正常新回放的显示位置必须与权威位置一致。
- 教学无分路单位、法阵友军和决赛横向布局不套用本次普通三路约束。

## 验证

1. lane_playable_bounds_check.gd：极端位移、闭墙、开一道/两道墙支援、草地区域、教学/决赛排除；PVE/Boss/PVP 完整样本覆盖 3881 次存活位置。
2. lane_wall_battle_capture.gd：正式回放入口，校验实际膜面端部不斜切、墙竖直平行、可战斗区三等分；逐帧检查显示位置与模拟位置一致。
3. battle_lane_barrier_check：34 项；battle_final_lane_wall_check：12 项。
4. determinism_check：111 项；battle_visual_separation_check：26 项；battle_reach_target_check：43 项。

## 恐惧魔专项验收

恐惧状态的生产位移链路 `_tick_skills → _skill_fear → _step_team → _move_without_pushing` 使用同一战斗状态判断闭墙，并预留受击单位身体边距。恐惧持续期间碰到未解除光墙会停在墙内，墙解除后才允许穿过。

`tools/fear_wall_collision_check.gd` 从正式 dark_fear 定义读取技能和四星覆盖，通过真实技能调度施加恐惧，逐 tick 验证整段 2/3 秒持续时间。64 个组合覆盖两道墙、双向、普通/四星、1/3 格体型、正常/10 倍速度和闭墙/开墙，共 1600 次位置检查，全部通过。生产修复复用上一轮统一边界代码，本轮新增专项防回归测试。

```sh
Godot --headless --path . --script res://tools/fear_wall_collision_check.gd
```
