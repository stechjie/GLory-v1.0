# 棋盘皮肤

对局里**摆放界面**（摆棋子那页）的底图、河流、待命区、萝卜、商店按钮换成一套主题图。只换图，不碰玩法。

- **只有自己看得见**：游戏里没有看别人摆放界面的功能（观战在战斗画面），所以皮肤不进出战名片，战斗服务器不用管。
- **在主界面「备战」页的「棋盘皮肤」页签换**，对局里不能换；在商城的「棋盘皮肤」分类买。
- 默认皮肤「青草地」永远免费。
- 名字约定（2026-09-27 定）：对局里摆棋子那页叫「摆放界面」，主界面按钮进的那页叫「备战」。

## 由哪些东西组成

| 东西 | 在哪 |
|---|---|
| 皮肤目录（有哪些皮肤、名字、可选设置） | `data/prep_skins.json`，随安装包 |
| 图 | `assets/skins/prep/<皮肤 id>/`：`board` `river` `bench` `carrot` `shop_button` `preview`（都是 .png） |
| 按皮肤取图 | `scenes/prep/PrepSkin.gd`（`SLOTS` 是槽位和默认图） |
| 玩家现在用哪张 | 账号服务器 `players.prep_skin`（`database/021_prep_skin.sql`），接口 `GET/PUT /v1/me/prep-skin` |
| 卖 | `data/shop.json` 里 `kind` 为 `prep_skin` 的商品 |
| 看效果、出预览图 | `scenes/debug/PrepSkinReview.tscn`（编辑器里按 F6） |
| 门禁 | `tools/prep_skin_check.tscn` |

## 下次加一张皮肤（不用改代码）

### 1. 美术出图

| 文件 | 尺寸 | 要求 |
|---|---|---|
| `board.png` | 2560×1440 | 棋盘底图，不透明。中间摆棋子那块别画会和格子打架的东西 |
| `river.png` | 1672×941 | 只有下方一条河道不透明，其余透明 |
| `bench.png` | 2688×1520 | 待命区 8 格。**格子位置照原图描**（冰雪版就是这么做的，可以当范本） |
| `carrot.png` | 1214×1295 | 萝卜居中、四周透明。别比原图宽太多，组队局后排的宠物会被挡 |
| `shop_button.png` | 不限 | 底部商店按钮。**裁掉四周的透明边**，不然按钮会显示得小一圈 |

哪张不想换就不给，自动用青草地那张。原图在 `SLOTS` 里写着路径，可以拿来对比。

### 2. 放进项目

在 `assets/skins/prep/` 下建文件夹，**文件夹名就是皮肤 id**：`prep_skin_` 加小写英文、数字、下划线，例如 `prep_skin_lava`。把图放进去。

### 3. 登记

`data/prep_skins.json` 的 `skins` 里加一段：

```json
{
	"id": "prep_skin_lava",
	"name": "熔岩",
	"name_en": "Lava",
	"firefly_color": [1.0, 0.55, 0.25],
	"river_glow": false
}
```

后两项可以不写：`firefly_color` 是满场光点的颜色（默认金色萤火虫），`river_glow: false` 关掉下河面的流动波光（那层是照草地河道画的）。

### 4. 看效果、出预览图

打开 Godot 编辑器（会自动导入新图），打开 `scenes/debug/PrepSkinReview.tscn` 按 F6：

- 点新皮肤的按钮看效果；勾「萝卜旁摆 6 只宠物」看萝卜挡不挡宠物；
- 满意后点「**生成预览图**」，写出 `preview.png`（备战页和商城卡片上那张），切回编辑器让它导入。

### 5. 跑门禁

```
Godot --headless --path . res://tools/prep_skin_check.tscn
```

要 PASS。它查：图有没有拷全、有没有预览图、`prep_skins.json` 的键有没有写错、商城卖的皮肤在不在目录里。

### 6. 要卖的话

`data/shop.json` 加一件商品：

```json
{
	"id": "shop_prep_skin_lava",
	"kind": "prep_skin",
	"grants": "prep_skin_lava",
	"currency": "diamond",
	"price": 300,
	"name": "熔岩棋盘",
	"name_en": "Lava Board"
}
```

🔴 **商品 id 和皮肤 id 卖出去之后永远不能改**（归属表存的是皮肤 id，见 `docs/商城系统设计.md`）。不写进 `shop.json` 的皮肤就是免费的。

### 7. 发布

1. **美术不进 git**：跑 `tools/update_asset_manifest.ps1` 更新资产清单，把新图传到云盘素材包。不然别的电脑打出来的包里没有这张图（门禁会红）。
2. 出新 APK，versionCode 加 1。
3. 推送、更新账号服务器（`shop.json` 跟着 `deploy/update.sh` 上去）。

先后无所谓：旧包看不到它没有图的皮肤（商城会藏起来），所以不会卖出用不了的东西。

## 第一次上线（冰雪）要做的

1. **Supabase 先跑 `database/021_prep_skin.sql`**，再更新账号服务器。顺序反了，读写皮肤的接口会报错（列不存在）。（2026-09-28 已做）
2. **旧包看不到皮肤商品**：旧包不认识皮肤，会把它当成头像显示，能买却用不了。所以客户端要在请求头里声明
   认识皮肤（`X-Glory-Client: …; kinds=prep_skin`，`AccountManager.CLIENT_KINDS`），账号服务器只把皮肤发给声明过的
   （`backend/app/routes/shop.py` 的 `DECLARED_KINDS`）。
   🔴 **不按版本号判断**：本机导出写 versionCode、同事 `tools/workspace` 的安卓流水线不写、iOS 写成 build_number、
   编辑器是 0 —— 最初按「versionCode 17 以上」挡，同事出的包全报 0，就漏了（2026-09-28 改成声明）。
   以后再加**新种类**的商品（不是新皮肤），两边名单各加一个名字；加新皮肤什么都不用改。
3. 战斗服务器不用动。
4. 价格 300 钻是占位，要策划定。
