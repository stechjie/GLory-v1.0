# 10.06 PvP 分路左右对齐修复记录

## 现象（用户反馈）

> 平时我在最左的道，在 PvP 却突然变去最右的。

只有蓝队（座位 3-5，房间下排 1/2/3）会遇到：蓝队 1 号 PvE 在最左路，一到 PvP 就跑到最右；3 号反过来；2 号（中路）不受影响。

## 根因

PvP 是两队打同一场，战斗服务器按「红队在下、蓝队在上」摆规范棋局，第 i 路是红队 i 号对蓝队 i 号
（A 对 1、B 对 2、C 对 3，和房间里 A 在 1 正上方一致）。两处叠在一起出了问题：

1. 模拟里蓝队的棋盘是**左右镜像**摆的（云顶式面对面，`BattleSimShared.board_cell_pos`）。
2. 9.25（`16e980d`）为了让蓝队看到的自己棋子和摆放界面一样，把蓝队的 PvP 画面**整张转 180°**
   （`BattleArena._sim_to_world_pos` 里 x、y 都翻）—— 棋子方向抵消回来了，**分路左右却跟着反了**。

镜像还带来第二个问题（用户 10-06 指出）：PvE 回合点「查看另一队」看对面打怪时，对面主力在左边；
到 PvP 它却在右边。布局是重要的策略，看到在哪就该在哪。

## 规矩（用户 10-06 定）

**正上方对正下方**，房间、PvE、看对面打怪、PvP 四处左右一致：

- 房间：A 在 1 正上方（不变）
- 分路配对不变：A 打 1、B 打 2、C 打 3；PvE 送佣兵的配对也不变
- 棋盘：对面摆在他左边的，在你画面里也在左边，你左边那格正对着它

曾经提过「改成面对面：A 打 3」—— 用户否决：房间里 A 在 1 正上方，配对必须和房间一致。

## 部署（协议 38）

位置是战斗服务器算的、画面翻转是客户端做的，**两半必须一起换**：旧客户端配新服务器，蓝队会看到
自己的棋子左右颠倒；新客户端配旧服务器也一样。所以升了协议号：

1. 战斗服务器重新打包、部署到 p38（确认依据：服务器日志 `server started protocol=38`）
2. 出新包，所有人换包

账号服务器不用动。PvP 里每一路格子的对位变了（蓝队第 0 列现在正对红队第 0 列），PvP 打出来的结果会和以前不同。

## 门禁

`tools/pvp_lane_alignment_check`（16 项）：

1. `board_cell_pos`：不镜像时敌方第 0 列和我方第 0 列同一个 x；默认（PvE / 决赛）照旧镜像
2. 真的 `prepare_team_state`（固定对局夹具第 6 回合）：蓝队 1 号的棋子全在最左路，第 0 列在本路左边；
   夹具给蓝队 1 号加了一个佣兵，佣兵不压在棋子身上
3. 同一个蓝队棋盘：PvE（查看另一队看到的那场）第 0 列在左，PvP 也在左
4. 决赛照旧镜像
5. 画面：蓝队看 PvP 翻前翻后 x 一样、z 相反，最左路仍在最左

变异验证：换回「镜像 + 转 180°」→ 4 条红（正好复现用户看到的「1 号跑到最右」和「看到在左、打的时候在右」）；
决赛也去掉镜像 → `final_mirror_changed`。

实拍对比（固定对局第 6 回合，蓝队 1 号 / 红队 A 两个视角 + 蓝队 PvE 对照）在 10-06 的对话里发过，
截图方法：临时场景用 `FixedBattleFixture.setup_match_state` + `compute_team_replay` + `GameState.set_pending_battle_package`
交给真的 `BattleScreen.tscn`；这台机器要用 `--rendering-method gl_compatibility`，默认渲染器第一帧编译着色器会卡住。
