## 二、两条用户硬性口径（开工前已确认）

1. **「战斗中释放技能时」才响四星技音**，不是升星那一刻。
   → 接线点放在战斗演出里的「技能施放上升沿」与母灵「死亡执行」事件，不放在 `four_star_upgrade` 升星流程。
2. **「自身不包括队友」** —— 战斗/特效里的音效只能听见**自己棋子**造成的。
   → 判定口径复用既有 `_is_local_owned_unit(sim_uid)`（`owner_slot == local_slot`）。
   队友是**不同 slot**，被这个判定天然排除；所以「自身」与「我方（含队友）」在这里是同一种实现，
   不会误伤队友，也不会漏掉自己。

## 三、四星专属技音效的接线

此前 `STAR4_CUES` 里 `god_archangel` / `dark_doom` 直接复用 `god` / `dark` 的音频文件。
本轮把**大天使、末日守卫**拆成独立 cue（各自专属音频），母灵/神王/黑龙沿用各自文件：

```gdscript
const STAR4_CUES := {
    "human_king": CUE_STAR4_HUMAN_KING,
    "god_archangel": CUE_STAR4_ARCHANGEL,   # 9.18 拆出，原复用 god
    "god_king": CUE_STAR4_GOD,
    "undead_mother": CUE_STAR4_UNDEAD_MOTHER,
    "dark_dragon": CUE_STAR4_DARK,
    "dark_doom": CUE_STAR4_DOOM,            # 9.18 拆出，原复用 dark
}
```

两处触发（都带「自身」闸门）：

- **通用技能施放**：`scenes/battle/BattleVfx.gd` 的 `_play_skill_cast_vfx()`（约 386 行），
  对本次施放单位的 `sim_uid` 判 `_is_local_owned_unit()` 且 `_is_star4()`，才 `SfxService.play(star4_cue_for(uid))`。
  `_is_star4()` 从 `_state` 的 `player`/`enemy` 两侧里按 `uid` 取 `star`，等于 `GameConstants.MAX_STAR`（=4）才成立。
- **母灵「死亡执行」**：同文件 `mother_execute` 分支（约 878 行），对 `source_uid` 判「自身 + 四星」，
  才播 `star4_cue_for("undead_mother")`。

`star4_cue_for(unit_id)` 间接派发，所以 `CUE_STAR4_ARCHANGEL` / `CUE_STAR4_DOOM` 走 `INDIRECT_CUES` 豁免
（不要求直接调用点，但要求 `STAR4_CUES` 里有登记）。

## 六、本轮抓出来的坑（BattleVfx 缩进）

`BattleVfx.gd` 是被 `BattleResult.gd` / `BattleScreen.gd` 用 `extends` 继承的**父脚本**，
父脚本有解析错误会级联让两个子类一起挂。

`mother_execute` 分支第一版把 `if not mother.is_empty():` 写到了与 `elif` **同级**（2 个 tab），
导致 `mother`（声明在 `elif` 体内，3 个 tab）不在作用域，报
`Parse Error: Identifier "mother" not declared in the current scope` 并把 `BattleResult`/`BattleScreen` 一起带红。

修正：把 `if not mother.is_empty():` 及其整个 body 整体往里压一档（3 个 tab，`if` 体 4 个 tab），
全部收进 `elif mother_execute:` 体内。压完重跑 `--import` 已无 SCRIPT ERROR，
`BattleResult`/`BattleScreen` 恢复正常加载。
