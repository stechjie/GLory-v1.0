## 0. 先给结论

上一版的主体架构已经落地：`BattlePresentationDirector`、单位 Actor/锚点、立绘 fallback、cue profile、预算和真机记录器都存在；真机中的“胶囊占位体”也已经消失。现在的主要矛盾从“有没有战斗演出架构”转为以下四类：

1. **资源交付树已经不完整，白模不是单个材质参数问题。** 当前 `asset_delivery_check` 报 759 个缺失、40 个大小不符、9 个哈希不符；模型检查报 59 个失败。APK 里看到的 2D 立绘只是 fallback，不能证明 3D 模型及贴图完整。
2. **测试存在假绿。** `battle_presentation_director_check` 在同一进程中出现 GDScript parse error，最终仍打印 `PASS` 并以 0 退出；这会让回归门禁失去意义。
3. **真机战斗可运行但仍不够好读。** 普通战约 2–4 秒、Boss 约 5 秒；蓝色晶柱和全身护盾长期遮挡单位，胜利反馈单薄，低分辨率立绘与高清卡牌/背景风格不一致。
4. **教程能走到 15/17，但存在明确的完成风险。** 内部步骤键直接显示给玩家；采购面板遮住待命区，使“买完再上阵”看起来像卡住；Android 返回键直接退到桌面，重新进入后语言和教程从头开始。

因此执行顺序必须是：**先恢复可信资源和修复红灯/假绿门禁，再修白模，再调战斗观感，最后做教程与性能收尾。** 不允许先继续堆 VFX 来掩盖资源断链。

## 4. P1：战斗观感第二轮整改

### [ ] P1-01 增加“最短可读演出时长”，不改战斗模拟结果

**挂接点**：`BattlePresentationDirector`、`BattleScreen` 进入结算前的 `drain`、cue profile。

**AI 实施**：

1. 模拟仍按固定 tick 立即算完；只对 presentation timeline 设可配置阅读窗，禁止用全局 `Engine.time_scale` 改 PVP/回放逻辑。
2. 普通战目标时长 5–8 秒，Boss 8–12 秒；如果事件少，用开场编队、Boss 登场、关键命中、死亡停顿和胜利收尾填充，不用空等。
3. `attack_start → impact` 至少 180–350 ms；死亡至少保留 350–600 ms；Boss 大招前摇至少 500 ms；最终死亡到胜利字样至少 450 ms。
4. 允许“跳过演出”立即 drain，但必须留下最终状态、死亡和胜负三类不可丢反馈。
5. 录制 timeline JSON，明确每个 cue 的 queued/start/end/drop_reason。

**验收**：固定 10 个种子的普通/Boss 样本都满足时长窗；最终 state/replay SHA 与修改前完全一致；2×速度和 skip 不残留 tween/timer。

### [ ] P1-02 降低蓝色晶柱的视觉优先级

**挂接点**：`scenes/battle/BattleLaneBarrier2D.gd` 及对应场景。

**AI 实施**：

1. 晶柱只作为边界提示：高度缩到当前约 45%–60%，横向移到角色活动区外，常态 alpha 控制在 0.15–0.30。
2. 只在开场 0.4 秒或单位越界时增强，随后淡出；低画质改为细线/地面纹理。
3. 给 barrier 增加 `presentation_priority=ambient`，预算紧张时先降级。
4. 自动截图计算晶柱遮挡的角色像素占比；任一角色 >10% 失败。

**验收**：不看半场文字也能分辨边界，但晶柱不再成为画面最亮、最高的主体。

### [ ] P1-03 把持续护盾从“大泡泡”改成“短促施加 + 低占用常驻”

**挂接点**：shield cue profile、`StatusVFXController`、`VFXQualityBudget`。

**AI 实施**：

1. 护盾施加时播放 250–450 ms 的完整泡泡；常驻状态只留脚底环、血条小图标或薄边缘，alpha ≤0.22。
2. 护盾吸收伤害时短闪，破盾时播放一次碎裂；没有事件时不要每帧高亮。
3. 多个护盾合并为一个状态显示，按剩余吸收量更新，不叠多层透明球。
4. 高/中/低质量分别限制透明层和粒子；critical 的“破盾”不可丢，ambient 的常驻波纹可降级。

**验收**：角色面部/武器主体至少 80% 可见；满编队没有大面积透明叠层发白。

### [ ] P1-04 提升 fallback 立绘质量并统一战场轮廓

**挂接点**：`UnitPortraitFallback3D.gd`、`UnitVisualResolver.gd`、角色资源 registry。

**AI 实施**：

1. 优先使用 512/1024 像素战斗半身图，不复用 64/128 图标；报告实际 texture size，低于 384 直接警告。
2. 去掉资源中预烘焙的粗黑边，改用统一 shader outline；移动端只用单次采样/轻量描边。
3. 统一脚底基准、目标高度、朝向、队伍色底座、双线性/各向异性和 mipmap 策略。
4. 近战、远程、Boss 分别配置 scale/anchor，不允许所有角色用同一高度常量。
5. 3D 模型恢复后仍保留 fallback，但设备记录中每次 fallback 都要按 unit_id/reason 聚合。

**验收**：1280×720 和 2640×1216 下角色不糊、不锯齿、不贴地漂浮；角色与高清卡牌的色彩/描边语言一致。

### [ ] P1-05 补足命中、死亡与胜利三段收尾

**AI 实施**：

1. 普攻：轻微前冲/后坐、命中闪、单次小屏震；暴击只放大 20%–35%，不堆全屏闪白。
2. 死亡：先受击停顿，再溶解/倒下/淡出，血条和状态图标同步，不突然消失。
3. 胜利：镜头轻收束、幸存者定格、胜利字样和短音效/震动；至少保持 0.8 秒后进入奖励。
4. 无障碍开关：可关闭屏震、闪光、hit-stop；低电量/低画质自动降级。

**验收**：不看伤害榜，5 名测试者能在固定视频中正确指出普攻、暴击、护盾、破盾、死亡和 Boss 大招，识别率 ≥80%。

## 8. Codex 建议执行批次

每批只解决一个可验证边界，建议按下列顺序给 Codex 下任务：

1. **V2-A 资源恢复**：P0-01～P0-02。没有可信 zip 就停在明确 blocker。
2. **V2-B 测试可信度**：P0-06～P0-08。先消灭 parse error 和假 PASS。
3. **V2-C 白模门禁**：P0-03～P0-05。产出材质 JSON、contact sheet 和清理回归测试。
4. **V2-D 战斗节奏**：P1-01、P1-05。固定 replay A/B，不改 final-state SHA。
5. **V2-E 视觉层级**：P1-02～P1-04。晶柱、护盾、立绘各自单独提交。
6. **V2-F 教程闭环**：P1-06～P1-10。自动跑完 17 步并做中断恢复。
7. **V2-G 发布/性能**：P1-11～P2-02。真机矩阵、包身份、内存和文档实况。

每个批次的交付都必须包含：

- 修前/修后截图或 JSON 对比；

- 若涉及 UI/VFX，再安装到明确 package ID 的真机重测。
