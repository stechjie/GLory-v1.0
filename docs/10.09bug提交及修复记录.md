## 第 1 条：棋盘上已有人王时，把商店的人王拖到棋盘空格被整个吞掉

**现场（用户原话）**：「当棋盘上人王时，从商店里拖动人王到棋盘上（即便此时棋盘上是一个一星人王，也不会自动升星），会显示『传奇棋子只能上场一个』，不会进行购买操作。」

**根因** `scenes/prep/PrepBoardController.gd` 的 `_buy_or_merge_shop_to_board()`：`target == null`（拖到**空格**）那一支只有一句 `show_message(tr("toast_unique_limit"))` + `return` ⇒ 玩家拖过来的那一枚既不升星、也不进备战区，**连钱都不扣**，整个操作被一句提示吞掉。

**修法**：这一支复用与「上阵已满」**完全同构**的分流函数 —— 原 `_auto_dispatch_shop_when_board_full()` 本轮**改名 `_auto_dispatch_shop_card()`**（两个调用点共用一份），按文档三条意图排优先级：

| 顺序 | 条件 | 行为 |
|---|---|---|
| ① | 棋盘上有同名同星、可升星 | **就地升星**（不占新格） |
| ② | 棋盘升不了、待命区有同名同星 | **在待命区升星** |
| ③ | 都升不了、待命区还有空位 | **落进备战区** |
| ④ | 都不行 | 这时才提示「传奇棋子只能上场一个」 |

★ 第 ① 步在这条路上是**活代码**，不是死代码：`_refresh_all()` 的第一步 `_auto_combine_all()` 会把棋盘 + 待命区的同名同星自动融合，所以稳态下棋盘不会挂着可合成的一对 —— 唯一能凑出一对的时刻，恰好就是「玩家正把商店这一枚放下」的当下。

**实拍取证**（`work/_qa_1009/probe_bug1_shot.gd`，走真实入口 `_drop_on_board(空格, {kind:"shop"})`，棋子固定用人王 `human_king`）：

| 情形 | 前置 | 拖动后 | 结论 |
|---|---|---|---|
| ① 能升星 | 棋盘 0 号格 1★ 人王、备战区 8/8 | 0 号格 **1★→2★**；金币 2000→1950；备战区不变；无提示 | 意图(1) |
| ② 升不了 | 棋盘 0 号格 2★、备战区 5/8 | 0 号格**仍 2★**；**备战区 5→6**（新人王落第 5 格）；金币 2000→1950 | 意图(2) |
| ③ 都收不下 | 棋盘 2★、备战区 8/8 | **不扣钱**、卡没买走、两边都不动；弹「传奇棋子只能上场一个」 | 意图(3) |

对照图 `其他/work/_qa_1009_fix/预览图/bug1_case{1,2,3}_*.png`。

**门禁** `tools/prep_1005_check.tscn` 81 → **100** 条（新增 `_setup_unique_board` + 三个用例）。变异：把唯一棋子那一支整段删掉 ⇒ 该组 9 条全红。

## 第 2 条：选了金钱类宝藏后，获得的技能按钮排进左下角宝藏区、无法使用

**用户意图**：「头像和羁绊之间还有一些空位，把『羁绊/宝藏』向上挪动，与头像处靠近，以腾出位置解决这个问题。」

**修法**：`SELL_LEFT_PANEL_TOP_RESERVE` 132 → **48**（＝ 头像底边 124 ＋ 间距 8 − `left_drop.y` 84），整栏上移 84px。

**实拍复核**（`work/_qa_1009/probe_layout_full_shot.gd`，非 headless）：满羁绊 = **最多同时出场 4 个种族**（赤灯使 `lattern` 不在商店池，`data/shop.json` 里没有任何 crimson id）＋ 5 枚 money 类宝藏全带。

## 第 3 条：3V3 结算后从大厅重进刚结算完的房间 ⇒ 按准备无反应、按离开提示「需要取消准备」

**用户要求**：「查一查无法取消准备是什么原因。」

**根因（两状态互锁）**

1. `team_local_slot == -1` —— 本次会话没有座位。结算房把没回来的人标成 `settling`，且不放进 `room.peer_slot`，于是 `NetworkService._send_room_state` **整份不发**（客户端留着旧状态）。
2. `_pending_ready == 1` —— 上一次「准备」的在途意图，而它是 `Main._lobby_exit_requires_cancel()` 的**唯一**判据之一。服务器那两条路让确认回包**永远不来**：`_rpc_team_set_ready` 在座位 state == `settling` 时**直接 return**（连 `_rpc_team_action_failed` 都不发）；`_send_room_state` 见 peer 不在 `peer_slot` 就**整份不发**。⇒ 意图撤不掉。

而两个出口互为唯一：`Team3v3Lobby._on_primary_pressed`（`my_slot < 0` 静默 return）与 `NetworkService.team_set_ready`（`team_local_slot < 0` 静默 return）。⇒ 玩家被**永久**锁在大厅。

**修法四条**（`scripts/autoload/NetworkService.gd`）

- `local_ready_intent()`：`team_local_slot < 0` 直接早退 —— 座位都没了，「准备」这件事不存在，不能拿它锁人。
- 新增 `_clear_pending_ready(reason)`：**意图与它的期限必须一起清**（漏一个就留下「意图永远在途」的状态）。`reset()` / `_on_server_disconnected()` / `_rpc_team_room_closed()` / `_rpc_settlement_room_switch()` 全部改走它。
- `_rpc_room_state` 尾部：除「回包 ready == 意图」这条原判据，再加「**本地座位已经不是 player**」（settling / empty / dummy / 被顶座 / 宽限转 AI）⇒ 也清。
- 新增 `READY_CONFIRM_TIMEOUT_SEC = 4.0` + `_tick_pending_ready()`：服务器既不确认也不回绝时兜底作废（这一版 ready 没有 request/ACK + revision，只能拿期限兜底，写法同 `_leave_deadline`）。`team_set_ready()` 无座位时补一行日志（以前一声不吭，真机现象「按了完全没反应」查无可查）。

★ C24 的「在途 ready ⇒ 不许退出」原窗口**保持不变** —— 有专门用例 `c24_window_kept` 钉住。

**门禁** `tools/lobby050607_check.gd` 9 → **18** 条（新增 6 条）。变异两处：`local_ready_intent` 去掉无座位早退 ⇒ 红 2；`_rpc_room_state` 去掉「座位不再是 player 也清」⇒ 红 1。

## 第 4 条：结算面板「本回合总造成伤害」没算元素伤害

**用户口径**：「元素伤害指的是四种元素的伤害，比如毒状态毒伤」，要**计入「本回合总造成伤害」、不计入棋子个人伤害**。

**实测结论（与直觉相反，先取证再动手）**：**普通棋子挂的毒早就计入** `stats[].damage_dealt` —— 自爆场景里归毒 18000 **全额**记在挂毒棋子名下（`work/_qa_1009/probe_poison_credit.gd`）。真正丢的只有两条**没有棋子身份**的路：

1. `BattleSimTreasures._process_death_explosions()` / `apply_death_poison_explosion()` —— 自爆灵的死亡爆炸**及其挂上的毒**：整段没有 stat source（自爆灵已阵亡、也不是这一击的攻击者）⇒ 实测爆炸 250 ＋ 毒 600 ＝ **850 全丢**。
2. `BattleSimulator._maybe_spawn_parasite_clone()` —— 寄生灵分身：`uid` 不在 `unit_stats` 里（每个 uid 只在开场登记一次），而 `DamageService._add_stat_value` **只认已注册的 uid**、否则静默丢弃 ⇒ 分身的普攻与它挂的毒无人认领（实测 500 ＋ 600 ＝ 1100）。

两条恰好都是**灵族**，所以现场表现就是「灵族 + 毒羁绊阵容只算了棋子伤害」。

**修法**

- `DamageService`：新增 `static var _element_owner_slot := -1` 与 `const UNATTRIBUTED_OWNER_KEY`；`begin_stat_context()` 从 fighter 的这个键取席位，`begin_stat_source_uid()` / `clear_stat_context()` 复位；`_record_damage()` 里 `_element_owner_slot >= 0` 即走 `_add_element_damage()` 并 **return（不写任何棋子 `damage_dealt`）**；`apply_sudden_death_damage()` 强制把旁路关掉再还原（环境伤害没有主人）。
- `StatusEffectService`：`add_poison` / `add_bleed` 把 `element_owner_slot` 一并存进 `params`，`_apply_dot_damage()` 结算时保存 / 还原。★ **两处数值缩放白名单都必须加 `element_owner_slot`**（`add_status` 的 dark_debuff_strength 一处、`_boss_reduced_params` 一处）—— 否则「对 boss 减半」会把下标 3 当成数值改成 1.5，毒伤就记错席位。
- `BattleSimTreasures.apply_death_poison_explosion()`：整段包在 `set_element_owner_slot(victim.owner_slot)` / 还原里。
- `BattleSimulator._maybe_spawn_parasite_clone()`：给分身打 `clone[UNATTRIBUTED_OWNER_KEY] = killer.owner_slot`（**不动 `clone.owner_slot`** —— 那是 duplicate 自受害者来的，动它会牵动羁绊解析）。
- `BattleSimulator.result_from_state()` 两个 return 都带出 `element_damage_by_slot`。
- `FinalSettlementData.build()` 用**同一套边选择口径**收账本（`slot < side*3 or slot >= side*3+3`，键一律 `int()` 归一 —— JSON 里会变字符串）并传给 `update_round_damage(seats, stats, element_by_slot := {})`；`FinalSettlementPanel._ready()` 也会二次重算，所以同样要传。

**门禁** 新增 `tools/settle_element_damage_check.tscn`，**32** 条，6 个用例：爆炸及其毒精确值（250 / 850）、分身（500 / 1100）、**已归属毒不双计**（防回归）、狂暴死亡不算元素、`update_round_damage` 并桶（含字符串键归一 + 默认参数不回归）、3v3 全灵族端到端恒等式「总伤害 ＝ Σ个人伤害 ＋ 元素账本」且 `grand_total > per_piece_total`。

变异 5 变体全 CAUGHT。另做**修复前对照**（`work/_qa_1009/prefix_equiv_check.py`，把元素旁路整体静音）：`dark_undead_20260929` 与 `crimson_integration` 的红数与修复前**一字不差**，而本门禁变红 5 条 —— 反向证明判据有判别力、且本轮的改动没有波及那两条既存红。
