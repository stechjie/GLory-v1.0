## 已确认的两个代码缺陷

1. **迟到报文被当作新握手。** ENet 删除断开端点的 DTLS peer 后，UDPServer 会将该端点后续的加密 alert/application data 当成新连接，送入期望 ClientHello 的 Mbed TLS，从而报 `-30464`。原版 Godot 4.7 在客户端优雅断开 3/3 次复现；人工向新端点发送非 ClientHello 数据报也能复现。修复在分配新 UDP peer 前，只允许 epoch 0 的 DTLS 1.0/1.2 ClientHello 类型报文进入握手。已存在/正在握手的端点不走此过滤，证书、cookie、分片、重传和握手内容继续交由 Mbed TLS 验证。
2. **Cookie 上下文重复清理。** `DTLSServerMbedTLS::stop()` 调用 `cookies->clear()`，随后引用析构再次调用 `clear()`；原实现释放后未复位 `inited`，导致三组 mutex 再次释放。修复清理时重置状态；保留 mutex 自身的错误检查，未屏蔽异常。

实现以 Godot 4.7 官方提交 `5b4e0cb0fd279832bbdd69fed5354d4e5ad26f88` 为唯一基线。补丁在 `deploy/engine/godot-4.7-dtls-admission.patch`，不是更改生产证书、关闭加密或删除错误输出。真实握手失败保留原 ERROR，并增加 `DTLS_HANDSHAKE_FAILURE remote=... code=...`；非法首包输出最多每秒一条 `DTLS_ADMISSION_DROP` 元数据。其 `count` 为自上次打印后的合计，不代表这些报文都来自打印的那个地址；最后未满一秒的计数可能没有后续输出。专服连接日志增加端点，便于之后将 peer ID、断连及 TLS 事件关联；客户端上传日志不增加这一字段。

候选引擎使用 release template。Godot 4.7 此构建默认禁用路径覆盖，初次启动门禁因此明确失败（尚未执行网络用例）。已在 Linux 的两个使用位置显式启用 `OVERRIDE_PATH_ENABLED`，保留专服现有 `--path` 和隔离测试 `--script` 启动方式；其余组件无此宏依赖，增量重编并重新链接后重跑全部候选门禁。另修正 `ClientLogService` 只在 debug 构建输出的条件：专服模式无论构建类型均输出到 journald，手机发布版仍保持原静音行为，避免更换引擎后丢失连接/诊断日志。

## 后续归因

历史缺失的报文无法通过新日志补回。新版本遇到非 ClientHello 首包会明确归类为 admission drop；若是真正进入 Mbed TLS 后失败，仍会记录错误码与端点。只有关联实际的新事件，才能进一步确认线上来源。短期无错或单次连接成功不等于所有历史错误已确认为同一根因。
