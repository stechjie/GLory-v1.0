# GLory 0.07(beta) 修复与验证

iOS 数字版本为 0.0.7。网络协议升为 33，服务器与客户端必须配套更新；旧协议 32 客户端需要升级。应用内部目录名保持不变，避免影响既有存档和服务器密钥位置。

## 修复

- 断线恢复：在座位凭证验证通过后，允许接管心跳已停滞至少 9 秒的旧连接；新鲜连接、错误凭证仍受保护。可靠回放发送增加每连接 32 KiB、全局 256 KiB 的未确认字节窗口；超过 20 秒无块确认只终止该回放传输并释放配额。
- 普通近战移动：改为扫掠检测和自身滑动，避免先穿入敌人再由双向分离推出敌人。出生重叠修正及显式技能击退保留。
- 战斗加载：备战时异步缓存战斗场景，预热已知棋子和特效；战斗准备显示阶段文字和进度条。未知敌方资源仍可能在入场时加载，有界缓存避免无限预热。
- iPhone 语音：增加 LiveKit Swift 原生桥接、系统麦克风权限申请、用途声明和动态框架；修复等待授权和切换语音状态的时序。
- 长录像：重复死亡棋子帧采用无损引用编码，展开时恢复独立帧，并验证展开大小上限。

## 已验证

- 普通移动复现：旧逻辑在 600 ticks 内把站定目标推出 482.312 px；修复后的碰撞检查 61 项通过，显式恐惧击退保留。
- 服务器调度 315 项；回放编码 119 项；回放交付与配额清理 159 项；心跳 24 项；语音状态机 395 项通过。测试记录保留于本地 reports/mobile-fixes-20260926。
- 最新运行时代码公网 DTLS 压测：2 vCPU 服务器、4 个独立客户端进程、120 人/30 房/5 波，600/600 次回放交付，断线和心跳超时为零。
- iPhone build 16 原生组件测试：授权成功，另一端收到 1271 帧非静音音频；关麦后双端状态一致。用户确认听到反向发送的两声提示音。未保存录音。
- Android 真机备战预热对照：第 1 回合入场准备从 11.259 秒降至 6.141 秒；第 21 回合约 11.9 秒，未见改善。正常播放约 60 FPS。

## 仍需说明的边界

120 人测试证明该负载下连接及交付稳定；每波等待仍约 100–152 秒，不代表高并发战斗等待体验已达标。真实蜂窝运营商网络、最终发布包完整游戏流程需单独验收。预热不是消除加载，且增加显存占用。

Godot 4.7 在 DTLS 退出时仍有三条已知互斥锁诊断；压测运行期未发现引擎错误，不将退出诊断隐去。iPhone 原生组件验收不等同于已覆盖耳机路由、拒绝后恢复、所有前后台切换场景。

## 发布验收

同步 GitHub 和 Drive 后，以同一提交生成产物。每个 IPA 必须通过 tools/package_content_check.py、签名和框架检查，并安装到真机。服务器使用独立版本目录、保留旧版本，部署前确认房间排空，部署后验证协议、端口和实际房间列表响应。Git push 以远端提交 SHA 为准；资源仅上传有变化的内容及校验清单。
