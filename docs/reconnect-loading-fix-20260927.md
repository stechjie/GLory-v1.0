# 2026-09-27 重连与战斗加载修复

## 现场证据

北京时间 10:30–11:00 的 `glory-server.service` 日志中，10:45–10:55 多个 protocol=33 客户端发生 `rpc node checksum failed`，建房请求被识别为其他 RPC 并拒绝；同一时段也有成功恢复 room=200233 的记录。线上 NetworkService.gd 的 SHA-256 与发布提交 327628ed、本次修改前 main 一致。不能仅凭协议数字或窗口中旧的 0.04 标题判断客户端与服务器一致，也不能把所有玩家的断线归为同一个原因。

## 行为变更

- 协议 34 在认证阶段校验编译后的 RPC 配置和方法参数/返回类型指纹。不同方法表即使误用相同协议号，也明确拒绝为版本不匹配，不再错派建房、状态查询或重连请求。客户端与服务器必须成套更新。
- 后台查询旧对局复用正在建立的连接；前台手动恢复或 reset 会使旧查询失效。旧结果不能清除新恢复的凭证，也不能保留旧查询锁。认证与状态回复分别计时。
- 有在线队友的对局一直保留原座位恢复能力；无人在线的对局暂停计算，恢复窗口由 30 秒延长为 30 分钟，结束或到期后解除新建房间限制。网络状态不明时保留凭证和重连入口。
- 战斗加载文字和进度条放入独立、不透明的中央卡片，避免与顶部 HUD 重叠；卡片跟随进度条一起释放。
- 部署时预取当前回合模型、贴图；点击准备后，等待队友/服务器期间仍继续特效预热，直到真正交接战斗场景。继续使用资源所有权和增量缓存，不预装整局所有资源。
