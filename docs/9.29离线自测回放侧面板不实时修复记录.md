# 9.29 离线自测「大祭司技能没生效」——回放侧面板不实时修复记录

> 日期：2026-09-30（承接 9.29 第三轮）
> 诉求原文：离线自测面板攻速等属性未实时同步，此前已优化过但仍有问题；大祭司的技能在面板上并未生效。
> 用户要求：**先判定是「技能未生效」还是「面板不正确」**；若是面板不正确则修复并实时显示、更新 README、备份改动文件；**若是技能未生效则不要急着修，等指令**。
> ★ 用户纠正：截图下方**两只都是大祭司**（不是神侍）。这一点很关键——两只大祭司互为「最近友军」，技能应互相加强。

## 〇、结论先行

**判定：技能生效，面板不正确。** 已按用户指令修复。

- 真实模拟里大祭司技能**完全生效**：1★ `26 / 0.900 → 28 / 1.050 → 30 / 1.200`；4★ 攻击 `90 → 119 → 157 → 207`、攻速 `0.900 → 1.350 → 1.800 → 2.250`。
- 面板恒显基准值 `26 / 0.900`，**与技能叠了多少层无关**。
- 根因在**回放侧**（离线自测「开始测试」走先录帧后回放的路径），与前两轮修的**实时模拟侧**不是同一条路。

## 二、根因：回放帧是 13 列冻结结构，不含攻/攻速/防/暴击

### 2.1 离线自测有两条路径，前两轮只修了一条

| 路径 | 入口 | 前两轮是否修到 |
|---|---|---|
| **实时模拟侧** | 直接跑 `BattleSimulator`，就地改写 fighter 活字段 | ✅ 第一、二轮已修 |
| **回放侧** | `OfficeTestSim.compute_test_replay_async` —— **先录帧、后回放** | ❌ 本轮才修 |

### 2.2 断在哪一层

`BattleSimulator._replay_capture_frame` 只写 **13 列冻结结构**：

```
uid / pos / hp / alive / attack_count / skill_ready / shield /
skill_stacks / statuses / damage_dealt / ...（共 13 列）
```

**不含 `atk` / `attack_speed` / `defense` / `crit_bonus`。**

回放时 `BattleScreen._apply_replay_frame` 只回填帧里有的字段 ⇒ 回放侧的 fighter 对象里，**这四个字段永远是 `def` 基准值** ⇒ 面板的 `live_attack_speed` / `live_defense` / `live_crit` 一路读到基准（26 / 0.90），**无论技能叠了多少层都不动**。

这正是用户截图的现象：状态栏写着「攻速提升」、面板攻速却是死的。

### 2.3 为什么不能给 `frames` 加列

- `frames` 是**冻结结构**，加了列会改冻结哈希；
- 联机回放的字节数会跟着漂（`replay_transport` 的 `bytes=2093425/2093425` 这类断言会动）；
- 老回放包与新客户端的兼容性也会受影响。

⇒ **另带一条旁路**，不动 `frames` 本身。

## 三、修法：活字段旁路快照 `live_stats`

### 3.1 录制侧 `officetest/OfficeTestSim.gd`

在 `compute_test_replay_async` 的录帧循环里，每步之后调 `_capture_live_stats`：

- 只为「数值发生变化」的那一帧记一条（不是每帧都记，避免 payload 膨胀）；
- 每条记录 `{ "f": 帧号, "atk": 攻, "as": 攻速, "df": 防, "cb": 暴击加成 }`；
- 只在 `live_stats` 非空时挂进 payload ⇒ **联机回放 payload 没有这个键，行为完全不变**。

```gdscript
static func _capture_live_stats(state: Dictionary, frame_index: int,
        live_stats: Dictionary, last_live: Dictionary) -> void:
    for f: Dictionary in (state.get("player", []) + state.get("enemy", [])):
        var uid := str(f.get("uid", ""))
        if uid.is_empty(): continue
        var atk := int(f.get("atk", 0))
        var aspd := float(f.get("attack_speed", 0.0))
        var dfn := int(f.get("defense", 0))
        var cb := float(f.get("crit_bonus", 0.0))
        var prev: Variant = last_live.get(uid, null)
        var changed := true
        if typeof(prev) == TYPE_ARRAY and (prev as Array).size() == 4:
            var p: Array = prev
            changed = int(p[0]) != atk or absf(float(p[1]) - aspd) > 1e-6 \
                or int(p[2]) != dfn or absf(float(p[3]) - cb) > 1e-6
        if not changed: continue
        last_live[uid] = [atk, aspd, dfn, cb]
        if not live_stats.has(uid): live_stats[uid] = []
        (live_stats[uid] as Array).append(
            {"f": int(frame_index), "atk": atk, "as": aspd, "df": dfn, "cb": cb})
```

### 3.2 显示侧 `officetest/OfficeTestScreen.gd`

- 新增成员 `_live_stats`，在 `_start_replay(replay)` 里从 `replay.get("live_stats", {})` 取；`_return_to_edit()` 清空。
- `_refresh_stat_panel()` 里把 `var f: Dictionary = value` 换成 `_patched_with_live_stats(value)`。
- `patched_with_live_stats(f, live_stats, frame)` 取「≤ 当前帧的最近一条」补进**副本**（`f.duplicate()`）。

★ **必须写副本**：回放侧的 fighter 对象是**跨帧复用**的，直接改它 ⇒ 数值会串帧污染。门禁里钉了 `patch_mutates_input` / `patch_no_copy` 两条结构断言。

★ 实现写成 `static`，供探针与门禁直接调用（重型场景不能 headless `new()`）。

## 五、本轮踩坑与仓库纪律

★ **批跑不要加 `--quit-after`**：本轮给批跑脚本加了 `--quit-after 180`，导致 `battle_playback_stability`、`replay_transport` 等长门禁**在跑完前被强制退出**，表现成 `NO_RESULT` 的**假失败**。批跑器原参数是纯 `--headless --path`（不带 quit-after，靠 `subprocess timeout=300` 兜底）。已修正脚本并写进注释。

★ **判定先于修复**：用户明确要求「是技能未生效还是面板不正确」先分清楚——**若属技能问题必须停下来等指令**。本轮先跑真实模拟证明技能生效，才动手改面板。

★ **结构断言要限作用域**：`patched_with_live_stats` 是 `static func`，切函数体时 `\nfunc ` 截不断 `\nstatic func `（本仓既有教训的变体），判据用三锚点取最短。

★ **变异脚本四道加固**：`.r4bak` 备份 + 还原只认备份 / 残留拒跑 / SIGTERM·SIGINT 兜底还原 / 基线先绿；`subprocess.run(timeout=...)`；锚点按目标文件行尾归一（本仓 `.gd` 纯 CRLF）。
