## 2. 席位原有分层

`_build_slot()` 里同一个席位按「后加的在上面」叠了四层：

```
slot.png 木环底板 (184x175 @ 基点)
  → 圆头像 (106x106 @ +39,+40，圆形 shader 裁圆)
  → 玩家的头像框 (160x160 @ +12,+13，不裁圆)
  → 铭牌复本 (AtlasTexture 取 slot.png 的 region，86x35 @ +48,+135)
圈外名牌 / 状态字 / X 按钮 / ±AI 按钮 各自独立，不在圈内
```

关键几何（`SLOT_POS` 上排 y=229 / 下排 y=502，x=447/739/1015）：

- 头像 106 @ (39,40) ⇒ 中心 **(92,93)**
- 头像框 160 @ (12,13) ⇒ 中心 **(92,93)**
- 圆盘 160 @ (12,13)，素材内孔中心也在 (92,93)（下面第 3 节实测）

⇒ 三分支**头像中心是同一点**，这是「切换默认框 ↔ 自定义框时头像不横跳」的依据。

## 4. 实现要点

```gdscript
const TEX_PROFILE_AVATAR := preload("res://assets/ui/main_menu_live/profile_avatar.png")

func _apply_slot_frame(index, identity, state) -> void:
    var occupied := state in ["player", "settling"]
    ...
    var custom := occupied and not frame_id.is_empty() and frame_id != "frame_default"
    ...
    _slot_frames[index].visible = custom
    _slot_bases[index].visible = not occupied              # 玩家席隐藏木环
    _slot_frame_bases[index].visible = occupied and not custom  # 无框才画圆盘
    _slot_plates[index].visible = occupied                 # 玩家席一律补铭牌
    # 头像落点：有框 78@(53,54) / 无框 106@(39,40)，改完就地 _apply_tracked()
```

- **底图引用原先被丢掉**：`_build_slot()` 里是裸调用 `_add_texture(TEX_SLOT, pos, SLOT_SIZE)`，
  返回值没保存 ⇒ 想隐藏木环没有把手。新增 `_slot_bases` / `_slot_frame_bases` 两个数组。
- **铭牌复本必须扩到「所有玩家席」**：那块六边形木牌本来就画在 `slot.png` 里，底图一隐就
  跟着没了。原先只在有自定义框时补（那时是怕被框盖住），现在改成玩家席一律补。
- **空位 / 假想敌完全没动**：`occupied` 为假时底图照旧显示、圆盘不画、框不画、
  铭牌复本也不画（吃底图自带那块），头像不可见、落点仍是 106@(39,40)。
- **落点必须落节点**：`_placed` 只是期望值，改完必须 `_apply_tracked()`。
  换座（`_on_slot_pressed`）与加/减 AI 之后**只调 `_refresh()`、不调 `_layout()`**，
  只写 `_placed` 不落节点会让头像停在旧位置旧尺寸（10.01 第 4 条同型的坑）。

## 6. 二轮：形状修复（被压成椭圆 → 与大厅一致）

**用户反馈（真机测试）**：「测试后发现一个问题，形状发生了改变，变成了椭圆。但是大厅的形状是圆的」。

**根因**：`_add_texture()` 内部写死 `rect.stretch_mode = TextureRect.STRETCH_SCALE`（值 **0**）
= **非等比拉满矩形**。大厅 `MainMenu` 那两处走的是 keep-aspect 系：

| 节点 | 位置 | 拉伸方式 |
| --- | --- | --- |
| 大厅头像框 `_profile_frame_art` | `MainMenu.gd` | `STRETCH_KEEP_ASPECT_CENTERED`(5) |
| 大厅金棕圆盘 `_profile_base_frame` | `MainMenu.gd` | `STRETCH_KEEP_ASPECT`(4) |
| **席位头像框（改前）** | `Team3v3Lobby.gd` | `STRETCH_SCALE`(0) ← 罪魁 |
| **席位金棕圆盘（改前）** | `Team3v3Lobby.gd` | `STRETCH_SCALE`(0) |

商城五张框素材都不是方图（竖长），实测 W/H：`emerald` 0.889 / `frost` 0.773 /
`dragon` 0.845 / `astral` 0.789 / `inferno` 0.798；金棕圆盘 850×825 = 1.030。
拉满 160×160 的方盒子 ⇒ 横向被压扁 ≈1.28 倍 ⇒ 看起来就是椭圆。

**修法**（与大厅一一对应，不新造口径）：

```gdscript
var frame_base := _add_texture(TEX_PROFILE_AVATAR, pos + SLOT_FRAME_POS, SLOT_FRAME_SIZE)
frame_base.stretch_mode = TextureRect.STRETCH_KEEP_ASPECT       # 同大厅圆盘
...
var frame := _add_texture(null, pos + SLOT_FRAME_POS, SLOT_FRAME_SIZE)
frame.stretch_mode = TextureRect.STRETCH_KEEP_ASPECT_CENTERED   # 同大厅头像框
```

**量化**（纯黑底、只留目标节点渲染，量非背景像素包围盒的 W/H）：

| 对象 | 画出来 W/H | 素材 W/H | 倍率 |
| --- | --- | --- | --- |
| 席位框 · 改前 | 1.0263 | 0.7980 | **×1.286（压扁）** |
| 席位框 · 改后 | 0.7961 | 0.7980 | ×0.998 |
| 大厅头像框 | 0.8012 | 0.7980 | ×1.005 |
| 席位金棕圆盘 | 1.0461 | 1.0420 | ×1.004 |

改后席位与大厅差 0.6%（像素取整级别）；圆盘另确认居中无偏移。

**门禁新增 6 条**（63 → 69）：`lobby_modes`（前提体检：大厅自己那两个节点若也在拉满矩形，
下面的比对就没意义）、`frame_mode_like_lobby`、`base_mode_like_lobby`、`no_stretch_scale`、
`aspect_preserved`、`non_square_frames_exist`。

**判据不抄常量**：`frame_mode_like_lobby` 不是「席位 == 5」这种硬编码，而是**真建一个大厅页**
（`class MenuProbe extends "res://scenes/menu/MainMenu.gd"`，`_ready()` 只跑 `_build() + _layout()`、
不启动 BGM），读它那两个节点的实际取值来比。抄常量就是两个真相，以后改一处忘另一处，门禁照样绿。

### 自查订正：`aspect_preserved` 原本是**恒真的自证式断言**

第一版写的是「无条件按保持比例去算落点，宽高比必然等于素材宽高比」—— 这是数学恒等式，
**变异前后都真**，属于无声失效：M11 把 mode 改回 `STRETCH_SCALE` 时它照样 PASS。
改成**读生产节点当前生效的 `stretch_mode`** 之后再算（`_drawn_ratio()`：`STRETCH_SCALE` ⇒
返回盒子比例；keep-aspect 系 ⇒ 返回素材比例），M11 才多红这一条（偏差 0.2265）。

另注：`KEEP_ASPECT_CENTERED` **不改 `Control.size`**，只在盒子里留黑边 ⇒ 光看节点尺寸
是量不出椭圆的，只能看 mode；像素级证据在渲染图里，不在 headless 门禁里。

### 三条自查订正（如实记录）

1. **M8 第一版是「变异本身写错了」**：`TRACK_TAIL[:2]` 保留的其实是
   `_apply_tracked`、删掉的是那句无害的 `return` ⇒ 变异无效 ⇒ GREEN 是**正确结果**，
   不是门禁漏判。改正成「只留 `[size, return]`」后 RED。
   结论：**「变异 GREEN」要先怀疑变异，再怀疑判据**。
2. **M8 能咬住的断言原本只有 `switch_size` 一条，margin 太薄**：
   `_ready()` 里 `_refresh()` 之后紧跟 `_layout()`，会把偏差抹平，所以只有
   「只调 `_refresh()`」那几步照得出来。补一条通用不变式：在那个时刻逐席比对
   头像节点实际尺寸与 `_placed` 期望值（`tracked_0..5`）。

3. **M9 第一版会让门禁崩**：直接改回 `_add_texture(TEX_SLOT, ...)` 裸调用 ⇒
   `_slot_bases` 元素为 null ⇒ 门禁读到 null 抛 SCRIPT ERROR、进程被宿主按轮次闸门
   砍断，污染留在生产文件里。换成「节点还在、只是贴图不对」后干净 RED。
   ⇒ 变异要挑「能被判据判掉」的形态，别挑「让门禁崩掉」的形态。

# 三轮（2026-10-02）：任意头像框下，头像都一样大

## 10. 需求与根因

> 还是存在问题：同样一张图片，其他头像框显示的图片大小和默认头像框显示的图片不一样，
> 会变小。现在要求不管是大厅的头像，还是房间的头像，用任意头像框，大小都应该和默认
> 头像框的一致，**头像框也同步修改**。
> （中途修正）修改下，头像的位置**不偏移往下**，而是**允许头像框超出屏幕外**。

拆成两条可判定承诺：

| # | 承诺 | 判据落点 |
| --- | --- | --- |
| A | 同一张立绘，戴任意框与戴默认框，**可见直径相同** | 三方渲染量测 + `bbox == 头像直径` |
| B | 头像框**按内孔反推尺寸**，内孔几何与默认圆盘重合 | `frame_drawn_size` / `frame_box_origin` + 两张数据表 |

### 根因（三条，都是量出来的，不是推的）

1. **旧口径主动缩头像**。`MainMenu` 里除了 `_profile_portrait`(123) 还额外有一个
   **78×78 的 `_profile_frame_portrait` 专门给「戴了商城框」用**；房间席位同理
   （`SLOT_FRAME_AVATAR_SIZE = 78`）。于是同一张立绘，**戴上框就从 123 缩到 78**
   （−37%），这就是玩家报的「变小」。
2. **框是固定盒 + 保持比例 ⇒ 内孔远小于头像**。五张商城框素材 W/H = 0.773~0.889
   （都是竖长），塞进 160（或 180）的方盒后按长边贴满，画出来宽度只有盒的 8 成，
   内孔自然装不下 106 / 123 的头像 —— 旧口径「把头像缩到 78」正是在迁就这件事。
3. **框盖在头像上面**。默认圆盘是**垫在头像下面**的（内孔看不见，露出来的只有外圈金环），
   而自定义框是**后加的 ⇒ 盖在头像上**，它那道圆内孔会实打实切掉头像边缘。
   同一份头像、不同内孔的框，切掉的量还不一样 ⇒ 大小不一。

## 11. 新口径

> **头像尺寸恒定；框画在头像下面；框的内孔几何对齐默认圆盘。**

三条缺一不可，且都是**结构**上的（不是调数值碰运气）：

1. **头像恒定**：房间恒 106@(39,40)、大厅恒 123@圆盘中心。三分支（无框 / 默认框 /
   自定义框）共用同一个头像节点，不再有那个 78 的副本（大厅的
   `_profile_frame_portrait` 直接删掉，房间的 `SLOT_FRAME_AVATAR_POS/SIZE` 删掉）。
2. **框画在头像下面**：`_build_slot()` / `_build()` 里加 `move_child(...)`，把框挪到
   头像之前。于是**头像的可见像素与戴哪个框逐像素无关** —— 这是「一样大」的结构性保证。
   与默认圆盘同一层次，观感也一致。
3. **内孔几何对齐默认圆盘**：
   - 目标内孔直径 = `圆盘盒边长 × 默认框内孔占比`，房间 `160×0.6271≈100.3`、
     大厅 `180×0.6271≈112.9`（都 **小于**头像，所以头像盖得住、不会露背景缝）；
   - 绘制宽度 = `目标内孔 ÷ 该框自己的内孔占比`（`AvatarCatalog.frame_drawn_size`）；
   - 框盒落点 = `圆盘中心 − 该框自己的内孔圆心偏移 − 绘制尺寸/2`
     （`AvatarCatalog.frame_box_origin`）—— **必须**走这个函数，因为 6 张商城框的

## 12. 渲染量测（三方对照，决定性）

难点：`KEEP_ASPECT_CENTERED` **不改 `Control.size`**，节点尺寸看不出「画出来多大」；
而「头像可见直径」在「框在头像下面」时**天然等于头像自己的直径**，也照不出漏缝
（缝在头像**外面**）。所以每次渲三张：

| 张 | 内容 | 用途 |
| --- | --- | --- |
| A | 框 + 头像 | 量「头像可见直径」 |
| B | 只有框（无头像） | 标出「框没画到的区域」 |
| P | 既无框也无头像（原图） | 漏缝检测的基准 |

`A − B` = 头像真正露出来的像素（从质心往 720 个方向取中位数 ×2 ⇒ 与内孔占比同口径）；
`|A−P|<δ 且 |B−P|<δ` 且落在「头像外一圈环带」= 露了背景（漏缝）。

| 位置 | 默认圆盘 | 6 张商城框 | 结论 |
| --- | --- | --- | --- |
| 房间席位 0 | 101.5 | 102.0 ~ 102.5（+0.5% ~ +1.0%） | bbox 全为 `106×95` ⇒ 可见范围就是头像节点本身 |
| 大厅资料卡 | 123.0 | **123.0（+0.0%）** | bbox 全为 `123×123` ⇒ 头像是个完整的圆，**没有缝** |

- 房间的 +1% 是量测口径的偏差（AA 边在「深棕圆盘」与「框内孔透出的背景」上的对比度
  不同，阈值吃到多一列像素），改动前后同为 106 宽，不是真变大。
- 大厅逐帧 **+0.0%**、`bbox` 全 123×123 —— 这是「头像可见像素与戴哪个框无关」的直接证据。

### 五条自查订正（如实记录）

1. **第一版口径「内孔 ≥ 头像」写反了**：漏缝的条件是内孔**比头像大**（头像盖不住内孔），
   不是小。frame_hole_check 第一版的 `*_no_gap_*` 断言按反的方向写，12 条全红 ——
   正是这 12 条红逼出了「内孔圆心偏移」这张表。改对方向后全绿。
2. **「内孔 = 头像直径」与「内孔 = 默认圆盘内孔」的效果并不等价**（玩家提问过这一点）：
   在「框画在头像**下面**」这个正确层次下，**两者的可见结果确实相同**（内孔边界永远被
   头像盖住），所以玩家的直觉是对的；但**框的绘制尺寸不同** —— 取头像直径时最厚的
   炽焰之心要画 219 宽、左边缘直接出屏；取默认圆盘内孔只需 197 宽。选了后者。
3. **偏移的素材侧测量只有亚像素级稳定度**：炽焰之心的火焰把内孔边界挤得很碎，
   两套独立实现（射线+最小二乘 vs 洪水填充质心）给出的圆心差 5px（素材坐标），
   换算到绘制坐标 <1px。所以判据按**绘制坐标**判 1.5px，而不是按素材分数判 ——
   按素材分数判会为了一个不可见的量把门禁调松。
4. **占比表的数值口径变了**：由「从**图心**打 180 向射线」改成「从**内孔圆心**打 720 向
   射线」（因为圆心偏移必须与占比同源，否则两者互相矛盾）。旧值 0.6683/0.5951/… 相应
   变成 0.6617/0.6122/…。量产脚本 `frame_hole_table.py` 与门禁 `frame_hole_check.gd`
   用**同一套算法**，对表偏差 ≤0.0053。
5. **S9 第一版锚点静默失效**：`TAB*3 + "_apply_tracked(placement)"` 命中了 **3 次**
   （行匹配不是行首锚定，4 个 TAB 的行里也含这串）⇒ `expect=1` 不满足 ⇒ 打上
   `VERDICT SKIP`。脚本里「锚点 0 命中判 SKIP、不算过」的设计正是为了拦住这类
   无声失效；换成三行锚点后 RED。⇒ **锚点要长到唯一，且必须把 SKIP 当失败看。**
