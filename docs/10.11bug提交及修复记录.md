### 第 3 / 9 条 presence 标记 `in_match`（推翻 9.29）
- **旧名与旧迁移继续禁**：`room_started`、`database/022` **不许回来**；新字段是 `in_match`（迁移 032）。
- `database/032_presence_in_match.sql`（LF）：`alter table player_presence add column if not exists in_match boolean not null default false`。
- 后端：`presence.heartbeat(..., in_match=False)` 写该列；`should_notify()` 多了「进/出对局」这一种跳变；
  `_notify_watchers()` 的 payload 带 `in_match`，**隐私口径与 `room_id` 同一个开关**；
  `friends._in_match_visible(online, room_visibility, in_match)` 是唯一判据（不在线 / 关掉房间可见性 / `None` 都不算）；
  `FriendSummary.in_match` + `FriendItem.in_match` 带出；`HeartbeatBody.in_match: bool = False`（**默认 False 是给旧客户端**）。
- 客户端：`NetworkService.is_in_match()`（① 阶段 ∈ prep/battle/result ② 本地房主退回 `team_round_active` ③ **还留着 `match_started` 的可重连凭证** ⇒ 掉线或手动退出但局没结束也算在对局中）；
  `AccountManager.configure_presence(...)` + `_send_presence()` 上报；`Main._install_presence_reporting` 接线。
- 第 3 条 = `PartyLobby` 三档；第 9 条 = `Team3v3Lobby._can_invite_online_friend()` 只收「在线且不在对局中」。

### 第 7 条 对局内 30 秒无活人 ⇒ 自动结束（作废、不结算）
`scripts/autoload/NetworkService.gd`：
- 新增 `const NO_LIVE_HUMAN_END_SEC := 30.0`；
- `_finish_abandoned_match(room, winner_slot, end_reason="last_human_online")` 加第三参；`winner_slot < 0` = 作废，`outcome := TeamOutcome.DRAW`；
- 新增 `_tick_void_watchdog()` / `_void_room_eligible()` / `_room_live_human_count()` / `_void_abandoned_match()`；
- 1 秒 tick 里 `_tick_reserved_seats()` 之后调 `_tick_void_watchdog()`；
- `_rpc_abandon_seat()` 给座位打 `manual_exit_slots[slot] = true`（手动退出 = 已掉线 >30s，立刻不算活人）。

★★ **两条反直觉但故意的判据**：
1. `_void_room_eligible()` **刻意不跳 `suspended`** —— 「全房零在线真人、还留 token 等人回来」正是本规则要收掉的状态；
   `_last_online_human_winner()` 跳它是为了「没走光前别急着判胜」，语义相反。
2. **必须有真人座位**才判 —— 不加这条，纯 AI 房 / 单人练习一开局就自杀。

### 第 7 条「退出对局 = 掉线 > 30 秒，但保留重连」
`abandon_started_match()` 重写：本地房主 / 未开打照旧清场；**打过的局**改走 `_notice_manual_exit_then_reset()`
（发 `_rpc_manual_exit_seat` 后 **await 两帧** 再 `reset()` —— ENet 同帧断开会把刚排队的包直接丢掉）。
新增 `_rpc_manual_exit_seat(token)`：**刻意不调 `_clear_seat_metadata`、不 erase token**，只打 `manual_exit_slots[slot] = true` + `human_offline_since[slot]`，并校验 `get_remote_sender_id()` 就是座位主人。
⚠️ 用 `_rpc_manual_exit_seat` 而**不是** `_rpc_abandon_seat`：后者会抹掉座位上的账号信息、把座位转 AI，结算时跑路的人反而一分不扣；而且它前面有 `_active_match_for_token` 那道闸，对**正在打的局根本不生效**。
`_confirm_exit_for_new_match()` 确认后 `abandon_started_match(); return false`（**退出不等于放行新局**）。
文案（`MatchExitPenalty.gd`）改成「退出后你这一局按掉线处理：能点主菜单的『游戏重连』回来，这一局结束前开不了新局。」

### 第 8 条 升级石星爆（新组件 `ui/components/StarBurst.gd`）
**纯 `_draw()`**，刻意不用 `StyleBoxFlat` / 贴图 —— 本仓 `procedural_ui_ratchet` 是只降不涨的棘轮，用 StyleBox 实现这层光会把棘轮顶红。
- ① `HALO_STEPS = 4` 层同心核光；② `RAY_COUNT = 10` 根星芒（长 1.0 / 短 0.6 交替，每根沿长度切 `RAY_SEGMENTS = 5` 段做由内向外衰减 + 尖端消失）；③ 中心亮核。
- 呼吸 `BREATH_PERIOD_SEC = 5.0`、`BREATH_FLOOR = 0.55`（**最暗不归零**）；相位按 `get_instance_id()` 错开；`mouse_filter = IGNORE`；不可见时 `_process` 直接 return。
- 接线：`CarrotCampPanelV3` 每格石头（天青 / 地绿 / 人红）在 `refresh()` 里 `burst.visible = count > 0`，星爆层是 `box` 的**第一个子节点**（先画底板 → 再星爆 → 再图标文字）；
  `PrepUI` 营地**入口按钮**按队伍里任意一颗升级石亮。

★ 用户后续两轮口径收敛（最终版）：入口星爆改成**冰蓝白、明暗交替、从图标中心向外探出约 20px**，且**天 / 地 / 人三格不许动**。

## 本轮顺带抓到并修掉的真缺陷（第 8 条演示截图时）
**营地入口按钮上的星爆从来没画出来过。**
- 根因：`PrepWidgets.make_framed_text_button()` 返回的是**普通 `Button`（不是 `Container`）**，挂上去的子 `Control` 尺寸不会自动铺满 ⇒ `carrot_burst.size == (0,0)` ⇒ `StarBurst._draw()` 在 `radius <= 1.0` 处**直接 return，一个像素都没画**；而 `visible` 一直是 `true` ⇒ 只验 `visible` 的门禁**完全漏掉**。
- 修：给入口星爆补一行 `carrot_burst.set_anchors_and_offsets_preset(Control.PRESET_FULL_RECT)`。
- 门禁加固：新增 `_assert_drawable()`（可见时必须 `size.x > 1 and size.y > 1`）+ 结构断言钉这一行。
- ★ 同族老坑提醒：**「存在」≠「被正确赋值」**。
