# Glory 非 UI 视觉统一化：改进清单与 Codex 执行计划

日期：2026-09-06 · 审查基线：本机源码 `cc40801` · 状态：**仅完成审查与方案，全部实施项尚未执行。**

## 1. 建议采用的方向

**保留现有 UI，将其他内容统一为“暖金木石、切面造型、手绘色块的奇幻微缩棋盘”。** 角色像放进这个世界的精致棋子；森林、雪地和熔岩保留各自环境色；技能保留人、神、暗、亡灵的识别色，但共同采用明确的大形、有限的明暗层次、受控的高光与一致的接地关系。

这条路线适合当前工程：主菜单、卷轴、族标和主要战场底图已经提供了足够清楚的视觉基准；已有 toon 材质、角色包装器、特效模块和验收工具可继续使用。优先统一**实际材质、贴图细节、灯光、描边、比例、阴影、特效显示规则**，再处理无法通过这些手段改善的个别模型。不建议整库重建、切换引擎或为统一文件后缀而批量转换模型。

本方案用“样板通过 → 按同一规范推广 → 全量检查 → 实战同框验收”保证可执行性。**方案本身不等于已经取得统一画面**；缺失源资产恢复、样板视觉通过、真实渲染和真机预算通过，是宣布完成的必要条件。没有通过的条目必须保留为未完成，不能用“文件存在”“套了同一个 shader”代替。

## 3. 改动边界：UI 是固定参照

### 3.1 冻结清单

| 必须保持 | 范围 |
|---|---|
| UI 源素材与导入效果 | 工程内 `ui/**`、`assets/ui/**`、`assets/fonts/**`；按钮、框、族标、头像、立绘、商店卷轴、宝藏卡、HUD 水晶和字体 |
| 页面外观与交互 | 布局、尺寸、锚点、层级、文字、配色、点击区域、教程气泡、菜单/大厅背景及装饰；即使文件同时含世界代码也只改允许函数 |
| 战斗信息层 | 头顶血条、名称、伤害文字、状态图标、排行榜、HUD；不得用全屏后处理给这些内容调色 |
| 已有操作反馈 | 备战格圈、选择/拖拽/射程提示、待命格底板、UI 按钮/卷轴上的特效；包括 `assets/vfx/prep/**` 和关联反馈脚本 |
| 阵营与规则 | 阵营颜色、选中语义、预警范围、棋盘格、三路、碰撞与寻路、技能判定、命中时刻、回放确定性 |

特别注意：文件夹名字不能完全决定边界。`assets/vfx/status/` 中的图标及 `assets/vfx/skills/distinct_v2/stun_star_mark_v2.png` 都属于 UI，身体光环才属于可调世界效果；`FormationCrystal.gd` 是备战 HUD 水晶，不属于可改的战斗结算 3D 水晶。`BoardReadabilityStyle.gd` 的共享颜色同时影响操作提示，本计划只读参考，不改其已有值。

[VFXStatusEffect3D](/Volumes/repository/github/GLory/GLory-v1.0/effects/vfx3d/modules/VFXStatusEffect3D.gd:67) 的 `StatusReadableIcon` 与 `StatusMote_*` 当前共用profile。实施前必须隔离消费者：图标保留原材质、大小、位置、时序、颜色和能量，仅身体粒子/光环接新世界样式。否则调根节点size、opacity或调色就会间接改变UI。世界视口内的UI还须保护其最终输出响应；更改tonemap后若图标变色，应通过独立信息层/保留原渲染响应解决，不能直接接受偏差。

### 3.2 本计划允许修改

角色/怪物/Boss/援军/佣兵/宠物的 3D 显示材质、专用运行贴图、必要的网格优化；非 UI 的棋盘背景、河流和世界装饰；世界灯光、相机渲染质量、接触阴影、分路环境特效；技能的主体/弹道/冲击/地面光环。相机位置、投影与棋盘映射首轮冻结，只统一灯光和画质参数；需要改构图时另做有锚点回归的后续项。

菜单宠物和卡片内 3D 模型允许改善模型本身，但容器、按钮、尺寸布局不变。首轮不改变它们在页面上的占位面积。

## 5. 非 UI 视觉规范 v0.1

本节为**试制规格**，不是已实测最佳值。先在 UV-01 的样板里校准并记录最终数值；全量阶段遵循已冻结样板，不能逐个资产另创风格。

### 5.1 颜色、形状与材质

| 项目 | 执行规则 |
|---|---|
| 核心语言 | 木、岩石、布、旧金属、切面水晶；大形清楚，边缘适度倒角，避免全场写实噪声与全场纯平面色 |
| 主色来源 | 只读 [GloryTokens](/Volumes/repository/github/GLory/GLory-v1.0/ui/theme/GloryTokens.gd:16)：GOLD≈`#ECC159`、CYAN≈`#6BC7D9`、TEXT_PRIMARY≈`#F5F0E1`、INK_PANEL RGB≈`#1C1309`、SURFACE≈`#12151C`。HEX 为源码浮点量化，不是从所有 PNG 精确提取 |
| 用色方式 | 金色用于金属镶边、圣光与少量强调；青色用于晶体/魔法局部。不得把所有怪物和技能染金。世界色表独立存放，只引用固定 UI 色作为来源 |
| 人/神/暗/亡灵 | 人：钢蓝、皮革棕、暖金；神：象牙、旧金、少量青；暗：灰紫、深紫、局部紫红；亡灵：骨白、灰褐、受控黄绿。以现有族标身份为准，每族有暗/主体/高光三色 |
| 森林/雪地/熔岩 | 保留黄绿/冷灰蓝/灰岩暖橙环境身份；压低中央战斗区细节和装饰对比；不能统一成同一张绿色地图 |
| 明暗 | 角色以现有两段 toon 为起点，保留稳定柔化的分界；材质响应一致，环境可更柔但不抢角色。先保持 `band_softness=.02`、normal 默认关、specular 默认0作为对照，再按样板调整 |
| 细节 | 普通角色按约70 px的现有战斗距离审查；保留脸、武器、头冠、翅膀等识别大形；约3–5个主要色块为整理起点，去掉缩小后只剩闪烁的碎纹理 |
| 材质分类 | opaque 身体、cutout 发片/叶片、blend 玻璃/魔法单独记录；颜色纹理、法线、发光遮罩、UV与顶点色的用途不可混淆 |

### 5.2 显示与动效合同

所有像素目标均指**最终输出画面换算到720 px高**的测量值，不能直接拿作 shader 模型空间数值；同时保留实际世界视口尺寸与最终放大倍率。H为固定相机、批准基准idle姿态的身体剪影高度，排除武器、状态图标、阴影与VFX；飞行/特殊模型显式登记测量部位。H存进profile，一次测定，不随攻击/粒子变化逐帧重算。

| 对象 | 样板起点 | 测量与约束 |
|---|---|---|
| 角色外轮廓 | 普通1–2 px；大型/Boss/水晶2–3 px | 在手机实际大小查看脸/手/武器；飞行细翅单独例外；避免纯黑粗线吞没细节 |
| 角色体型 | 同体型档与批准剪影高度偏差≤10% | 普通、重甲、飞行、巨型、Boss分档；不把所有模型机械归一身高；不改逻辑占格 |
| 接地 | 共用渐变软阴影，色取深冷灰或深棕；首试alpha .25–.40 | 阴影宽跟身体投影宽关联；飞行高度影响阴影，脚/阴影/技能挂点不随待机乱跳；原有阵营提示保留 |
| 普通命中 | 一个主要形状+最多一个辅助层；主形约0.35–0.65倍可见身高H | 只缩装饰，不变范围判定；大招/巨型目标登记独立尺度 |
| 弹道 | 主体清楚、尾迹薄；线宽约.025–.06H | 与真实起点/目标相连；范围圈由玩法半径投影，不用美术倍率改变警戒边界 |
| 时序 | 命中强调约80–140ms、普通尾部150–300ms | 保留既有命中事件/Director节拍；状态主体随状态结束，允许短淡出；不改伤害和动画攻击锁 |
| 发光 | 主体保色混合；加法只用于局部亮核/火星 | 普通命中先试近白面积≤5%，Boss峰值≤12%；超过阈值持续≤100ms。定义见验收章节，不把数值当唯一审美判定 |
| 常驻环境效果 | 细、低对比、较慢；核心战斗区少装饰火花 | 重要预警始终清楚；不能靠把所有效果变淡隐藏风格冲突 |
| 画质档 | 低档减辅助层/粒子/灯光，高档保留细节 | 同一主形、色相、事件语义；不出现低档另一套风格或关键提示消失 |

## 8. 完成的判据与检查方法

### 8.1 每个资产的记录格式

实施者为模型、背景、特效分别建立机读清单；以下是**建议schema示意**，不是当前已有文件：

```json
{
  "schema_version": 1,
  "asset_id": "dark_suc",
  "kind": "character",
  "source_path": "res://assets/models/units/dark_suc_animated/dark_suc_animated.tscn",
  "source_sha256": "实施时填实值",
  "disposition": "restyle_material_texture",
  "profile_id": "world_v1/dark/cloth",
  "runtime_consumers": ["prep", "battle"],
  "surface_contracts": [],
  "baseline_capture": "实施时填路径",
  "candidate_capture": "实施时填路径",
  "checks": {"source": "TODO", "style": "TODO", "motion": "TODO", "device": "TODO"},
  "exception": null
}
```

3D模型的surface_contracts在真实条目中不得为空；每表面填写透明类型/纹理/实际material/profile。背景和2D特效标surface=N_A，改填texture/material/blend/pivot/有效尺寸合同，不编造mesh表面。状态只用TODO/BLOCKED/PASS/FAIL/有理由的N_A，不能留空。缺少before/after、执行设备或检查对象数量时不得标PASS。

### 8.2 自动门禁与人工/视觉判断各自负责什么

| 检查 | 必须达到 | 判断方式 |
|---|---|---|
| 资源闭包 | 所有正式引用可加载，缺源/缺动作/白模/fallback为0 | manifest +真实ResourceLoader+最终导出包核查 |
| 风格覆盖 | 75战斗路径、3宠物、2水晶、全部正式特效/场景都有有效profile | 检查实际生效表面/实例uniform，不能只数配置文件 |
| UI冻结 | 字体/PNG/导入设置/布局/文本/交互/反馈不变 | SHA256+字段差异；同设备固定时刻独立UI层图。半透明UI叠在新背景上自然合成变化不判UI源改变 |
| 光照与色族 | 不同页面仍认得出同种材料；人物不被地面色带偏 | 同角色样板并排、标准色块、批准palette对照；不规定不同地图所有像素相等 |
| 主次 | 一眼先看见角色/危险信号，再看地面装饰 | 原始显示尺寸与灰度图；雪地浅色、熔岩暗色、森林黄绿逐类检查 |
| 轮廓/比例/落地 | 达到批准目标与例外表，无漂浮/黑团/脸被线吞没 | 输出720高等效像素量测+真实手机原图+动作录像 |
| 特效亮度 | 主形保色，常驻效果不盖角色和预警 | 固定相机同帧开/关特效差分定位ROI；扣UI层；ROI取实际效果包围盒，不用整屏稀释亮点占比 |
| 近白指标定义 | UV-14的提案阈值校准后冻结 | sRGB先转线性亮度，Y≥.94为近白；只在效果变化像素里计比例，记录ROI/阈值/时间。120ms亮核需≥60fps采样，12fps资产抓帧不足 |
| 动态表现 | 无材质跳变/UV闪烁/描边爬线；anchor和状态正确 | idle/run/attack/hit/death，重叠透明、召唤、取消、跳过、切场录像 |
| 玩法不变 | 同seed阵容simulation_replay_sha256、final_state一致 | 使用既有ReplayDigest；美术字段改变可能使payload hash变化，须解释，不能混同模拟变化 |
| 手机性能 | UV-19既定设备目标通过，无回退/泄漏 | 实机重复采样，记录温度/时长；桌面或灰底矩阵不能代替 |

**视觉评分表**：每张代表同框图按“材质家族一致、光向/色温、轮廓重量、细节密度、体型/接地、特效主次”六项各0–2分。0=明显跨风格，1=仍有可指出的差异，2=与样板相容。进入全量前每项均须2分，并附一句依据；评分是复查工具，不能替代白模、动作、性能等硬检查。Codex可以读图评分，但要保留具体差异，不能只生成一个总分。

**差分测量合同**：固定相机、动作帧、随机种子、shader时间与曝光；先重复采集两张同配置无效果图，估计逐像素线性RGB最大通道差的99.9百分位噪声。特效变化蒙版阈值初试`max(.02, 3×噪声值)`，固定在校准metadata中；不能为了减少近白比例不断改阈值。如果引擎TIME或动态背景不能冻结，改用特效实例隔离蒙版，在同一真实背景上验证混合结果。蒙版交集排除冻结UI节点；ROI和变化像素数量同时报告，空蒙版判FAIL/N_A而非0%通过。

### 8.3 复用的工程检查

实施前确认实际Godot二进制与匹配模板。本项目声明4.7/Mobile；本轮本机未运行引擎，以下仅为后续命令。`<GODOT_BIN>`必须换成真实绝对路径，`<ISOLATED_PROJECT>`必须是已恢复的隔离工程绝对路径；不要直接对残缺原工程生成新manifest。
