# 语音与聊天界面修复

依据桌面《问题优化及修复.docx》的五项 UI 反馈完成此次修改。

## 修复内容

1. 房间三个语音控件统一使用 78×60 参考尺寸，跟随原房间画布缩放。定位时先设置字体，再设置尺寸，避免上一次较大的字体最小高度把新尺寸撑大。加减 AI、语音状态刷新前后尺寸保持一致。
2. 房间取消独立聊天记录弹窗，历史直接在原聊天区域中自动换行、滚动，保留快捷短语和打字入口。缩放时不重建记录，避免丢失阅读位置。
3. 备战三个语音按钮统一为 64×56、水平间距 8，底板宽度调整为 308，容纳语音、范围、成员和聊天入口。
4. 备战历史区域改为透明，无黑色背景与边框；浅色文字增加深色描边，保留回合分隔。房间羊皮纸背景上仍使用深色文字。
5. 战斗三个语音按钮统一为 120×56，竖直间距 8。真实字体测量发现双行文字最低需要约 50 像素，56 像素为文字留出空间。

新增 FloatingChatScroll 复用 Godot 原生滚轮和触摸滚动，浮动滑块不占布局宽度，内容侧预留空间，避免显隐导致重新换行。历史超出一屏且当前不在底部时显示滑块，回到底部隐藏。新消息到达时，仅在原本已经到底部时跟随最新消息。

## 验证结果

- `res://tools/comms_layout_check.tscn`：113 项通过。覆盖房间尺寸变化与 AI 状态刷新、三档语音文字、各组按钮等大、备战底板容纳、战斗等间距、透明样式、原生滚轮、浮动滑块控制、底部显隐及新消息阅读位置。
- `res://tools/chat_check.tscn`：293 项通过。更新了旧“飘字只显示几行”的断言，验证新历史区完整保留长消息、自动换行和文字可读性；原聊天协议与记录生命周期检查保留。
- 实际渲染：房间历史/最新消息、完整 PrepScreen 透明聊天区、战斗语音控件隔离图均已检查。渲染专项当时为 57 项通过，其后新增真实滚轮及三档文字检查，headless 专项为 113 项通过。
- `res://tools/voice_check.tscn`：412 项检查，8 项失败。失败涉及 Android AAR、桌面 DLL 与源码签名不符，旧语音 token RPC 签名/换座约定，以及仍存在的桌面转发文件。本次未改动这些后端或插件文件，也未重建插件，不能宣称整体语音门禁通过。
- Godot 测试退出日志存在资源未释放提示；完整场景渲染日志另有兼容渲染器粒子警告。未将这些提示算作通过的验证项。

运行示例：

```text
Godot --headless --path <项目目录> res://tools/comms_layout_check.tscn
Godot --headless --path <项目目录> res://tools/chat_check.tscn
Godot --path <项目目录> --rendering-method gl_compatibility res://tools/comms_layout_check.tscn -- --full-prep
```

截图模式将结果保存到 `work/issues_20260930/`（本次目录已创建）。场景工具只注入本地测试状态，不向真实房间发送消息。

## 人工验收

在自定义房间反复加入/移除 AI，切换语音三档，观察三个按钮保持相同大小。积累多条聊天消息后使用滚轮或触屏上翻，确认原框内可看历史、浮动条出现；新消息不会拉回底部。滑到底部后确认浮动条隐藏，后续消息自动跟随。

进入备战检查透明文字在战场上的可读性、语音键不超出底板；进入战斗检查按钮等高、间距一致。手机触摸操作及真实多人通话未进行实机验收。现有 EXE/APK 不会因修改源码自动更新，需要重新导出客户端；本次未发布或上传 GitHub。

## 备份

桌面交付的 `files/` 保留本次十个变更文件的项目相对路径；`before/` 保留六个原有文件的修改前内容；新增文件不在 before 中。`manifest.json` 提供类型和 SHA-256，`changes.patch` 仅包含本次差异，`verification/` 保存日志和截图。恢复时按相同路径复制 before 中的文件即可恢复本次原有代码；新文件可保留且不再被恢复后的生产代码引用。
