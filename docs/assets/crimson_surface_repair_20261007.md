## 已定位并修复的问题

原始 GLB 的 UV/硬法线切口在 Blender 中仍是独立顶点；此前直接 collapse 减面让本应相接的三角面独立收缩。例如赤舞者身体导入后 30,758 个 Blender 顶点中，只有 7,135 个位置和蒙皮一致的实际顶点。法线数值平滑无法重新接上已经分离的几何。

1. 减面前焊接位置完全相同、蒙皮权重一致（容差 1e-6）的顶点，保留每个面的 UV，不跨不同蒙皮连接。
2. 重算面朝向、清除导入的逐面自定义法线并使用连续平滑法线。
3. 保护原始轮廓极值顶点，避免减面缩短霜印使发梢等部位。
4. 赤舞者对保留下来的表面重排 UV、将原底色烘焙到 1024px atlas，以减少 UV 切口造成的顶点开销。旧切线空间法线贴图不适用于新 UV，因此仅这三个材质停用旧法线贴图。没有采用会抹去五官的颜色平滑实验。
5. 动画通道、关键帧、节点结构与骨架不重新导出；原始 inverse bind 补偿审计全部通过。

## 重建参数

使用已合并最新资源的隔离项目，保留 `assets/models/units/crimson_race/*.glb` 原件。

| unit | crimson_decimate.py 参数 |
|---|---|
| crimson | --target 0:19000 |
| dancer | --target 0:9500 --target 1:4000 --target 2:5000 --repack-uv |
| drumer | 无需减面 |
| hunter | 无需减面 |
| armbreaker | --target 0:12000 --target 1:6500 |
| Icey | --target 0:19000 |
| skypierce | 无需减面 |
| lattern | 无需减面 |

`--target` 是重排 UV 前的搜索目标；非流形几何可能使 Blender 提前停止减面，必须检查最终 glTF 顶点总数，不能只相信传入参数。具体命令为 Blender 执行 `crimson_decimate.py -- --glb <source> --out <dump.npz> <参数>`，再执行 `crimson_refine.py --project <隔离项目> --unit <unit> --dump <dump.npz>`，随后用 `dark_race_materials.py --race crimson` 生成材质。重排 UV 的 albedo 烘焙必须与 npz 放在一起，转换器会自动读取；不允许给新 UV 配旧法线图。
