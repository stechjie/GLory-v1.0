# Glory 跨设备 UI 安全区与战斗适配改造清单

日期：2026-09-26。范围：iPhone（优先复现 iPhone 17）、iPad、Android 手机/平板，以及系统允许的窗口尺寸变化。供同事使用 Codex 分批实施。

**交付状态：方案与源码核查，不是已修复报告。未修改游戏代码、未构建或安装包、未在本轮复现用户手机。** 本轮源码基线 `74ed959`。实施时重新确认分支、引擎二进制和导出模板版本；`project.godot` 的 `config/features` 写 4.7，不等于实际安装包一定由该版本构建。

## 1. 结论与推荐方案

推荐沿用现有 Godot UI、美术及游戏规则，实施：

**全屏装饰背景 + 统一平台安全区服务 + 安全区内响应式 HUD/弹窗 + 独立战场取景矩形 + 统一投影/点击坐标转换 + 注入式自动测试及真机门禁。**

不以 iPhone 17 型号写死右侧留白，不仅调整根分辨率，不把整张界面强行等比缩小到所有按钮难以点击，也不把逻辑战场/棋子位置改成随设备变化。

当前能确认存在多个没有接入系统安全区的页面；这与用户的右侧遮挡现象吻合，但**不能仅凭代码认定现场一定是灵动岛**。还可能是游戏内透明控件拦截、容器裁剪、UI 溢出、系统手势或触摸坐标偏移。第一张工单负责分类验证。

“能适配”的验收不是某台模拟器看起来正常，而是：支持范围内所有关键控件可见且可点，布局变化后棋子/血条/点击一致，战斗无关键内容裁切，且真机证据通过。尚未验证的设备只能写“待验证”，不能承诺所有机型已通过。

## 4. 先复现 iPhone 17 的“被挡”究竟是哪一种

实施者取得：具体型号/系统版本、游戏 build、来源（TestFlight/本地安装）、横屏方向、显示缩放设置、截图+手机外拍、发生页面/控件和手指操作视频。软件截图可能不会呈现真实硬件遮挡形状，外拍用于补证据。

调试包新增可开关的 GeometryOverlay（正式默认关闭）：

- 画出窗口可绘区域、原始平台安全区、换算后 SafeContentRect、UI 四边 margin、战场显示矩形、实际按钮命中区域、当前 pointer 命中节点。
- 显示 engine version/hash、build、render backend、窗口像素尺寸、根逻辑尺寸、窗口原点、屏幕/窗口变换、平台缩放/density、方向、keyboard rect、native inset 来源、layout revision。
- 输出布局记录到诊断日志，不写 token/账号凭证。屏幕截图与日志需匹配同一时刻和 revision。

|现象|确认方法|对应修复|
|---|---|---|
|被灵动岛/圆角/系统条挡住|外拍与安全区边界吻合，反向横屏问题随遮挡侧移动|平台 insets 与 SafeContentRoot|
|图形被游戏面板盖住|UI 树/clip_contents/CanvasLayer/最终绘制层级可证|改容器分区/弹窗布局，不靠加屏幕右边距|
|能看到但点不到|在按钮中心注入真实输入路径，检查命中节点与遮罩|修 mouse_filter/树序/模态输入，不只改 z_index|
|点中别处或拖拽偏移|画出原始触点与转换后点及格子多边形|修统一坐标转换，不在每页乘一个猜测比例|
|只在特定比例越界|安全区无异常，但 minimum_size 或固定 offset 超出|重排/滚动/折叠布局|

现有 `BattleArena._build` 已修过装饰底板吞点击，`tools/voice_battle_hit_probe.gd` 也有对应测试；必须保留，不能因为移动 HUD 又引入同类回归。`z_index=100` 不等于输入优先级正确。

## 5. 唯一安全区服务：接口、坐标与更新时机

### 5.1 拟新增模块

- `ui/layout/ScreenGeometryService.gd`：autoload，唯一读取平台窗口/安全区/键盘/缩放的入口，发布 `geometry_changed(snapshot)`。
- `ui/layout/PlatformInsetsProvider.gd`：Godot API 适配层；必要时通过本项目引擎版本匹配的 iOS/Android 原生桥补充窗口 insets/遮挡能力。
- `ui/layout/SafeContentRoot.gd`：把当前页面交互根布局到安全矩形，不负责缩放战斗逻辑。
- `ui/layout/ViewportCoordinateMapper.gd`：屏幕、根逻辑、Control 局部、SubViewport 像素和 3D 投影的统一接口。
- `ui/layout/LayoutProfile.gd`：按可用空间与触控尺寸选择布局档，不按机型字符串分支。
- `tools/safe_area_layout_check.gd/.tscn`：注入 fake geometry，不依赖开发机有刘海。

名称为设计建议，均尚未实现。不要再让每个页面单独复制 `_safe_rect()`。

### 5.2 统一 snapshot 合同

至少包含：`revision`、`window_content_rect_px`、`root_rect_logical`、`safe_rect_root`、`occlusion_rects_root[]`、`keyboard_rects_root[]`、`scale_to_native_units`、`orientation`、`source`、`valid`、`layout_profile`。

- 平台 safe 区、系统栏/挖孔、系统手势、键盘、浮动窗口控件是不同概念；保存来源，不把所有值相加两次。
- provider 输出规范：**当前游戏渲染内容区内、以当前窗口内容原点为零、当前方向、实际内容像素**。平台 API 返回点/屏幕坐标时由 provider 一次性转换，不让页面猜。
- `DisplayServer.get_display_safe_area()` 可作为移动平台基础来源；其他平台回退可能是显示器工作区，而不是本窗口。桌面窗口需裁交并转换；iPad 窗口、Android 多窗口必须确认返回覆盖范围。
- iOS 原生兜底取承载游戏的 view/window 的 safeAreaInsets/窗口遮挡信息，不用 UIScreen 全屏 bounds 代替当前窗口；点到 drawable 像素的比例以实际渲染视图测量为准，不硬写 @3x。
- Android 原生兜底从窗口内容视图的 WindowInsets 获取 system bars、display cutout 等；按需要分别考虑 systemGestures/mandatorySystemGestures 与 IME。读取与事件监听都挂实际渲染窗口，不用固定屏幕宽高减某个机型的刘海值。
- Godot cutout 列表为空不代表 iPhone 没有灵动岛：当前官方文档对 cutout 列表的平台支持与 safe_area 不同。测试不能以空列表自动宣布无障碍物。
- 原生桥是“API 覆盖不足时的补充”，不是开工第一步就无条件重编引擎。需锁定源码 commit/导出模板，先证明已有 API 缺失，再引入桥并回归。

### 5.3 坐标转换合同（不能直接抄简单宽高比）

定义 W 为规范化窗口内容像素，R 为根布局逻辑坐标，L 为某 Control 局部坐标。

1. provider 把原始安全区正规化为 W 中的 `S_w`，并与窗口内容矩形裁交。
2. 获取真实 `T_R→W`，包含 stretch、content scale、嵌入/窗口原点等。引擎的 `get_screen_transform()` 等接口可用于构造，但它们的全局屏幕/嵌入窗口语义必须先核实并归一到 W。
3. `S_r = inverse(T_R→W) × S_w` 的四角，再与根可视矩形裁交；对无旋转的 UI 得矩形。不要把一个全局屏幕矩形直接套到窗口局部变换，也不要在已转换后再乘 DPI。
4. 要放进独立 CanvasLayer/子容器：再使用 `T_L→R` 的逆映射，不能只减 parent.position 假定父级无缩放。
5. 四侧逻辑 inset 由 `S_r` 与根边界推导；再加产品边距。SafeContentRoot 本身不要重复在子页面施加同一组 inset。

若只有普通 fullscreen、同原点、无额外变换，按 width/height 比例换算可退化为正确结果；这只是经验证的特例，不是跨设备算法。

必须编写纯数学测试：不同原点、2x/3x 比例、非对称左右 inset、CanvasLayer、expand、额外 UI scale、窗口移动；正反变换误差不超过 1 个最终显示像素（不含实际美术锚点差异）。

### 5.4 生命周期与无效数据

- 启动、方向改变、Window/Viewport size_changed、窗口位置/缩放变化、应用恢复、键盘变化、native safe area 回调触发更新。
- 180° 横屏翻转可能宽高完全相同，所以只监听 size_changed 不够。缺原生回调时以低频（例如 4Hz）比较几何签名补漏，只在变化时发布，不能每帧重建 UI。
- 更新先采集→下一布局周期读取最终尺寸→发布同一 revision；处理 Container 延迟排序，避免 0 尺寸/中间值让画面闪到边缘。
- 启动 safe area 为零/非法时：短暂等待有效几何，沿用同窗口状态的最后有效值；没有历史值则使用明确标记的保守临时布局。日志与测试报告必须暴露 fallback，不能永久把全屏当安全区并报通过。
- 键盘是动态遮挡区域而非永远从底部减一个高度；iPad 浮动键盘可能在中间。provider 只拿到高度时记录能力限制，对输入焦点用可验证的避让策略，不宣称覆盖任意浮动位置。

## 6. 页面层级与布局：保留风格，改空间约束

```text
PageRoot（完整窗口，不整体缩成安全区）
├─ FullBleedBackground（仅装饰，可裁边，IGNORE）
├─ SafeContentRoot（有效安全区 + 产品边距）
│  ├─ TopStatus / EssentialActions
│  ├─ GameplaySlot（棋盘/战斗显示区）
│  └─ BottomActions / SideRail（按可用空间重排）
└─ DebugGeometryOverlay（仅调试，IGNORE）

ModalStack 独立 CanvasLayer
├─ 全窗口遮罩（按已有模态机制阻止下层输入）
└─ SafeModalContent（同一 geometry source；独立局部坐标）
```

### 6.1 布局策略

- 根先保留 1600×720、canvas_items、expand，不同时改基础分辨率和全项目字号；先消除安全区缺口，再按物理可点性调整 theme/layout。
- 装饰图可 cover；含按钮/文字/棋盘格/目标指示的内容只能 contain、重排或滚动，不许为了铺满裁掉操作。
- 布局档按 **可用窗口原生 pt/dp 与内容最小尺寸** 决定，不能仅用 expand 后常常不变的逻辑宽度，也不能 `if iPhone17`。
- `wide`：两侧信息/动作栏和中间棋盘并列；`compact`：次要面板折叠，动作排成横栏或分页；`tall/narrow`：上方状态、中间完整棋盘、下方可滚动功能面板，系统强制变窄也不让关键按钮消失。
- 档位条件用 `available_width >= left_min + gameplay_min + right_min + gaps` 等实际约束，结合可触达性；临界值加滞回，避免持续拖动窗口时来回闪。
- 不同时双重指定 Container 子项位置和让 Container 管布局；手工版式用专用 Control，布局由一个 owner 负责。
- 文案长短与双语必须纳入最小宽度；按钮可换行或改紧凑文案+详情，不能静默截断关键“取消/确认/退出”含义。

### 6.2 触控目标与字号

Apple 一般按钮命中区至少 44×44pt；Android 建议至少 48×48dp。图标可以小于命中区，但邻近命中区不能重叠。[Apple 设计建议](https://developer.apple.com/design/tips/)、[Android 无障碍触控建议](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)

本项目 `TOUCH_MIN=48` 需改为经度量换算的布局下限：

`min_logical_hit = min_native_hit / (native_units_per_root_unit × local_to_root_scale)`

其中 native units 是 iOS pt 或 Android dp；二者不是硬件像素。Android density 与 iOS point/view 比例由平台度量，不用 `screen_dpi` 猜所有平台。上述为无旋转标量示意，实际以最终控件四角和缩放矩阵验算。

- 现有战斗 36 高按钮不能直接认定合格；最终命中区不足就重排并加大，不全屏缩小。
- 当一个棋子格在最小窗口内无法同时保持可辨认与可点击时，需要放大棋盘/选择辅助或收起旁栏，而非偷偷放大透明命中区覆盖相邻格。
- 字号与面板内容在最终设备上检查；保留当前中文字体回退，不能以修适配为由删除字体或降级缺字。

## 7. 战斗适配：显示变化不得改变战斗规则

### 7.1 本项目最稳妥的第一版

由于 Glory 同时有预绘制 2.5D 战场与 3D 模型，第一版采用 **固定参考取景比例、在 GameplaySlot 内完整容纳**。外层全屏背景填补空余，不强求棋盘/战场本身占满每一块像素。

1. 参考画幅先以现有背景 `1672×941` 为候选，在一个认可的参考截图上校准并冻结 `BattleFrameSpec`（参考比例、相机姿态、玩法有效框、背景锚点）。它不同于根 UI 的 1600×720，不能直接当同一坐标。
2. SafeContentRoot 内先测量 HUD 占用的顶栏/右栏/底栏；划出完整矩形 `GameplaySlot`。`BattleViewportHost` 以 contain 置入该矩形，棋盘不被动作栏盖住。紧凑档把次要操作折叠，保留足够战斗空间。
3. 场内背景、3D viewport、场内血条/分道线/单位命中区共享 BattleViewportHost；场外 HP/语音/跳过在 HUD。装饰 full-bleed 背景可复制底图或沿用已有环境，不参与命中。
4. 宽屏增加侧边装饰/信息空间，4:3 平板增加上下空间；不拉伸单位，不裁掉极边棋子。阶段一不根据不同屏幕随意扩大模拟视野。

contain 的几何合同（R 坐标）：

```text
s = min(GameplaySlot.width / reference_width,
        GameplaySlot.height / reference_height)
BattleHost.size = reference_size * s
BattleHost.position = GameplaySlot.position + (GameplaySlot.size - BattleHost.size) / 2
```

这里的 s 只决定战斗显示框，**不把 HUD 和文字一起缩小**。小窗口若战斗过小，优先重排 HUD/折叠非关键面板；不能把 contain 当作触控尺寸问题的解决方案。

### 7.2 相机、背景与结算

- 保留正交相机，并显式配置 keep_aspect；参考 frame 固定比例后相机基础取景不必随每个设备乱变。只有 frame 设计需要扩展时再做 bounds-fitting。
- 自适应基础值保存为 `base_framing_size`（拟新增），替换胜利收束与下一场重置中硬编码的 7.2；参考模式可以仍校准为 7.2，但消费者不能各自写常量。
- 如实现不同画幅的第二阶段：把玩法有效边界、角色最大高度、必要血条投影到相机平面，以 KEEP_HEIGHT 的正交相机计算 `size >= max(required_height, required_width/aspect)`，再加明确视觉 margin；实际投影测试验证 API 轴含义与模型边界。不得只按 ground AABB 导致高角色头部被切。
- 背景地面标线/水晶/分道线与模型一同校准。现有背景 cover 与相机 zoom 是两套缩放，迁移后不能各自独立计算；关键背景锚点必须和棋盘投影一致。
- PVE、Boss、PVP、21 回合左右对战、观看另一队、胜利水晶、跳过演出分别验证。镜头 shake/tighten 不得作用于 HUD；若演出镜头会裁关键对象，应限制收束范围而非修改战斗状态。
- `BattlePresentationDirector`、VFX 命中点、3D/2D 飘字统一走 mapper。不要把屏幕边距注入 BattleSimulator、NetworkService 的棋盘/距离/寻敌规则。

### 7.3 显示坐标与输入必须同时改

规范链路：

```text
模拟坐标 → 既有世界坐标 → Camera3D.unproject_position
        → SubViewport 像素 → Battle/Board Host 局部 → 根 UI

触摸事件（所属 viewport 坐标） → Host 局部 → 显示纹理 UV
        → SubViewport 像素 → project_ray → 既有棋盘平面/格子
```

- Host 显示的纹理实际 content rect 可能有边框/contain 空白；先减真实 content rect 原点，再除其大小，UV 超出 [0,1] 则不命中。不能按整个屏幕宽高映射。
- 输入来自 Godot `_gui_input`/Viewport 时通常已经做过引擎窗口转换；**不得再次当物理坐标减 safe inset/除 stretch**。原生坐标只有在 provider/原生桥入口才转换一次。
- 现有 `_world_to_main_screen` 和反向 `_prep_board_projected_ground_position` 成对替换；`_world_to_arena` 的返回空间明确为 arena local，若消费方换到 HUD CanvasLayer 要显式再变换。
- `get_global_rect()` 不能在任意旋转/不同 CanvasLayer 下被当作统一物理 hit rect；测试取最终变换后的四角/多边形，clip 链也参与可见性检查。
- 更新触发要覆盖 Host **位置**和尺寸、相机投影/方向、渲染比例变化。`PrepBoardModels` 已使用 item_rect_changed 处理纯平移，保留这一能力，不退回只连 resized。
- 普通 Control 点击继续交给 Godot GUI 分发；自定义棋盘拾取才使用统一 mapper。不要同时手动转发和默认接收造成重复购买/摆放。

### 7.4 3D 分辨率与 UI 分开

当前 SubViewportContainer.stretch=true，960×540 不是可靠的最终渲染上限。以实际 `SubViewport.size` 和 Host 最终显示像素核对。

- 固定取景比与纹理渲染像素比必须一致；不同画质只改变渲染分辨率/特效预算，不改变棋盘布局和 UI 命中。
- 用版本适配的 stretch_shrink 或独立分辨率控制器管理 3D 成本，避免 iPad Retina 全分辨率把 GPU 占满；不能一边让 container 自动管 size、一边每帧手写 viewport.size 相互覆盖。
- UI 保持清晰渲染；降低 3D 分辨率后，投影换算必须读取当前实际尺寸，不用 960×540 常量。
- resize 过程中合并布局重算，昂贵模型不销毁重建；无需重开对局、重载资源或重跑模拟。性能变化必须与改造前同设备同战斗比较。

## 8. iOS / Android 导出与系统行为检查

### 8.1 iPhone / iPad

- 核对实际 IPA 中 supported orientations、iPad 对应声明、设备家族、SDK 和 Godot 模板版本。仓库文本不替代最终包检查。
- 横屏游戏支持两个横屏方向：使用实际引擎的 sensor landscape 枚举，并核对导出方向声明；不要未经验证把字符串改成某个网上数字。
- iPad 可变窗口不能只依赖“横屏锁定”防御。对收到的窄/高窗口进入紧凑/纵向空间布局，至少状态、关键操作、退出/恢复可用；进入对局前明确最小可玩窗口策略。已在线对局不可因窗口变化自动投降/断线或暂停服务器。
- 对极窄且无法满足玩法与触控要求的窗口，明确提示放大窗口/切回全屏，保留安全可达的必要操作；这类降级状态不能宣称完整可玩。全设备支持的验收边界需写出，而不是无限缩小。
- 系统 home indicator 的隐藏/手势抑制不是 safe area 替代。系统窗口控件、来电/权限弹框返回、后台恢复后重取几何。

### 8.2 Android 手机/平板/折叠窗口

- 从真实 APK/Manifest 读取 target SDK、orientation、resizeableActivity、appCategory、cutout/沉浸式配置；仓库目前简化的 `export_presets.cfg` 不是发布包参数的完整证据，构建脚本可能覆盖。
- 至少测试 Android 15/16 的 edge-to-edge，以及项目支持的旧版系统；三键导航与手势导航分别验证。
- 状态栏/导航栏临时拉出或收起不得造成控件跳出安全区/点击错位；不依赖用户手动在厂商设置里开某个全屏选项。
- 折叠/铰链是潜在内部遮挡，不总能用四边 inset 表达。只有声明支持跨铰链展开时才接窗口布局信息；选择单侧内容窗或明确双区布局，不能把棋盘中间放在不可用区域。
- 桌面窗口标题栏、浮动键盘、多窗口要通过同一 geometry contract；不将整个物理显示屏大小当 App 的内容窗口。

## 10. 自动化与真机验收矩阵

### 10.1 几何测试输入

### 10.2 必须执行的断言

1. 每个标注 critical 的可见交互控件，其有效命中多边形落在安全可用区域内；与 cutout/IME/系统遮挡不相交。滚动页面允许未显示内容在屏外，但滚到底后最后一项和关闭操作可达。
2. 实际触摸分发到按钮：中心及边缘内缩采样点各点按一次，只有目标业务回调触发一次；模态开启时底层不触发。不能只调用 `button.emit_signal("pressed")` 伪装点按测试。
3. 布局有效区域必须与关键 UI 的 clip 链和最终 CanvasLayer 相符；只验 rect encloses 不足以证明没被透明节点挡。
4. 棋盘每格中心/边缘样本执行世界→屏幕→拾取往返；改变 Host 原点/尺寸、开关侧栏、换画质、左右旋转后结果一致。数值映射误差≤1 最终显示像素，棋子美术锚点偏差另以基准截图审查。
5. PVE/Boss/PVP/final 的玩法边界、最大模型/血条、水晶演出不被 viewport 裁掉；伤害数字不过安全区可读边界。必要时改变标签摆放，不改模拟坐标。
6. 180°翻转仅 inset 变化而宽高不变时仍 relayout；键盘隐藏/恢复、原生 inset 延迟更新后不残留旧 padding。
7. 反复开关弹窗/resize 100 次，无信号重复、节点泄漏、点击连发，变化结束后不持续逐帧全量布局。
8. 固定种子/输入的同一战斗，在不同布局下模拟结果/奖励摘要相同；GUI 测试不可使用生产玩家数据或 GM 改正式结果。
9. 布局异常 fallback、接口不支持、资源缺失都进入测试报告；空图/白模/截图成功不等于完整视觉通过。

更新旧门禁而非删除：

- `tools/responsive_layout_check.gd`：从只验证 min(viewport/REF_SIZE)，改为验证安全内容框、物理可点性、控件可达与实际输入；保留无 inset 基准。
- `tools/tutorial_overlay_layout_check.gd`、`tutorial_arrow_alignment_check.gd`：注入非对称 inset 与独立 overlay 变换；测试 oracle 不复制生产换算公式。
- `tools/prep_initial_model_layout_check.gd`：加 Host 平移/缩放和侧栏变化。
- `tools/voice_battle_hit_probe.gd`、`battle_hit_victory_check.gd`：安全区改造后仍不能吞点击，胜利镜头重置正确。
- `tools/startup_transition_check.gd`：启动到菜单及方向切换期间不闪出安全区。

新增变异测试：故意去掉右 inset、重复应用 DPI、删除 Host 原点、将纯装饰 mouse_filter 改 STOP、把镜头 reset 写回 7.2，测试应分别失败；避免生产与测试复制同一错误算法仍“全绿”。

### 10.3 真机最低矩阵

- 用户实际 iPhone 17 + 实际系统/包版本：左横屏、右横屏、默认/可用显示缩放、前后台、键盘；这是原问题关闭的必需项。
- 至少另一种屏幕尺寸/遮挡形态的 iPhone，避免只对单机校准。

## 11. 实施边界与禁止的快捷修法

- 不写 `if model == iPhone17: right_margin=...`；不对所有设备盲加同一条宽黑边。
- 不用 viewport/aspect ignore 拉扁 UI，不把放大按钮等同于修安全区，不仅提高 z_index 处理点击失败。
- 不以隐藏 home indicator、强制旧 target SDK、关闭系统手势作为适配主方案。
- 不修改棋子逻辑位置、碰撞/寻敌距离、战报或排位规则来适应屏幕；不引入不同设备战斗结果差异。
- 不只修页面内 root 却漏掉 ModalStack、键盘、教程、登录/错误页及临时右侧按钮。
- 不在一个 PR 同时换 UI 风格、根分辨率、渲染器、资源版本和整个相机体系；按工单留可验证基线。
- 不声称一份 Markdown 能保证所有硬件。保证来自统一坐标合同、自动回归和声明范围内真机验证；不具备验证条件时把阻塞写清楚。
