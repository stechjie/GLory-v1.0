## 1. 逐条落点与根因

### 第 1 条 · 计数图案去掉「外部椭圆 + 中间黑色底色」

`PrepDeployCounter._draw()` 原来叠了三层：`RoundedRectDraw.draw_soft_glow()`（外发光）、
`draw_colored_polygon(..., PLATE_BG)`（深色半透明底板）、`draw_polyline(..., BORDER_WIDTH)`（玩家色描边）。
三样一起删，只留 `_draw_piece_icon()` + 双遍 `draw_string()`。

* `box` / `center` / `GLOW_MARGIN` 仍照算 —— 图案中心点没变，`PrepBoardModels` 里
  `PREP_DEPLOY_COUNTER_VIEWPORT_SIZE(162×88)` 与 `CANVAS_SIZE` 的对应关系不受影响。
* 数字那层深色投影**刻意保留**：去掉底板之后，它是数字贴在草地上时唯一的可读性保障。

### 第 2 条 · 房间「朋友列表」隐藏玩家 ID，只显示昵称

`Team3v3Lobby._online_friend_row()` → `AccountManager.display_name(player_name, code, false)`。
`display_name(name, code, with_code := true)` 在 `with_code=false` 时只返回昵称。

* 好友码**不是删掉、只是不显示** —— 邀请（`_on_invite_friend`）仍按它发消息。

### 第 3 条 · 商店「刷新」UI 对齐 + 开商店隐藏语音 UI

* 刷新键（`PrepUI._build_rest()` 里的 `refresh_shop`）：`offset_left -105 → -143`、
  `offset_right 25 → -13`。框宽 130、中心正好落在右侧竖列（W-78）；原值中心在 W-40、
  右缘还探出屏幕（就是 10.06 截图里那个「贴在最边上」的观感）。
  竖直方向本来就没问题（`offset_top -200`，列底 518）。
* `_on_shop_picker_toggled(is_open)`：原来对语音三键调三次 `_set_overlay_blocked`（只禁输入、
  仍占位置）；现在改调新抽的 `_set_comms_ui_hidden(is_open)` —— 商店开着整块隐藏，
  关店走 `set_deferred("visible", …)` 下一帧放回（理由同 `_set_overlay_blocked`：
  「点商店外面关店」的那一次点击不该当场打回这些键）。
* ★★ **第一版漏了底板（真机复测后才发现，见 §6）**：右下角那四个键（语音 / 队友 / 所有人 / 聊天）
  **外面还有一层共享底板 `_comms_dock`** —— `PanelContainer`，`COMMS_DOCK_WIDTH=308`、
  `COMMS_DOCK_HEIGHT=88`、`offset_right = -CHAT_RIGHT + 10 = -138`、`z_index=19`，比最左的语音键
  还宽一圈，垫在整簇后面。第一版只藏了语音三键 ⇒ **底板与聊天按钮原样留在右下角**，
  玩家看到的就是「开商店了右下角那一堆根本没动」。所以 `_set_comms_ui_hidden` 的成员表是
  `[_comms_dock, _chat_button, voice_button, audience_button, members_button]` 五个。
* 用 `var _comms_hidden_visible: Dictionary = {}` 记住**进来时各自的可见性**，关闭时
  `set_deferred("visible", was)` 按原样恢复 —— **不硬写 true**：底板/聊天键在某些模式下本来就不显示。

### 第 4 条 · 赤律族羁绊图标消除外圈黑色部分

`assets/ui/race_logos/crimson.png` 原来是 **RGB、无 alpha、黑底烘焙在像素里**；
`god.png` / `human.png` / `dark.png` / `undead.png` 都是 RGBA + 四角透明。

* 结果：不透明像素占比 **55.0%**，四角 alpha=0，外圈全透明，内圈深色是家族共有风格。
* 备份 `其他/work/_qa_1006/crimson_orig_backup.png`（sha `d0703af86f5dcaee`）；新 sha `a0ab6d311d683784`。
* 对照图 `其他/work/_qa_1006/race_family_compare.png`。
* **已跑 `--import` 重导入**（`.godot/imported/crimson.png-7b3011ff….ctex` 已刷新），
  仓内 `.import` 文件数量改动前后均为 33，未产生额外噪声。

### 第 7 条 · 落点还在商店里就不算一次购买

根因（读码）：商店弹窗是**非模态透明 Container**（`mouse_filter = PASS`）、背景层一律 `IGNORE`，
悬在它下面的棋盘格/待命格**仍会接到这次放置**；而弹窗正好压在棋盘下缘 ⇒
「在商店里随手一拖松手」被当成上阵买入（误购）。

* `_drop_on_board()` / `_drop_on_bench()` 开头加 `if _shop_drop_inside_store(d): return`。
* 新守卫只在 **`kind == "shop"` 且 `_shop.picker_open`** 且落点在
  **弹窗矩形**或**外挂层（钱袋 A / 刷新键）子控件矩形**内时返回 true；
  拖到棋盘/待命格空位照旧买入（正常路径）。
* 为可测性加了一个默认参数 `at: Vector2 = Vector2.INF`：省略时就是真实鼠标位置
  （生产路径原样，`_drop_on_board`/`_drop_on_bench` 都不传）。**为什么必须留这个入口**：
  headless 里 `get_global_mouse_position()` 拿不到真光标，而这条判据的核心恰恰是「落点在哪」。

### 第 8 条 · 房间界面加「静音 / 已静音」键

`Team3v3Lobby` 右上角新增 `MuteButton`（`MUTE_BTN_POS = (1500, 26)`、`edge = "right"`，
跟随安全区右缘；`MUTE_BTN_SIZE = (140, 62)`）。

* 按钮走 `PrepWidgets.make_menu_button`，**刻意不用 `Button.new()`**：`procedural_ui_ratchet_check`
  对 `Team3v3Lobby.gd` 的 `Button.new()` 基线是**恰好 3**，棘轮只许降不许涨。
* 语义与备战期那颗同源（`_is_audio_muted()`）：
  ① `Master` 总线被静音 —— 本键自己按下去的那一步；
  ② 设置页把「背景音乐」关了（`Presentation.music_allowed() == false`）。
  **只看背景音乐、不看界面音效**：后者只掐 SFX，玩家还听得见 BGM。
* `_toggle_mute()` 的目标状态从 `_is_audio_muted()` **反推**，不是直接翻转总线 ——
  在「设置页关过音乐」（键上写着已静音、总线其实没静音）那一态按下去，
  必须**真正把声音打开**（清总线静音 + `PlayerProfile.set_presentation_toggle("music", true)`），
  否则按下去只是把一个没静音的总线翻成静音、**按了像没反应**。

## 6. 第二段：真机复测反馈 —— 第 3 条第一版漏了整簇底板

用户真机复测后回报：**「修复后发现还是有问题：1、开商店而语音 UI 没消失。」**

### 6.1 根因

第一版 `_set_voice_ui_hidden()` 只对**语音三键**置 `visible = false`，但右下角那一簇
**外面还有一层共享底板 `_comms_dock`**（`PanelContainer`，`308×88`，`z_index=19`，
带 `GloryTokens.flat_box` 深色圆角皮肤，`offset_right = -CHAT_RIGHT + 10 = -138`，

### 6.4 教训

* **判据必须覆盖「用户肉眼看到的那一整块」**，不能只覆盖「我以为有问题的那几个节点」。
* **改 UI 显隐类修复，判据要走真实入口**（`toggle_picker()`），别直接调处理器 ——
  否则接线断了也全绿，与真机现象脱节。
* 遗留：`m2_bug3_refresh_offsets`（刷新键 offset）不受第二段影响，无需重跑；
  `m3` 因函数改名已重标定锚点（`var members: Array = [_comms_dock, _chat_button]` → `[]`）。
