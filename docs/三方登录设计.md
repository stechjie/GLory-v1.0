## 三、玩家看到什么

### 平台差异

| 平台 | 能用的登录方式 |
|---|---|
| Android | Google。没有 Google 服务的手机（比如新款华为）不显示这个按钮，只能当游客 |
| iOS | Apple、Google |
| Windows / Steam | 第一期没有，按钮不显示。Steam 第二期 |

### 资料页「账号与登录」区块

放在自己的资料页、「注销账号」上方。登录相关的东西都集中在这里，不放进设定页——设定页在对局里也会弹出来。

| 状态 | 显示 |
|---|---|
| 游客，没绑 | 「游客账号：删除游戏或换手机后无法找回」+「绑定 Google」「绑定 Apple」（iOS） |
| 已绑定 | 每种一行：「Google · ab\*\*\*@gmail.com」。第一期没有解绑 |
| 底部 | 「切换账号」。游客点它，先弹强警告：「游客账号退出后再也找不回，当前进度会全部留不下来」，要再确认一次 |

### 绑定

1. 点「绑定 Google」→ 系统弹出 Google 选账号 → 选完。
2. 成功：这一行变成「Google · ab\*\*\*@gmail.com」，红点消失。**编号、宠物、钻石、段位全都不变**——就是同一个号，只是多了一种登录方式。
3. 这个 Google 已经属于别的号时，弹窗：

   > 这个 Google 账号已经绑定了另一个游戏账号。
   > 【切换到那个账号】当前账号的进度不会带过去（游客账号会永久留不下来）
   > 【取消】

   选切换，等于用这个 Google 登录（见下一段）。**不合并任何东西。**

### 用 Google / Apple 登录（新装，或切换账号）

1. 点按钮 → 系统弹窗选账号。
2. 这个 Google 绑过号 → 进那个号，和原来一模一样。
3. 没绑过 → **用它开一个新号**（和游客号一样从新手开始，只是一开始就绑好了）。
4. 那个号在别的手机上登录着 → 那台被踢下线，提示「账号在另一台设备登录」（现有规则，不变）。

## 四、整体怎么走

```
手机原生组件（Google / Apple）
    │  拿到一张「身份证明」（id_token，一小时有效）
    ▼
账号服务器  ── 拿它去 Supabase 绑定 / 登录 ──►  Supabase Auth
    │  查 player_identities，换成 player_id
    ▼
游戏里的一切照旧只认 player_id
```

- **客户端从头到尾不直接连 Supabase**，和现在一样都经过账号服务器。
- 身份证明只在内存里转一手，**不存盘、不进日志**。

## 五、账号服务器接口

都放在 `routes/auth.py`（`/v1/auth` 下），Supabase 那一侧的调用都放进 `supabase_auth.py`。

| 接口 | 要登录吗 | 做什么 |
|---|---|---|
| `POST /v1/auth/provider` | 不用 | 用 Google / Apple 登录。body：`provider`、`id_token`、`nonce`（Apple 要）、`player_id`（新装时本机签的，同 `/anonymous`）。回的格式和 `/refresh` 一样 |
| `POST /v1/auth/link` | 要 | 把 Google / Apple 绑到当前账号。成功后 Supabase 会发**一套新凭证**，照样回给客户端，**客户端必须存回新的那张**（同 `/refresh` 那条规矩） |
| `GET /v1/auth/identities` | 要 | 当前账号绑了哪些：`is_anonymous`，加上每种的 `provider` 和打码邮箱 |

### Supabase 报错 → 我们回什么

| Supabase 回 | 账号服务器回 | 客户端 |
|---|---|---|
| 422 `identity_already_exists`（这个 Google 已经绑在别的号上） | 409 `identity_taken` | 冲突弹窗 |
| 400 `email_exists`（这个 Google 的**邮箱**已经属于别的号） | 409 `identity_taken` | 同一个冲突弹窗 |
| 身份证明过期 / 无效 / nonce 对不上 | 400 | 「登录失败，请重试」 |
| 其他 | 502 | 同现有报错 |

### 其他规矩

- **限流**：`/provider` 会凭空造出新号，和 `/anonymous` 一样按 IP 限；`/link` 和邮件、商城那些接口一样，按玩家每分钟限。
- **封号**：不用另外写。`/provider` 走 `players.resolve_or_create`，要登录的接口走 `players.get_by_auth_uid`，两处都会对被封的人抛 `AccountBanned` → 403。
- **管理员邮箱不能登录游戏**：`/provider` 登进来的 Supabase 用户如果在 `admin_users` 名单里，回 403，不建玩家。原因见第七节第 4 条。
- **注销账号**（`/v1/me/delete`）多做一步：删完游戏资料，再删 Supabase 那边的用户，见第七节第 6 条。

## 七、实现要点（为什么这么做）

### 1. 第 0 步验证了什么（10-22，正式服 Supabase）

| 检查 | 结果 |
|---|---|
| 游客号绑 Google | ✅ 编号不变，自动变成非匿名，邮箱也填上了 |
| 换手机只用 Google 登录 | ✅ 回到同一个号 |
| 另一个号绑同一个 Google | ✅ 被拒，返回 `identity_already_exists` |
| 只剩 Google 一种时解绑 | ✅ 被拒，返回 `single_identity_not_deletable` |

绑定的调用：`POST /auth/v1/token?grant_type=id_token`，body 带 `link_identity: true`，用玩家自己的 access token。
⚠️ 这个接口回的 `user.identities` 是空数组，要看绑了哪些，以 `GET /auth/v1/user` 为准。

还没验证：Apple（要真机）、iPhone 上的 Google。

### 2. Google / Apple 身份存在 Supabase，不写进 `player_identities`

`003` 当初的设想是「加 Google 就往这张表加一行」。实际用 Supabase 的原地绑定以后：
- Google / Apple 挂在**同一个 Supabase 用户**上，`player_identities` 里还是只有那一行 `('supabase', auth_uid)`；
- 再往表里抄一份 `('google', …)` 就是两处记同一件事，解绑、注销时漏删一处就对不上。

所以**以 Supabase 为准，表里不抄**。`player_identities` 留给 Supabase 不认识的登录方式——第二期的 Steam。这份文档定稿后，RFC 第四节要改成同样的说法。**第一期不需要新的数据库迁移。**

### 3. 一个玩家只对应一个 Supabase 用户

单设备踢人（`login_sessions`）是按 Supabase 用户编号算的。原地绑定正好保证了这一点。**以后任何设计都不能让一个玩家对应两个 Supabase 用户**，否则两台设备同时在线会踢不掉。

### 4. 两种冲突，加上「按邮箱自动认人」

- 冲突有两种报错（第五节表格前两行），都按「不合并」处理。比如同一个人在两个号上分别绑了 Google 和 Apple，而两边是同一个邮箱，就会碰到 `email_exists`。
- 直接用 Google 登录时，Supabase 发现邮箱和某个已有用户相同，会**自动把 Google 挂到那个用户上**。对玩家是好事：同一个邮箱的 Google 和 Apple 会回到同一个号。
- 但**运营后台的管理员也是同一个 Supabase 项目里的邮箱用户**。第 0 步就踩到了：拿管理员邮箱点 Google 登录，Google 被自动挂到了管理员账号（898f799a）上。后台本身不受影响（后台只认「密码 + 手机验证器」，再加我们自己发的 Cookie），但管理员账号不该变成玩家，所以 `/provider` 要挡掉名单里的人。

### 5. 「手动关联」开关只管解绑

实测：Supabase 的「Allow manual linking」关着的时候，用身份证明绑定**照样成功**，只有解绑会被拒（`manual_linking_disabled`）。第一期不做解绑，所以这个开关现在用不上；正式服已经打开，开着没有坏处，**保持现状**。以后做解绑时，测试服的 Supabase 也要打开。

### 6. 注销账号要连 Supabase 用户一起删

`profile.delete_player()` 的注释早就写了：现在不删 Supabase 用户，是因为里面没有个人数据；**接了 Google / Apple 之后必须重新做**，因为那时 Supabase 用户里有邮箱。

- 做法：`erase_player()` 删完游戏资料以后，调 Supabase 的管理接口删掉这个用户。
- 这个接口要 secret key。**新开一个 `supabase_admin.py` 专门放它**，不进 `supabase_auth.py`（那个文件写明了不用 secret key）。请求头照 `admin.py` 传图那段：新式的 `sb_secret_…` 只放 `apikey`。
- 删 Supabase 用户失败时，游戏资料已经删掉了，不回滚。把 player_id 和 auth_uid 记进日志，管理员可以手动补删。
- 不管有没有绑定，都一律删。分两种情况处理反而容易出错。
- 账号服务器的 `.env` 要有 `GLORY_SUPABASE_SECRET_KEY`。传图功能已经在用它，部署前确认正式服配了。
- 10-22 实测请求头：拿本机 `.env` 里的 `sb_secret_…` 只放 `apikey`，删一个不存在的随机编号，Supabase 回 `user_not_found`（说明认这个密钥）；只带公开 key 回 401。

### 7. Apple 的两条特别规矩（iOS 那一期做）

- **注销时要撤销 Apple 授权**，这是 Apple 的硬性要求，Supabase 不会替我们做。打算的做法是：注销时让玩家再用 Apple 确认一次，拿到一次性授权码交给账号服务器，账号服务器换成令牌后马上撤销。这样平时什么都不用存。需要在 Apple Developer 建一把 Sign in with Apple 的密钥（.p8）放在账号服务器上。
- Apple 给的用户编号**跟着 Apple 开发者账号（Team）走**。App 以后转到别的开发者账号，所有 Apple 玩家的编号都会变。所以现在发 `com.superforge.glory` 的那个开发者账号，最好就是长期用的那个。

### 8. 我们的数据库不存邮箱

邮箱只在 Supabase 里。资料页显示的打码邮箱，是账号服务器每次现查 Supabase 拿到的，不落库。

## 八、Steam（第二期，10-22 开工）

10-22 他答：有 Steamworks 账号和 App ID；在 MSI 这台测；第 0 步照做。

### 方案改了：账号服务器当 Steam 的签发方（不用原来的「代登录」）

原来打算由账号服务器拿管理员权限替 Steam 玩家「代登录」Supabase。10-22 改成：

1. 游戏向 Steam 要一张票（`GetAuthTicketForWebApi`）→ 账号服务器拿发行商 Web API 密钥去问 Steam（`ISteamUserAuth/AuthenticateUserTicket`）→ 得到 SteamID。
2. 账号服务器**自己签一张 5 分钟的身份证明**（`app/steam_oidc.py`），只在服务器内部用，不交给客户端。
3. 交给 Supabase 里登记的自定义提供方 `custom:steam`。Supabase 从 `/oidc/steam/.well-known/openid-configuration` 和 `/oidc/steam/jwks.json` 取公钥验签。

好处：Steam 和 Google 完全走同一条路 —— 登录、绑定、冲突（`identity_already_exists`）、注销删用户全部复用，`player_identities` 继续不用。
风险：Supabase 文档只写了网页跳转的用法，没写「拿身份证明直接登录」能不能用于自定义提供方（源码里是支持的）。第 0 步就验这个；不行再退回「代登录」。

### 玩家看到什么

| 场景 | 做法 |
|---|---|
| Steam 第一次启动 | 问一次「新玩家 / 我在手机上玩过」。新玩家直接用 Steam 开号，以后打开自动登录 |
| 我在手机上玩过 | **电脑出 6 位码**（5 分钟、只能用一次、限制尝试次数），手机「资料页 → 关联电脑」输入，手机先确认「关联到 Steam 用户 XXX？」，确认后电脑自动进手机那个号。手机是已登录的一方，由它确认才安全 |
| 冲突 | 电脑上已经用 Steam 玩出进度、又想关联手机号：不合并，二选一 |
| 共用电脑 | 每次启动比对当前 Steam 账号和本机存的号绑的 Steam，不一致就重新用 Steam 登录 |
| 家庭共享 | 用玩家自己的 SteamID |

| 步 | 内容 | 状态 |
|---|---|---|
| 0 | 签发方的公开地址 + 私钥（update.sh 自动生成）+ Supabase 登记 `custom:steam` + 服务器上跑 `deploy/check_steam_oidc.py` | 代码写完（未提交），等部署和登记 |
| 1 | 账号服务器：Steam 验票、`/v1/auth/provider` 和 `/v1/auth/link` 加 steam、关联码接口、Steam 昵称 | |
| 2 | 游戏：GodotSteam（只在电脑版加载，手机包和战斗服务器都不带）、第一次启动选择页、电脑和手机两边的关联码页面 | |

## 十三、绑了 Google 之后，换手机还会丢什么（10-22 逐项查过）

**跟着账号走（存在账号服务器，不会丢）**：昵称、头像、头像框、资料；钻石、金币、买过的东西；宠物、出战种族、棋盘皮肤；等级与等级奖励；段位、信誉分、对局记录；好友、私聊、邮件、七日登录。

**教学进度**：原来只存在手机上，换手机要重过一遍。10-22 改成登录时由账号服务器回 `onboarded`（等级 ≥ 2 或者已经有宠物，现有数据就能判断，不用迁移），手机收到后把本机教学标成完成（`PlayerProfile.adopt_account_onboarded`）。只改「还没开始」的：本机正在教学（比如「重新体验教学」）、已经完成或跳过的都不动。

**还会丢的（只存在手机上）**：

| 东西 | 存在哪 | 丢了的后果 | 处理 |
|---|---|---|---|
| 图鉴解锁进度 | `user://profile.json` 的 `codex_seen` | 换手机后图鉴从头解锁 | 要同步到账号服务器（新表 + 接口），另做 |
| 正在打的那一局 | `glory_reconnect.json`、`glory_beta_004.save` | 对局中途卸载重装就回不去那一局，可能按中途离开处理 | 账号认领座位是 RFC 9.7，压在后面 |
| 本机设置（语言、音量、画质、震动、特效） | `profile.json` | 要重选一次语言、重调设置 | 本来就是设备设置，不跟账号走 |
| 公告已读记录 | `glory_announcements_seen.json` | 旧公告会再弹一次 | 不处理 |
| 教学奖励还没补发的那一份 | `profile.json` 的 `tutorial_reward_pending` | 教学打完时没网、还没补发就卸载，这份奖励会丢 | 极少见，不处理 |

**整个号还是可能找不回来的情况**：
- 换到 **iPhone**：iOS 版还没有 Google 登录（一 B）。
- 换到**没有 Google 服务的安卓手机**（比如新款华为）。
- 玩家自己的 **Google 账号丢了或被封**：第一期没有第二种找回方式。
- **注销账号**：永久删除，按设计就是这样。
- **还没绑定的游客号**：和以前一样，删游戏、换手机就没了。

**看起来像丢了、其实没丢**：
- 换手机时选错了 Google 账号，或者手滑点了「开始游戏（游客）」：进的是另一个号，原来的号还绑着 Google，用「切换账号」就能回去。
- `glory-login` 项目被停（试用到期没升级）：所有人暂时用不了 Google 登录，但绑定都还在，项目恢复后照样能登。

## 十四、已知局限

- **换号逃封还是挡不住**：被封的人换一个 Google 账号照样能开新号，绑定不解决这个问题。
- **被切换掉的游客号会留在库里**：没有任何登录方式能回去，和现在删游戏丢掉的游客号一样。
- **没有 Google 服务的安卓手机**用不了 Google 登录，只能当游客（第二期之后也许可以给它们做绑定码）。
- **Google 测试状态最多 100 个测试用户**，内测人数超过之前要把同意页改成正式。
