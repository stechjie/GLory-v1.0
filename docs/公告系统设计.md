## 一、拍板记录

| 事项 | 结论 |
|---|---|
| 管理员从哪里改 | **Supabase 后台直接改表**。没选「只能经 SSH 打开的小网页」和「正式后台 + 管理员账号」 |
| 管理员是谁 | 目前只有两个人，本来就有 Supabase 权限。有不碰代码的运营 / 客服时再做正式后台，写的还是这张表 |
| 第一版客户端 | **一次做全**：公告栏 + 红点 + 登录弹窗 + 维护画面 + 停服预告横条。理由：每加一样客户端功能都要玩家更新一次 |
| 图片 | **第一版必须有**。每条一张，登录弹窗与列表共用同一张 2:1 |
| 图怎么到手机 | 账号服务器从 Supabase Storage 公开桶取回原图，手机只从我们自己的域名下载 |
| 图片格式 | **服务器把原图自动转成 WebP**（2026-09-15 改）。原来是「原样转发、超过 512 KB 就拒」，第一张实测的 PNG 就是 2.1 MB。没选「放宽上限收 PNG」：玩家下载量是 WebP 的六七倍，而且占的是和战斗服务器同一台机器的带宽 |
| 战斗服务器 | 不动，不顶协议号（查过 `08acd08` 那版包收到不认识的推送会直接忽略） |

## 二、玩家看到什么

| 形态 | 什么时候 | 数据从哪来 |
|---|---|---|
| 公告栏 | 点主菜单右侧「公告 / 活动」 | `GET /v1/announcements` |
| 红点 | 有没看过的（或 revision 加过的） | 同上 + 本机记录 |
| 登录弹窗 | 进主菜单时，勾了 `popup`、这个 revision 没弹过；一次启动最多 3 条 | 同上 |
| 停服预告横条 | `kind = urgent` 的公告变成可见的那一刻推给在线的人；之后登录的人拉到列表时也会出 | WebSocket 推送 + 列表 |
| 维护画面 | 启动时登录失败 / 连不上服务器，并且 `/status.json` 说在维护 | Caddy 直接给的静态文件 |

弹窗不打扰规则：只在主菜单上弹；有别的弹窗（被顶号提示、房间面板……）时等它关掉；**新手教学没走完不弹**。

## 三、管理员操作手册

### 发一条普通公告

1. **（第一次）建桶**：Supabase 后台 → Storage → New bucket，名字 `announcements`，**勾选 Public**。
2. **传图**（可选）：拖进这个桶。PNG / JPG / WebP 都行，单张 10 MB 以内，服务器会自动转成 WebP、太大的自动缩小。
   文件名只能用英文字母、数字、`.` `_` `-`，可以有 `/` 分目录，例如 `2026-09/summer.png`。
3. **新建一行**：Table Editor → `announcements` → Insert row：

   | 列 | 怎么填 |
   |---|---|
   | `kind` | `event` 活动 / `news` 系统 / `update` 更新 / `urgent` 紧急 |
   | `status` | 先填 `draft` |
   | `title_zh` / `body_zh` | 必填标题；正文可空 |
   | `title_en` / `body_en` | 可空，空着时英文玩家看中文 |
   | `image` | 第 2 步的文件名，没图留空 |
   | `popup` | 要登录弹窗就勾上 |
   | `sort_order` | 越大越靠前，置顶给个大数 |
   | `starts_at` / `ends_at` | **一定带时区**：`2026-09-20 20:00+08`。`ends_at` 空 = 不自动下线 |
   | `preview_codes` | 填自己的好友码，例如 `AAAA2222, BBBB3333` |

4. **预览**：等半分钟，用 `preview_codes` 里的号进游戏，公告栏里会有一条「（预览）」。图片或好友码有问题时，
   游戏里和表格的 `problem` 列都会写原因。
5. **发布**：`status` 改成 `published`。

### 改一条已经发出去的

- 改错别字：直接改，**不要动 `revision`**。
- 大改（改时间、改内容、想让大家再看一遍）：改完把 `revision` 加 1，玩家会重新看到红点，要弹窗的会再弹。
- 换图：**传一张新文件名的图**，把 `image` 改成新名字。不要覆盖旧文件 —— 服务器每个路径只取一次，发现不了覆盖。
- 撤下：`status` 改成 `withdrawn`。**不要删行**，删了就没有「发过什么」的记录了。

### 停服预告

新建一行 `kind = urgent`、`title_zh` 写「10 分钟后停服维护，请勿开新局」，直接 `published`。
在线的人半分钟内屏幕顶部出横条（只显示标题），对局中也看得到。维护完把它撤下。

### 维护公告（账号服务器要停的时候）

在服务器上：

```bash
echo '{"maintenance": true, "title_zh": "服务器维护中", "message_zh": "预计 18:00 恢复。", "title_en": "Maintenance", "message_en": "Back around 18:00 (UTC+8).", "expires_at": "2026-09-20 19:00+08:00"}' | sudo tee /opt/glory/public/status.json
```

维护完删掉：`sudo rm /opt/glory/public/status.json`。忘了删也不要紧：过了 `expires_at`（按服务器时间）就不再显示。

它只在玩家**进不去**的时候替换「连不上服务器」那句话，不会挡住已经能登录的人。
只更新战斗服务器、账号服务器照常运行时用不上它 —— 用上面的停服预告。

## 四、图片规格

| 项 | 要求 | 为什么 |
|---|---|---|
| 格式 | 传 PNG / JPG / WebP 都行。**GIF 和动图不行** | 服务器统一转成 WebP；手机上显示不了动图 |
| 比例与尺寸 | **2:1**，建议 **1600×800** 或更大 | 列表、详情、登录弹窗共用；比例不对不会拉伸，会留边。1080p 的手机上，详情页里的图大约画 1600 像素宽，比这小会有点糊 |
| 原图上限 | 单张 **10 MB**、**1600 万像素**以内（例如 5600×2800） | 服务器要把整张图解码进内存，这台机器上还跑着战斗服务器 |
| 玩家下载的 | 自动转成 WebP（质量 85），长边超过 **2048** 的等比缩小。实测游戏手绘图 1600×800 约 265 KB（同一张图 PNG 约 2 MB） | 下载量小；长边限 2048 是因为低端安卓机解码大图会闪退 |

转不了的图**不会发给玩家**，公告照常显示文字，原因写在 `problem` 列。
转出来的图不带 EXIF：手机照片里的拍摄位置不会发出去；照片的「横竖」会先按 EXIF 摆正再转。

### 正文格式

正文支持少量 BBCode：`[b]粗[/b]`、`[i]斜[/i]`、`[u]下划线[/u]`、`[color=#FFCC00]颜色[/color]`，
以及跳游戏内页面的 `[url=glory://prep]去备战[/url]`（可用：`prep` `codex` `friends` `profile`）。
其它方括号原样显示成文字。**不支持外部链接和图片标签** —— 哪天有后台权限的账号被盗，这就是给全服发钓鱼链接。

## 五、链路

```
管理员 ── Supabase 后台 ──> announcements 表 + Storage 公开桶里的原图
账号服务器每 30 秒读一次表；图片第一次出现时从公开地址取回原图 → 转成 WebP → 按内容哈希存 /var/lib/glory-media
玩家 ── GET /v1/announcements ──> 账号服务器内存里的快照（不查库）
玩家 ── GET /media/<sha256>.webp ──> Caddy 直接给文件（永久缓存）
玩家 ── GET /status.json ──> Caddy 直接给文件（账号服务器停了也在）
```

- **为什么服务器取回、不让手机直连 Supabase**：RFC 第三节第一条；玩家能不能连上 supabase.co 没验证过；
  取回时就能转换并把原因写回表格。以后要换方案只改服务器，客户端只下载接口给的地址。
- **转换在后台线程里做**：一张图几百毫秒 CPU，放在主循环里会让所有人的心跳和接口请求排队。
  只接 PNG / JPG / WebP 三种解码器 —— 不限的话 Pillow 会去试 EPS，而 EPS 会调系统里的 Ghostscript。
- **文件名 = 转出来那份的 SHA-256**：同一个地址永远是同一张图，可以永久缓存；手机下载完逐字节校验，
  拿到的一定是服务器转好的那份。
- **「该不该显示」按服务器的钟判**，不看手机时间（改手机时间就能提前看到活动公告）。
- **看过哪些、弹过哪些存玩家手机**（`user://glory_announcements_seen.json`）：换手机会再提醒一遍。
  不按当前列表裁剪 —— 账号服务器刚重启时会短暂返回空列表，裁了就全服重弹。
- **客户端开始在每个请求里带 `X-Glory-Client: protocol=28; build=N`**。今天服务端不读它，
  是给以后「只给旧版本弹请更新」留的：已经发出去的包补不上这个头。
- **手机的图片字节上限（2 MB）故意比服务器转出来的上限（1 MB）宽**：这个数字随 APK 发出去就改不了，
  以后服务器想放宽不用发新包。反过来（手机比服务器窄）手机会拒收，门禁钉着。

## 六、部署

顺序：**账号服务器先，APK 后**。反过来的话，新包拉不到接口，公告栏显示「暂时没有公告」，不报错。

1. Supabase：SQL Editor 跑 `database/008_announcements.sql`；Storage 建公开桶 `announcements`。
2. 账号服务器：`sudo bash /opt/glory/src/deploy/update.sh`。它会按 `requirements.txt` 装图片转换要用的 Pillow、
   装新的 systemd 单元（多了图片目录）、建 `/opt/glory/public`。
3. **Caddy（只要做一次，update.sh 不会替你做）**：

   ```bash
   sudo sed "s|GLORY_API_DOMAIN_PLACEHOLDER|glorytd-api.duckdns.org|" /opt/glory/repo/deploy/Caddyfile | sudo tee /etc/caddy/Caddyfile >/dev/null
   sudo systemctl reload caddy
   ```

   没做这一步：图片照样能用（后端自己给），但**账号服务器停机时维护公告读不到**。update.sh 检测到旧配置会打一条提醒。
4. 验证：传一张测试图、建一条 `draft` + 自己好友码的公告，半分钟后 `problem` 列为空、游戏里能看到图。
   `curl -I https://glorytd-api.duckdns.org/status.json` 在没有维护文件时应当是 404。
5. 出新 APK。

## 七、已知局限

- **已经发出去的包看不到公告**。旧包点「公告 / 活动」还是「敬请期待」。
- **整台机器挂了，维护公告也读不到**（Caddy 跟着没了）。要防这个得把文件放到别的机器上，第一版不做。
- **Supabase 后台权限很大**：看得到全部数据（包括玩家私聊原文），手滑能改到别的表，没有「谁改了什么」的记录。
  所以只给现在已经有权限的人用。
- **Supabase 后台显示的时间是 UTC**。填时间一律带时区；上线前先填一条测试的核对一遍。
- 同一个图片路径服务器只取一次、转一次（重启后再转一次）。覆盖 Storage 里的同名文件不会生效。
- 服务器取图或转换失败后 5 分钟内不重试；改个文件名会立刻重试。
- 横条与弹窗的「这次启动出过没有」只在内存里：重开游戏，还在有效期内的紧急公告会再出一次横条。
