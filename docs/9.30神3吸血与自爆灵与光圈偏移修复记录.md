## 一、羁绊神3·吸血对非神族单位也生效

**现象（用户报）：**「本身描述是对神族单位生效，但实测是对自身非佣兵棋子生效」。

**真源先对齐。** 羁绊文案真源是 `scenes/prep/panels/SynergyPanel.gd:154`：
「**神族单位**造成伤害时回复实际伤害 20% 生命」——文案限定的是**攻击者的种族**，
不是「队伍凑够 3 神」。

**根因。** `BattleSimulator._perform_attack` 里（原 994 行）取到队伍羁绊就直接回血：

```gdscript
var lifesteal := SynergyService.safe_factor(syn, "god_lifesteal")
if lifesteal > 0.0:
    _heal_unit(attacker, maxi(1, int(round(float(dealt) * lifesteal))))
```

`syn` 是**队伍**的羁绊（`_resolve_syn` 按 `team` 取），与攻击者种族无关 ⇒
队伍凑够 3 神之后，**任何**攻击者（含佣兵、含非神族棋子）普攻都回 20% 血。
同函数里暗族那条本来就带种族判定（`race == "dark"`），神族这条漏了 —— 属于
「同一函数两个分支不对称」。

**修法。** 判据与暗族对齐：

```gdscript
var lifesteal := SynergyService.safe_factor(syn, "god_lifesteal")
if lifesteal > 0.0 and str(d.get("race", "")) == "god":
    _heal_unit(attacker, maxi(1, int(round(float(dealt) * lifesteal))))
```

**取证（`work/_qa_930_bugs/probe_lifesteal.gd`，实跑）**

```
Q930A 前置 神来数=3 god_lifesteal=0.2（须 3 / 0.2，否则本探针无效）
Q930A GOD_神族     race=god    dealt=19 tgt_hp 1600->1581 hp 300->304 delta=+4 期望吸血=4
Q930A NON_GOD_非神族 race=undead dealt=26 tgt_hp 1581->1555 hp 300->300 delta=+0 期望吸血=5
```

★ 前置体检这行不能省：初版探针读 `state.get("player_syn")` 得 `god_lifesteal=0.0`
（**假阴性** —— 离线自测 state 的 `player_syn` 可能为空）。改成读
`BattleSimulator._resolve_syn(probe, state)`（即攻击者真正用的那一份）才读出 3 / 0.2。
这条就是「显示层/断言层必须调用被验证方真正使用的那个函数」在探针上的应用。

## 二、自爆灵被技能击杀时自爆失效

**现象（用户报）：**「自爆灵被技能击杀时，自爆技能失效」。

**根因。** 自爆灵（`undead_bomb`，`skill_id == "death_poison_explosion"`）的爆炸
**只**写在 `BattleSimulator._on_unit_killed` 里，而那是**普攻致死**的入口
（`_perform_attack` → 死亡 → `_on_unit_killed`）⇒ 被**技能/AOE**打死时整段不执行。
同一轮里「母灵」类死亡特性早已迁到 per-tick 清扫 `_process_race_death_traits`，
自爆灵**没跟着迁**。

**修法（三层）。**

1. 把爆炸本体抽成 `BattleSimTreasures.apply_death_poison_explosion(victim, vd, enemies)`，
   条件与原实现逐条一致（目标存活 + `_can_target` + 距离 ≤ 180）。
2. 新增 per-tick 清扫 `BattleSimTreasures._process_death_explosions(state)`，与
   `_process_race_death_traits` 同款 —— 覆盖**普攻 / 技能 / AOE 全部致死方式**。
   普攻那条路**保持原样**（死亡瞬间即时引爆），两边靠 `death_explosion_done` 去重。
3. ★ **清扫必须排到胜负判定之前**。`step_state` 第 411 行一旦
   `p_alive.is_empty()` 就 `state.finished = true; return`；自爆灵是**最后一个阵亡单位**
   时（真实战斗里很常见），tick 尾部那处清扫**永远轮不到**。所以现在两处调用：

```
BattleSimTreasures._process_revives(state)
BattleSimTreasures._process_temporary_deaths(state)
BattleSimTreasures._process_death_explosions(state)   # ← 9.30 新增，胜负判定前兜底
var p_alive := _alive(player)
...  胜负判定 early return ...
...  _tick_statuses / _tick_skills / _step_team / _separate_units / _process_shared_links
BattleSimTreasures._process_death_explosions(state)   # ← 9.30 新增，本 tick 刚死的补炸
_process_pending_kill_rewards(state)
BattleSimTreasures._process_race_death_traits(state)
```

**取证（`work/_qa_930_bugs/probe_bomb.gd`，实跑）**

```
Q930B SKILL 前置 skill_id=death_poison_explosion atk=145 pct=2.5 期望爆炸伤害=363
Q930B SKILL 致死=DamageService(技能/AOE) bomb_hp=0 alive=false done=false
Q930B SKILL tgt_hp 1600->1237 掉血=363 poisoned=true done=true
Q930B ATK   致死=_on_unit_killed(普攻) done=true
Q930B ATK   tgt_hp 1600->1237 掉血=363 poisoned=true done=true
Q930B DUP   再扫一次 额外掉血=0（必须 0）
```

三行 SKILL 是关键：**致死刚发生时 `done=false`（尚未爆炸）** ⇒ 这一炸确实来自清扫，
不是普攻入口顺手炸的；DUP 一行证明两个调用点没重复炸。

## 三、选「慷慨命运」后上阵光圈偏移，点赌博又恢复

**现象（用户报）：**「选择宝藏慷慨命运后出现的上阵光圈偏移的问题，点击赌博后光圈又恢复原样」。

**根因（代码路径不对称）。** 宝物入袋会改变左侧羁绊面板与商店内容，棋盘框
`board_frame` 被 HBox 整体挤动 —— 这是**平移**不是 resize，而
`item_rect_changed` 信号只在 rect 变化的当帧发出，落在
`PrepBoardModels._apply_prep_model_layout_after_frames` 的稳定轮询窗口之外的
二次平移会被漏掉，必须显式再排一次（`_queue_prep_model_layout_refresh`）。
四条相关路径里只有两条做了：

| 路径 | 函数 | 修复前 |
| --- | --- | --- |
| 联机宝藏入袋 | `_on_treasure_granted` | ✅ 有重排 |
| 慷慨命运·赌博 | `_on_generous_fate_gamble` | ✅ 有重排（tester 原话「点赌博又恢复原样」正是它） |
| 黄金祭坛 | `_on_altar_result` | ❌ 只有 `_refresh_all()` |
| 单机选宝藏 | `_pick_treasure` 非 `team_active` 分支 | ❌ 只有 `_refresh_all()` + `_queue_bonus_fx` |

**修法。** 把入袋收尾抽成共享函数，四条路径走同一条：

```gdscript
func _finish_treasure_change(bonus_before: Array) -> void:
    _refresh_all()
    _queue_bonus_fx(bonus_before)
    _queue_prep_model_layout_refresh()
```

调用点：`_pick_treasure`（51）、`_on_treasure_granted`（97）；黄金祭坛
`_on_altar_result`（269，它的按钮文案「剩余次数」同样会改变左面板高度 ⇒ 同样挤动棋盘）；
赌博路径（294）本来就有，保持不动。

★ 「两条路径各写一份 = 只修一条」是本轮第三次撞上同一形状的问题（神3/暗族、
普攻/技能致死、联机/单机），所以这次直接抽成**唯一写入点**，而不是再补一份。

**★ 打包时自校验器抓到一个真问题：7 个变异日志是 MIXED 行尾。** 根因不在 Godot，
在写入方 —— `mut_bug0930.py` 用 Python 默认文本模式 `open(..., "w")` 落盘，

sha256 与 CRLF 锚点全废。修法：落盘加 `newline=""`（原样透传捕获到的字节）；
若是自己拼的日志（`splitlines()` 已剥掉 `\r`）则显式写 `newline="\r\n"`。
`run_gates_930.py` 一并改成显式 `newline="\r\n"`（原来是靠平台默认值碰巧对）。
修完重跑变异（**仍 7/7 RED + 还原 MATCH**），全部日志复测 0 个 MIXED。

★ 这个错是「交付夹自校验」抓的，不是任何门禁抓的 —— 三方核对（missing / mismatch / extra）
全是 0，只有行尾扫描报红。所以校验器把「夹内任何 MIXED」判为 `VERIFY_FAIL`，
只比哈希的校验器会把它放过去。
