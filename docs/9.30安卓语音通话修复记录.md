# 安卓语音通话修复记录（2026-09-30 · 切范围「自动关麦」与两边互相听不见）

## 一、现象

手机进同一个语音房之后（用户 09-30 报）：

- 开麦后界面按钮是「开麦」态，但**队友听不到自己**；队友说话**自己也听不到** —— 两边都听不见。
- 来回切「队友 / 所有人」时麦克风会自己关掉。

## 二、证据（真机 logcat，不是推理）

`Glory_安卓语音通话修复_20260930/verification/device_before.log`
（09-30 17:16:47–17:16:58，装在手机上的旧包）。整份日志只有**一条**错误，重复 1333 次，全部落在同一行：

```
SCRIPT ERROR: Trying to assign an array of type "Array" to a variable of type "Array[String]".
    at: _apply_audience (res://scripts/autoload/VoiceService.gd:442)
    GDScript backtrace (most recent call first):
        [1] _process (res://scripts/autoload/VoiceService.gd:489)
```

`_process()` 每帧都调 `_apply_audience()`，所以这条报错是**持续**的，不是偶发。这是本轮唯一的实测原始证据。

## 三、根因一：`_apply_audience()` 每帧抛错 ⇒ `setAudience` 从未送达桥接

引入提交：共享仓 `db462f5`（09-29 18:13「fixed」，就是加「所有人 / 队友」权限的那一次）。

```gdscript
var identities := _team_audience_identities() if audience == Audience.TEAM else []
```

`_team_audience_identities()` 声明返回 `Array[String]`；三目另一支的字面量 `[]` 是**无类型 `Array`**。
`:=` 把 `identities` 推断成 `Array[String]`，运行时拿无类型 `Array` 去赋它就抛错，**函数当场中断**。

后果是一整条链，全部落在安卓桥接 `GloryVoicePlugin.kt`：

1. `_bridge.setAudience(...)` 在抛错点**之后**，从来没执行过；
2. 桥接的 `audienceConfigured` 因此永远是 `false` —— 它只在 `setTrackSubscriptionPermissions()` 成功后才置 `true`；
3. `applyMic()` 的前置条件是 `if (... || (enabled && !audienceConfigured)) return`
   （「权限没设好之前不许发布麦克风」），于是**麦克风一次都没有发布过**；
4. `setMicrophoneEnabled(true)` 每次都返回 `""` ⇒ Godot 侧 `_mic_on = true` ⇒ 界面按钮显示已开麦，
   而实际没有音轨上行。

**「两边都听不见」= 两台设备的麦克风都没有上行。** 这与日志完全对得上。

桌面门禁为什么没拦住：电脑上 `is_supported()` 为真但 `_bridge` 是测试替身，且这条路径在
`_apply_audience()` 里要走到第 4 行才碰三目 —— 真机上走过的路径，headless 那次没走到。
**「电脑上全绿」不等于「手机上这条路走得到」。**

## 四、根因二：切范围先关麦再开回来 ⇒ 「自动关麦」

`applyAudience()` 原来为了「让新权限生效」，先把麦克风撤下来、改完权限再开回去：

```kotlin
if (micOn) {
    r.localParticipant.setMicrophoneEnabled(false)
    synchronized(lock) { micOn = false }
}
... setTrackSubscriptionPermissions(...) ...
applyMic(gen, r, wantMic)          // 再开回来
```

于是断音有两条触发路径，**第二条不需要用户操作**：

- 用户点「队友 / 所有人」→ 断一下；
- 队友身份列表一变（资料到齐、有人入座）→ `_applied_audience` 的去重键变了 →
  `_apply_audience()` 又发一次 `setAudience` → 又断一下。

服务器侧并不需要这一撤一开：`setTrackSubscriptionPermissions()` 只是把新权限
（`UpdateSubscriptionPermission`）发给服务器，由服务器的订阅管理器重算谁能订阅；
发布者自己的音轨**不需要下架**。原设计真正要守的是「第一次发布麦克风之前权限必须已经设好」，
这一条由 `applyMic()` 的 `audienceConfigured` 前置条件独立保证，与撤麦无关。

## 七、明确没有覆盖的部分

- **没有真机联调**。本轮只修了「已定位并已用日志证明」的两条根因，不等于跨设备通话已通过。
- 「权限收紧（所有人 → 队友）之后，已经订阅上的非队友会不会立刻被服务器退订」这一条
  依赖服务器侧的订阅重算，**本轮没有设备证据**。如果真机上出现「切回队友后对面还能听见」，
  下一步是在切范围时对**非队友**补一次显式退订，而不是把「撤麦重发」加回来。
- 语音面板上的「已发布音轨 / 已订阅音轨」是本轮新加的诊断读数，尚未在真机上验过它的取值。
- 声音回声、延迟、蓝牙 / 有线耳机、切后台回来这些项本轮没有重新验收。

## 八、安装与人工验收

1. 手机上装 `其他/GloryBuild_voice_0930/Glory-0930-voicecall-fix.apk`（Debug，可覆盖安装，保留应用数据）。
   **必须两台设备装同一版**，且语音服务器（LiveKit）与战斗服端都不需要改。
2. 两台设备进同一房间 → 首次开麦授予录音权限 → 各自开麦。
3. 长按**扬声器图标**打开语音面板，看这几行（这是本轮新加的判据来源）：
   - 「已发布音轨」：自己开麦时应当 ≥ 1（=0 就是麦克风没上行）；
   - 「已订阅音轨」：对方开麦时应当 ≥ 1（=0 就是没收到对方的声音）；
   - 「连接」应当是「已连接」，「声音模式」开麦时是「通话」。
4. 来回切「队友 / 所有人」各 3 次：
   - 界面麦克风图标**不应**变回关麦；
   - 切换瞬间**不应**有明显的断音（原来这里必断）；
   - 「队友」档只有同队听得到；「所有人」档对面队伍也听得到（用第三台设备或换队验证）。
5. 出现异常时抓日志：`adb logcat -s GloryVoice godot > voice.log`，连上电脑抓，原文发回。
   重点看有没有 `SCRIPT ERROR`、`audience_failed`、`mic_failed`、`no_permission`。
6. 只覆盖工程源码不会更新已装的 APK；改完代码要重新导出并安装。
