# 安全区适配（iPhone 横屏的灵动岛 / 圆角 / 手势条）

2026-09-30。起因是 [GLORY_跨设备UI安全区与战斗适配改造清单_20260926.md](GLORY_跨设备UI安全区与战斗适配改造清单_20260926.md)
和用户在 iPhone 17 上看到的现象：**主界面左边的朋友、聊天，摆放界面左边种族 logo 那一栏被挡住**。

那份清单的范围是 13 个工单（原生插件、iPad 分屏、折叠屏、重做战斗镜头、按物理尺寸算按钮……），
这里是**缩到十月能做完、这台电脑能验证的部分**，以及没做的为什么没做。

## 一、玩家会看到什么

- iPhone 横屏：按钮和字**不再被灵动岛、圆角、底部手势条挡住**；背景照样铺满整个屏幕，不留黑边。
- 手机倒过来拿（灵动岛换到另一边）：跟着换边，不用重开游戏。
- 安卓手机、电脑：**什么都不变**。安卓现在的导出设置（`edge_to_edge` 关）本来就不画进摄像头挖孔，读出来四边都是 0。

## 二、做法：全游戏只有一个安全区来源

`ui/services/SafeArea.gd`（autoload，名字 `SafeArea`）。

| 用法 | 什么时候用 |
|---|---|
| `SafeArea.track(节点)` | 节点用锚点 + 偏移摆放、父节点铺满全屏。每条边按自己的锚点挪进安全区：铺满的内容根四边各缩进，贴右的按钮整体左移，居中的不动。**一行搞定，以后安全区变了自动跟着变** |
| `SafeArea.rect()` / `SafeArea.insets()` | 自己手算位置的页面（主菜单、大厅、图鉴），在布局函数里用；并连上 `SafeArea.changed` 重新布局 |

- 手机上读系统的安全区（`DisplayServer.get_display_safe_area()`），按「视口 / 窗口」比例换算成页面坐标；
  电脑上不读（那个接口在电脑上给的是整块显示器，不是游戏窗口），安全区 = 整个窗口。
- 每 0.25 秒量一次，变了才通知 —— 转屏 180° 时宽高不变，只听「窗口变大小」不够。
- 电脑上测试：启动参数加 `--safe-area=左,上,右,下`（逻辑单位），假装有刘海。

**原则：背景、遮罩、3D 画面铺满；按钮、文字、要点的东西进安全区。** 新写页面照这个做，
`tools/safe_area_check` 会把落进被挡区域的按钮和字列出来。

## 三、改了哪些

| 页面 | 怎么改 |
|---|---|
| 主菜单、组队大厅 | 居中画布放进安全区；贴左 / 贴右的那几列（头像、朋友、聊天 / 背包、邮件、设置、商店、公告）贴安全区的边。背景、上下装饰带、背景里的光效和宠物不动（它们对着背景图） |
| 摆放界面 | 主内容（左边羁绊 / 种族栏、上排、商店）、右上横排、右侧佣兵 / 萝卜营地一列、左下宝藏 / 联动 logo、聊天与语音、准备状态、帧率 |
| 选宝藏 | 三张卡按去掉被挡区域后的空间缩放，整列放进安全区（原来 iPhone 上会超出底部） |
| 战斗画面 | 跳过、切镜头、语音、队伍法阵血量、左侧攻击排行、狂暴提示、帧率。**战场本身不动** |
| 商城、背包、邮件、好友、聊天、公告、宠物 | 内容整块进安全区，背景铺满 |
| 图鉴 | 书本美术照样铺满；两页和返回键放进安全区（原来的 `_safe_rect` 其实是「书页保护框」，改名 `_page_keep_rect` 免得和系统安全区混淆） |
| 钻石商店弹窗 | 修了一个本来就有的毛病：卡片里的按钮继承了 280 的最小宽，五张卡被撑到约 1520 宽（设计是 1130），手机横屏两头会被挡 |
| 新手教学 | 原来自己读一套安全区，改成用同一个来源（手机上算出来一样） |

**棋盘不会错位**：摆放界面的 3D 石台是全屏固定的，格子圆圈每帧按投影重新对齐（`PrepBoardModels._tick_prep_board_layout_guard`），
挪动外面的 2D 容器不影响棋子和点击。截图核对过。

## 四、验证

- `tools/safe_area_check`（新）：假装是横屏 iPhone（左右各让 114、底 38 逻辑单位），把 16 个页面 / 弹窗真的打开，
  逐个查按钮、输入框、有字的标签、能点的图标有没有落进被挡的区域；同一页再按「没有刘海」跑一遍，确认电脑 / 安卓版面没被改坏。674 项全过。
- `tools/tutorial_overlay_layout_check`：加两档「灵动岛在左」「灵动岛在右」（左右不对称，专抓只让了一边、让了两次）。912 项全过，
  这一档第一次跑就抓到了选宝藏那一列超出底部。
- `tools/safe_area_capture`（新）：真渲染存图，被挡区域涂红。`--path . res://tools/safe_area_capture.tscn`（加 `-- --island=right` 换边），
  输出 `reports/safe_area/`。**要用隔离的用户目录跑**（页面会读存档）。
- ⚠️ **还没在真 iPhone 上验过。** 这台电脑出不了 iOS 包。

## 五、iPhone 真机验收（Mac 那边）

1. 出包、装到 iPhone 17。
2. 横屏正拿、倒过来拿各一遍，看：主菜单左边朋友 / 聊天 / 头像，右边背包 / 邮件 / 设置；
   摆放界面左边羁绊栏和左下宝藏 logo、右边佣兵 / 萝卜营地；战斗右上跳过 / 语音；商城、图鉴的返回键。
3. 每个都**真的点一下**（看得见不等于点得到）。
4. 有问题拍照（系统截图不一定拍得出灵动岛的形状）+ 说明是哪个页面、正拿还是倒拿。

## 六、没做的（对照清单）

| 清单 | 状态 | 理由 |
|---|---|---|
| ADAPT-05 战场独立取景（contain）、重做镜头 | 不做 | 要改 3D 取景与点击映射，风险最大。战场背景本来就是铺满的，被挡的只是边上的草地；等真机截图显示棋子被切了再做 |
| iPad 分屏 / 可变窗口、折叠屏 | 不做 | 十月测试是手机；iPad 全屏时同一套安全区照样生效 |
| 按物理 pt / dp 算按钮最小尺寸 | 不做 | 和「被挡」是两回事；没有真机数据先不动全局字号和按钮 |
| 键盘避让（浮动键盘） | 不做 | 现有输入框（聊天）没有被报被挡 |
| iOS / 安卓原生插件读窗口遮挡 | 不做 | Godot 自带的接口够用，没有证据说它读错之前不加 |
| 方向设置 | **待定** | `project.godot` 里 `window/handheld/orientation="landscape"`（字符串）。是否允许玩家倒过来拿（两个横屏方向都支持）要看 Mac 出的包实际声明了什么；安全区两边都能处理 |
