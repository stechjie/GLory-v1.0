## 用户定的规则

- **老虎**：每次有棋子升星（合成、用升级石升四星都算），当时手上（棋盘 + 待命区）**每一枚**一阶棋子
  生命 / 攻击 / 防御 +5%，按次数累计、不封顶。之后才买的棋子不吃以前的。合成出来的那一枚继承被合掉的几枚里
  最高的层数，再吃这一次的 +5%。头上的「★N」保留。
- **人王**：活过一场就长一层（PvE、Boss、PvP 都算），1~3 星每层 ×1.2、最多 5 层，4 星每层 ×1.3、最多 8 层；
  阵亡就移出棋盘。
- 两种成长都要**在摆放界面点开棋子时直接看到加成后的数**。

## 查到的问题

1. **老虎**（10-06 的实现）：只记一个「这局升过几次星」，开战时给所有一阶棋子统一乘 `1 + 5% × 次数`。
   后买的棋子也吃满全部次数；摆放界面上看不到任何变化。
2. **人王在线上一层都没长过**：成长是直接改棋子的 `def`，而战斗服务器收棋盘时只认它自己数据表里的 `def`
   （`NetProtocol.sanitize_cell` → `_trusted_def`，防作弊），改过的数被整份换掉。单机能长、联机不长。
3. **人王认错人**：战后按「存活棋子的格子号」认人王死活。三路的同一个格子号分不清是谁的：
   别人那路同一格的棋子活着，你的人王死了也照长。

## 怎么改的

成长记在**每枚棋子的格子上**（`scripts/units/UnitGrowth.gd`，规则只有这一份）：

| 字段 | 含义 |
|---|---|
| `king_growth_stacks` | 人王活过的场数（层数），封顶按星级 |
| `king_mult` | 人王累计倍率。每活一场乘 (1 + 当时星级的成长率)，升四星之前长的不追溯成 30% |
| `tiger_stacks` | 老虎层数 |

- **开战时乘**：`BattleSimShared._fighter_from_cell` 把 `king_mult × (1 + 老虎率 × 层数)` 乘到生命 / 攻击 / 防御上
  （攻速、暴伤不涨，同四星规格 §1）。老虎率看**这块棋盘主人**的出战宠物（联机 = 座位名片上的那只）。
- **摆放界面**：`UnitDetailFormat.format_unit_def` 显示加成后的生命 / 攻击 / 防御，并多两行
  「人王成长：N/上限 层（×倍率）」「老虎成长：+X%（N 层）」。和战斗读同一个函数，看到的就是实战乘的数
  （门禁逐项比过）。战力估算（`BattleStatsPanel.current_player_power`）也算进去了。
- **合成**：`UnitGrowth.inherit_on_merge` 取代原来两份「人王取最强」的代码，同时管老虎（取最高层数）。
- **人王死活**：战斗结果里的 `player_survivor_slots` / `enemy_survivor_slots` 换成 `king_outcomes`
  （主人座位 + 棋子 uid + 活没活）。凤凰复活体算活；被寄生复制到对面的那份不算。
- **人王技能文案**：「全属性永久 ×1.2」改成「生命、攻击、防御永久 ×1.2」（9.x 起就只涨这三项，文案一直没改）。

### 为什么层数由手机算、服务器只核上限（和 10-07 当时说的「服务器账本按编号记」不一样）

动手时查到两件事：

1. 服务器账本还在**影子期**，买棋子的意图会被拒（两边的卖棋退款算法不一样，服务器的钱可能比手机少），
   被拒的那枚棋子账本里就没有，之后跟它有关的合成也都对不上。按编号记在账本上，这些棋子的成长会**悄悄丢掉**。
2. 服务器现在本来就信手机报的 1~3 星（只有四星要核升级石记录）。

所以：层数由手机按上面的规则算、随棋盘提交；服务器只截它自己核得了的上限 ——

- **结构上限**（`NetProtocol` 收棋盘时）：人王层数 ≤ 封顶，且 ≤ 已经打完的回合数；倍率 ≤ (1+本星级成长率)^层数；
  老虎层数只给一阶非佣兵，≤ 100；NaN、字符串一律当 0 / 1。
- **账本上限**（`NetworkService._room_clamp_growth`）：每枚棋子的老虎层数 ≤ 服务器账本数到的这个座位的升星次数
  （合成 / 升四星的意图走到账本时 +1；出战宠物不是老虎就恒为 0）。
- 手机上的「★N」和详情按同一个次数截：`_apply_carrot_state` 现在影子期也跟服务器的次数走
  （以前只有账本转权威才跟），所以账本和手机对不上时，看到的仍然是实战用的数。

⚠️ 账本转权威（`economy_ledger_authoritative`）那天，层数要改成服务器按 uid 记在 roster 上。
