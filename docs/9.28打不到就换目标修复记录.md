## §1 现象与用户诉求

**用户原话**：「昨天修复的棋子排队不攻击的情况，今天又复现了此类问题。如果给这种情况的
棋子增加一个攻击不到原有敌人目标就攻击最近的可攻击目标的设定，能解决这个问题吗」。

**结论（先答后做）**：**方向对，而且 9.27 已经走了一半；缺的是触发点。**
现有实现是「**被挡住就换**」，不是「**打不到就换**」——

- `_ally_blocks` 是**几何预测**（沿直线有没有友军挡着），只在**重选那一刻**算一次；
- 锁定一旦成立，`_select_target` / `_select_attack_target` 命中就**直接返回**，
  只检查「目标还活着吗 / 还能不能选」，**不问「我还走不走得到」**。

于是只要**锁定发生在被挡住之前**（开局双方都还在走位），之后友军压上来封住走廊，
它就会一直锁着那个够不到的目标 —— 画面上就是「排队、站着不动、不攻击」。
这正是本轮补的缺口。

## §2 根因（本轮的判据依据）

```
_tick N   锁定 e_front（此刻无阻挡，直线最近 ⇒ 合理选择）
_tick N+k 友军并排压上，挡在 毒灵→e_front 的连线上
_tick N+k..M
          _select_attack_target → _locked_target 命中 → 直接 return
          （只问 alive / hp / _can_target，不问可达性）
          ⇒ 每 tick 都朝一个走不到的目标推，位移被 `_move_without_pushing` 吃掉
          ⇒ 零输出，直到队友先死
```

**证据（探针，本轮新增）**：毒灵被三只同速友军墙挡在射程外，最近只到 **62.0px**
（射程 36），全程**一次都没打过** e_front；而侧向的 e_side 明明可达。

## §3 做法

### 3.1 新增三个常量（`BattleSimShared.gd`）

```gdscript
const NO_PROGRESS_TICKS := 6      # 约 0.6s 无进展即认定"够不到"
const NO_PROGRESS_EPS := 0.5      # 单 tick 至少要近这么多才算"在推进"
const MAX_SWITCH_ATTEMPTS := 3    # 一次卡住事件最多换这么多次
```

`MAX_SWITCH_ATTEMPTS` 是**防互踢**的：没有它，两个都够不到的目标会每 6 tick
互踢一次（`locked_target_uid` 来回翻 = 目标标记闪烁）。换满就退回旧行为
（站着等队友死）—— 与 9.27 的兜底口径一致。

### 3.2 两个 `static` 纯函数（`BattleSimShared.gd`）

抽出来的理由：**让探针能直接驱动判定本身**，不必在探针里复刻一份
（复刻的那份会随生产漂移；本仓栽过：探针写的几何和生产的几何不是同一个，
于是判据全绿而功能没通）。

```gdscript
static func no_progress_step(prev_uid, cur_uid, best_dist, cur_dist, prev_ticks, eps) -> Dictionary
static func avoid_should_clear(avoid_uid, avoid_target, blocked_now) -> bool
```

★ `no_progress_step` 用**历史最好距离**当基准，而不是「上一 tick 距离」：
贴着队友侧滑时会一 tick 近、一 tick 远地抖，拿上一 tick 比会把停滞误判成推进，
缺口就永远触发不了。

### 3.3 接线（`BattleSimulator._step_team`）

三处，都在**每单位**循环里：

1. **解锁判定（必须在 `_select_attack_target` 之前）**
   ```gdscript
   if int(f.get("_no_progress_ticks", 0)) >= NO_PROGRESS_TICKS \
           and int(f.get("_switch_attempts", 0)) < MAX_SWITCH_ATTEMPTS:
       var unreachable := str(f.get("locked_target_uid", ""))
       if not unreachable.is_empty():
           f.avoid_target_uid = unreachable
           f._switch_attempts = int(f.get("_switch_attempts", 0)) + 1
       f.erase("locked_target_uid")
       f._no_progress_ticks = 0
       f.erase("_progress_uid")
   ```
   ★ 位置正是 9.24 死亡猎手判定栽过的地方（写在 `_select_attack_target` 后面
   就永远轮不到）。

2. **推进计数**：`in_range` 时复位；否则走 `no_progress_step`。
3. **避让解除**：被避让的目标已死、或去路已通（挡路的友军死了 / 让开了）→ 解除。

### 3.4 选敌侧读避让清单（`_team_select_target`）

```gdscript
var avoid := str(f.get("avoid_target_uid", ""))
if not avoid.is_empty() and pool.size() > 1:
    ... 剔掉 avoid 后若非空则替换 pool
```

★ `pool.size() > 1` 这个前提是刻意的：避让**不能把本路候选池清空**
（那会退化成 `_nearest`，绕开分路规则）。

### 3.5 状态字段只放 fighter 字典

`_no_progress_ticks` / `_switch_attempts` / `_progress_uid` / `_progress_best` /
`avoid_target_uid` 全部是 **fighter 字典字段**。

★ **没有碰回放帧**：`frames` 是 `_replay_capture_frame` 里**单次 13 列**构造，
属于 `ReplayDigest.SIMULATION_TOP_FIELDS`（含 `frames`），加列必然改冻结哈希。
门禁 `replay_frame_columns_untouched` 钉住了这一点。

### 4.2 正式门禁（`tools/battle_reach_target_check.tscn`）

**PASS 23 / 0**。行为 + 纯函数 + 结构三类齐全：

- 行为：上述 A/B/C 三个场景；
- 纯函数：`no_progress_step` 4 条（换目标归零 / 停滞+1 / 推进归零 / 微漂仍算停滞）、
  `avoid_should_clear` 4 条（死了解除 / 仍被挡保持 / 通了解除 / 空操作）；
- 结构：`_step_team` 真的调用推进判定、真的写/读避让字段、有换目标上限、
  `_team_select_target` 真的读避让、推进判定只有一份实现、
  **回放帧仍是 13 列单次构造**。

★ 结构断言**先剥注释**再做 `contains`。不剥的话会被自己的注释满足
（"写了注释就算通过"）—— 变异 M5 就是专测这一点的。

## §5 参数取值与取舍（都写进代码注释了）

| 参数 | 取值 | 依据 |
|---|---|---|
| `NO_PROGRESS_TICKS` | 6（≈0.6s） | 太短会在走位抖动时误判；太长玩家能明显看出"站那不动" |
| `NO_PROGRESS_EPS` | 0.5px/tick | 满速 16.5px/tick 远超它；"贴着队友蹭"只有 0~2px/tick |
| `MAX_SWITCH_ATTEMPTS` | 3 | 够换到位；再多就是互踢 |

**兜底口径**（沿用 9.27 及用户拍板）：全场都够不到时**退回旧行为**（站着等队友死），
不做"硬挤"。理由：硬挤会放大推挤抖动，属观感取舍。

**改动面**（只对「目标被友军挡住」的单位启用）**未变**：无阻挡的单位行为零变化，
`b_*` 三条断言钉住了这一点。

## §6 未做 / 风险（如实记）

- ★ **未做真机 / 观感验收。** 门禁只证「选敌判据对 + 不回归 + 结构在」，
  **不证**「屏幕上看起来不卡了」。
- ★ **未重新导出 EXE / APK。**
- ★ **集火效率的全局影响没有门禁能测**：新逻辑让「打不到」的单位改打别人，
  可能分散火力。只能靠真机观感。**这是本轮最大的未覆盖项。**
- ★ **确定性 / 回放一致性**：字段是 fighter 字典字段，不进 `frames`
  （门禁 `replay_frame_columns_untouched` 钉住），但**没有**专门的
  「同一 seed 两次模拟结果一致」新探针 —— 由既有的 `determinism_check` /
  `replay_identity_split_check` 覆盖（本轮已重跑，见 §7）。
- ★ **`MAX_SWITCH_ATTEMPTS` 只有结构断言、没有行为断言**：本轮的场景换一次就够，
  构造"两次都够不到"的场景才能测到上限。已如实标注，未强行造断言。
- ★ 用户截图里的**具体布阵没有被逐像素还原**：本轮复刻的是**机制**
  （锁定早于阻挡 + 友军墙 + 侧向可达目标），不是那一局的坐标。
