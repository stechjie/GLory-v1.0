## 根因

`assets/ui/main_menu_live/gold.png`(423×105) 与 `diamond.png`(418×105) **不是图标**，是**整条货币条**：

```
[ 圆金币 ] [ 深色数字底板 ......... ] [ 绿色「+」充值键 ]
   x≈26..106                            x≈333..392
```

主菜单是**整条**按 220×55 画出来、再把数字压在底板上（`scenes/menu/MainMenu.gd:186-189` 的
`_add_texture(TEX_GOLD, Vector2(645,35), Vector2(220,55))`，`stretch_mode = STRETCH_KEEP_ASPECT`），
所以那里看着是对的。

商城（`ShopScreen.gd`）只有「图标 + 数字」两格，却把整条塞进一个方格里：

- 余额位 `_purse_entry()`：`custom_minimum_size = Vector2(36, 36)`
- 卡片价格行 `_card()`：`custom_minimum_size = Vector2(28, 28)`

两处都是 `expand_mode = EXPAND_IGNORE_SIZE` + `stretch_mode = STRETCH_KEEP_ASPECT_CENTERED`。
4:1 的整条被压进 1:1 的格子 —— **图标和绿色「+」一起糊成一条亮片**。这就是玩家报的
「金币模型 / 钻石模型显示不正确」。

**像素取证**（模型看不了图，用 PIL 量）：对原图做连通域洪水填充，得金币连通域 `(30,21)-(102,80)`
（2593 px，面积对应直径 ≈57 的圆，说明外圈还带一圈深色描边）、钻石 `(36,14)-(98,84)`
（2337 px ≈ 菱形/圆宝石）；绿色「+」键的 bbox 是 `(333,24)-(392,75)`（gold）/ `(328,24)-(386,75)`（diamond）。
货币条四周 91% 不透明、8.6% 全透明（圆角与镂空），图标周围的底色是**不透明的暗棕**（约 `(23,19,9)`）。

## 改法（为什么这么改）

新增 `_icon_of(currency)` / `_crop(tex, region)` 两个小函数，用 `AtlasTexture` 从原图**裁出图标那一段**：

```gdscript
const GOLD_ICON_REGION := Rect2(26, 10, 80, 80)      # 原图 423×105，金币圆心 (66,50)
const DIAMOND_ICON_REGION := Rect2(35, 10, 72, 80)   # 原图 418×105，钻石圆心 (70,50)
```

- **不新增素材文件**。新建 `.png` 要走 `--import` 重导 + 资源清单登记，是两处容易漏的环
  （9.12 / 9.13 各因「图换了但 `.ctex` 还是旧的」中过一次）。裁在原图上传同一个 `preload`，
  一并绕开这个坑。
- `filter_clip = true`：关掉裁切边界上的线性采样，免得把旁边那块暗底板吸进来、图标带一圈脏边。
- `currency` 口径沿用文件里已有的 `_balance_of()`：`"diamond"` 是钻石，其余算金币。
- **不照搬主菜单的整条**：商城这两格是「余额 / 单价」，不是充值入口。整条带一个绿色「+」，
  在商城里就成了一个按了没反应的假按钮，反而把「充值」的暗示放到不该有的地方。
  主菜单保留整条（那里的「+」是真的充值入口），两处仍共用同一份素材。

图标格子尺寸（余额位 36×36、价格行 28×28）与 `HBoxContainer` 结构**都没动**，只换了喂进去的纹理，
所以版式零风险。裁出后金币约占格子 95%、钻石约 88% 宽，与改动前的占位相当，不会变小。
