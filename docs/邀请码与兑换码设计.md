## 一、拍板记录

| 事项 | 结论 |
|---|---|
| 邀请码是什么 | **就是好友码**（`players.friend_code`，8 位、排掉 0 O 1 I L）。不另造一个码 |
| 谁能填 | 注册 **7 天内**的新账号，**一辈子一次**，不能填自己 |
| 什么时候发奖 | 被邀请人**达到或超过 5 级**。填码时已经 5 级以上就当场发 |
| 为什么不加「排位到森卫」 | 讨论过、否决了。排位赢 +25 输 −20，保本胜率 44.4%：胜率低于它的人永远到不了森卫。会玩的刷子 4 连胜就到，真人拉来的新手朋友反而永远拿不到 —— 挡错了人 |
| 发多少 | 被邀请人 **50 钻**、邀请人 **100 钻**，发到邮箱，钻石进**赠送**列 |
| 邀请人上限 | **20 份，算「发了奖的」不算「绑定了的」**。算绑定的话别人开小号填你的码就能把名额烧光。超了被邀请人照拿，邀请人那份记 `capped` |
| 玩家看不看得到「邀请了几个人」 | **不显示**（用户定）。服务器也不下发。客服在后台玩家详情里看 |
| 兑换码 | 通用码（`GLORY2026`，全服可填、一人一次）和批量单次码（12 位随机）同一张表 |
| 兑换码次数 | **可以不限**（11-04 改，045）。通用码本来就要公开贴出去；人数上限挡不住小号，只会让晚来的真玩家看到「已领完」。收口靠**截止时间（必填，最长 365 天）**和撤回。11-03 定的是「必填、不许无限」，这条作废 |
| 已建的码能不能改截止时间 | **不能**（11-04 定）。提前结束就撤回；要延长就建新码 —— 延长不限人数的码等于多发钱，要重新走审批 |
| 小号刷不限人数的码 | 知道、先不挡（11-04 定）。被刷了再加「注册满 N 天 / 达到 N 级才能领」 |
| 批量码 | **整批同一个活动**：一个人一批只能领一个（不然评论区贴出来的码能被一个人全领） |
| 谁能建码 | 后台提交，**另一个管理员批准**（018 的规矩：发钱要第二个人批）。**撤回一个人就能做** |
| 入口 | 都在**资料页 → 资料设置**。不放设定页：设定页在对局里也会弹出来 |
| 两个入口分开 | 是。邀请码一辈子填一次，兑换码能填很多个，奖励口径完全不同 |
| 后台发物品 | 按种类分组：种族、头像框、宠物、棋盘皮肤（11-04）。种族能**整族**勾，也能展开只勾几个棋子 |
| 整族怎么算 | **算一件附件**（11-04 定）。领的时候补齐他缺的棋子、种族跟着解锁；全都有就算「已拥有」。一封 / 一个码最多 10 件，按棋子发一族就占 8 件，两族装不下 |

## 二、玩家看到什么

资料页 → 资料设置 → 「邀请与兑换码」（在注销上面）：

- 我的邀请码 + 「复制」
- 规则一句话：好友填你的码、升到 5 级时你得 100 钻、Ta 得 50 钻（数字从服务器拿，改 `.env` 不用出包）
- 「填好友的邀请码」输入框：**只有还能填的新账号才出现**。填过之后变成一句「升到 5 级后奖励发到邮箱」/「邀请奖励已发到邮箱」
- 「输入兑换码」：成功后提示去邮箱，邮箱马上刷新；失败保留输入（多半是抄错一个字）

玩家抄码时的全角（中文输入法）、空格、连字符、小写都会被服务器去掉。

## 三、🔴 风险（写给以后接手的人）

1. **一定会被刷。** 现在是匿名注册，没有手机号、没有实名。5 级门槛只是让刷「不免费」（每个小号约一小时真打），挡不住铁了心的工作室。真正的防线是三方登录（`docs/三方登录设计.md`）。
2. **钻石口径用户知情确认过**：邀请人 100 钻 × 上限 20 = 2,000 钻 = RM 200，是玩家整个消费天花板（约 RM 80）的 2.5 倍。
3. **被刷的时候怎么办**（都是改 `.env` 重启账号服务器，不用出包）：
   - 先关总闸 `GLORY_INVITE_ENABLED=false`：不能再填；已达标的**先不发、留着**，开回来之后的下一局照发
   - 或者降 `GLORY_INVITE_MAX_REWARDED` / `GLORY_INVITE_INVITER_DIAMOND`
   - 已经发出去、还没领的邮件可以在后台撤回（领走的收不回来）

## 四、运营手册

**建通用码**：后台 → 兑换码 → 方式选「一个码」→ 填码、最多几人能领、每人奖励、有效天数、原因 → 提交审批。
「最多几人能领」**留空 = 不限人数**。表单下面会写「最多一共发出 X 钻石」，不限人数时写「🔴 不限人数：每个账号 X 钻石，
有效 N 天内……没有总量上限」—— 批的人看到的就是这句。另一个管理员在「审批」页批准，批准那一刻码才建出来。

**发物品**：按种类勾。种族可以勾「整族」（一件附件，领的时候补齐缺的棋子），或者点「只选其中几个棋子」展开来勾。
商品目录里登记的都能发，**包括没上架的**：三张棋盘皮肤、松鼠 / 老虎（抽奖）、七日头像框、人族 / 神族的棋子。
发神族等于让他跳过 2–10 级的升级奖励；已经抽了几片碎片的人收到整张棋盘皮肤，那些碎片就没用了 —— 批的时候想一下。

**批量单次码**：方式选「批量单次码」→ 填生成几个（一批最多 5000）。批准后在兑换码列表那一组点「导出」，得到 CSV。
**导出的码是秘密**，别贴到公开的地方。

**撤回**：列表里「撤回」（一个码）或「整个活动撤回」（一整批）。一个人就能做，不用批。已经领走的收不回来。

**客服查「我邀请了人怎么没钻石」**：后台 → 玩家 → 「邀请与兑换码」卡片。常见答案：
- 被邀请人还没到 5 级
- 邀请人已经拿满 20 份（卡片上写「N 份因为拿满上限没发」）
- 奖励在邮箱里没领；邮件 30 天过期

**紧急时直接在 Supabase 里**（同 send_mail，不要手写 insert）：

```sql
select create_redeem_code(p_code => 'GLORY2026', p_max_uses => 5000, p_actor => 'arvin', p_diamond => 100, p_days => 14);
select create_redeem_code(p_code => 'OPEN2026', p_max_uses => null, p_actor => 'arvin', p_diamond => 100, p_days => 14);  -- 不限人数
select create_redeem_batch(p_count => 200, p_actor => 'arvin', p_diamond => 50);
select withdraw_redeem_code('GLORY2026');
select withdraw_redeem_campaign('batch_20261103_101500_ab12');
```

## 五、`.env` 开关（都可选，默认值就是上面拍板的数）

| 键 | 默认 | 范围 |
|---|---|---|
| `GLORY_INVITE_ENABLED` | `true` | 总闸 |
| `GLORY_INVITE_REWARD_LEVEL` | `5` | 2–20 |
| `GLORY_INVITE_INVITEE_DIAMOND` | `50` | 1–100000 |
| `GLORY_INVITE_INVITER_DIAMOND` | `100` | 1–100000 |
| `GLORY_INVITE_MAX_REWARDED` | `20` | 0–1000（0 = 邀请人一律不发） |
| `GLORY_INVITE_BIND_WINDOW_DAYS` | `7` | 1–365 |
| `GLORY_REDEEM_FAILURE_LIMIT` | `10` | 一小时内「码不存在」到这个次数就先不让试 |
| `GLORY_REDEEM_FAILURE_WINDOW_SECONDS` | `3600` | 60–86400 |

填超出范围的数，账号服务器**启动时**就报错退出（看 `journalctl -u glory-backend`），不会等到某个玩家升级那一刻才炸在对局结算里。

## 六、🔴 部署顺序

1. Supabase SQL Editor 依次跑 `043_invites.sql`、`044_redeem_codes.sql`、`045_redeem_unlimited.sql` ——
   **测试服和正式服两个项目都要跑**。可重复执行。测试服 11-04 已经跑过 043、044，只差 045。
2. `update.sh`（账号服务器）。
3. 出新包（资料页的入口在新包里）。

漏跑迁移就更新账号服务器：启动自检会喊 `SCHEMA 不一致`；填码、兑换 HTTP 500；
**邀请发奖会静默失败**（它在保存点里，失败只记日志、不影响对局结算）—— 所以一定先看 `journalctl | grep SCHEMA`。
漏跑 045：批准不限人数的码会报错、码建不出来（不会发错钱）。

后台网页、整族发放都在账号服务器里，**不用出包**。

战斗服务器不动，不顶协议号。

## 七、门禁要知道的

- 发奖挂在对局结算加经验之后（`progression.award_match` / `award_tutorial`），**包在保存点里**：发奖出错不能让整份战报回滚。`test_invites_pg.py::test_payout_failure_never_rolls_back_the_match` 钉着。
- 真库并发测试**必须先预热连接池**（`_warm_pool`）：池子初始只有 1 条连接，不预热的话「并发」的事务其实是一个接一个跑的，什么竞争都撞不出来，测试永远绿。2026-11-03 拿掉锁验证过。
- 客户端门禁直接读服务端源码，核对每一句新报错都有英文翻译（`scripts/account/AccountErrorText.gd`）。
