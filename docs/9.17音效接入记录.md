## 二、新增 `ui/services/SfxService.gd`（全局音效服务）

此前工程里**只有 BGM 播放器**和一个静音的确认音通道（`UiFeedback.CONFIRM_SFX_PATH := ""`），
没有任何通用音效服务。新增一个，五个设计决定各自都有理由：

### 1. 不做 autoload

照 `ui/services/UiFeedback.gd` 的先例：autoload 全部在第一个场景之前构造，条条都在
冷启动关键路径上（T3 实测 8730–8890 ms，预算 ≤ 3 s，是未闭环 blocker）。
改为由 `Main._ready()` 调一次 `SfxService.install()`，幂等。
`audio_sfx_check` 的 `main_does_not_install_sfx` 钉着「Main 确实调了」。

### 2. 不声明 `class_name`

headless 下 `--script` / `.tscn` 模式不走 import 注册，新注册的 `class_name` 会解析成
"Identifier not declared"。消费方一律
`const SfxService := preload("res://ui/services/SfxService.gd")`。

### 3. 播放器挂 `get_tree().root`，**且必须延迟挂载**

挂 root 而不是挂页面：`Main._clear()` 会把页面子树整个释放，挂页面上会出现
「战斗胜利音刚开口就被掐掉」——胜负结算那一刻页面正在换。

**延迟挂载是必须的，这一条踩过坑**（见第五节第 1 条）：
`install()` 的调用点 `Main._ready()` 正好落在 root 装配子节点的窗口里
（`data.blocked > 0`），此时同步 `add_child()` 会**直接失败且不报错给 GDScript**
（返回 void、无异常），结果是 8 个播放器一个都没进树、**整条音效链静默无声**。
所以一律走 `add_child.call_deferred`。

### 4. 总线只有 `Master` + `SFX`，**不加 Music**

`default_bus_layout.tres` 里只有这两条。四处 BGM 代码写着
`bus = "Music" if get_bus_index("Music") >= 0 else "Master"` —— 加一条 Music
总线会让它们**同时**改走一条从没调过音量的总线。`ui_feedback_check` 的
`music_bus_added_silently` 钉着这一条。

### 5. 静音门只有一处，且不接任何输入回调

每个 `play()` 都过 `Presentation.ui_sound_allowed()`（玩家「界面音效」开关 +
备战页 Master 静音键的合流）。裁决不散到各调用点，否则结果是「关掉了但某个音还在响」。

本服务**不接** `_input` / `_unhandled_input` / `_gui_input`：`PrepScreen._input()`
用 if/elif 同时处理鼠标与触摸且无去重，挂上去在 Android 上一次触摸会响两次，
**而在 Windows 开发机上看不出来**。所以调用点必须落在「业务已确认成功」的那一行之后。
另有一道 40 ms 同 cue 重触发保护兜底（挡的是「同一帧里多条路径都判定成功」）。

### 6. 8 路播放器池

AOE 多杀时的死亡音、连点时的按钮音都要能叠。都在响时抢最老的一路。

## 四、五处「原本没有事件可挂」怎么接的

这五类在本轮之前工程里**没有任何可用的事件信号**，是新增的接入方式：

1. **羁绊激活** —— 在 `PrepUI._refresh_all()` 末尾做**差分**：记住上一轮的
   `SynergyService.flags_from_counts()` 结果，本轮多出档位才响一次；回合切换时重置快照。
   阈值表钉在 `SynergyService.RACE_THRESHOLDS`（god `[1,3,7]` / dark `[1,2,5,7]` /
   undead `[1,4,7]` / human `[1,2,7]`），与 `SynergyPanel._race_entries()` 必须一致。
2. **宝藏联动** —— `TreasureService.add_owned()` 里取 `active_linkage_ids()` 的
   **前/后快照**，新增了联动才响。
3. **Boss 出现** —— `BattleScreen._prepare_battle_models()` 里按
   `_effective_kind() == "boss"` 判定（而不是新增一个信号）。
4. **人王之死** —— `BattleVfx.cue_play_death()` 里加 `_maybe_play_human_king_death_sfx(uid)`，
   按 uid 去重（一次战斗里同一枚只能响一次）。
5. **金币收支** —— 见下。

### 金币用「每帧比对」，钻石用「收据落地」

用户口径：**金币的任何增减都响**。

局内金币的写点散在 `PrepBoardController` / `PrepFlowController` / `TreasureChoicePanel` /
`GameState` / `NetworkService` / `Main` 六七处，逐点插必然漏掉以后新加的那一处；
而战后结算（`Main.gd` 的 `settle_post_battle_gold`）与联机权威同步是**整块赋值**，
逐点插正好覆盖不到 —— 那恰恰是最该响的一声。

所以监视 `GameState.gold` 每帧比对（`SceneTree.process_frame` → static 回调，
与 `UiFeedback.install()` 同一先例）。配套两个防误响的点：

- 冷启动那一刻 gold 从 0 变 100 **不是**一笔收支 → `_currency_ready` 为 false 时只记基线；
- 「换了一本账」（重开一局 `GameState.reset_run()` / 读档 `SaveManager.load_run()`）
  也不是收支 → 这两处显式调 `resync_currency_baseline()` 对齐且不出声。

**钻石不在这条链上**：钻石是服务端钱包（`AccountManager.fetch_wallet`），各页面自己
fetch 自己存，没有中心状态可盯。商城页那笔在收据落地处单独接（`ShopScreen._on_order_submitted`）。

## 五、本轮抓出来的三个静默缺陷（这一节是最值得留的部分）

三个都是「门禁全绿 / 没人会去看日志 / 只在真机上表现为没声音」的类型。

### 1. `add_child` 撞上 busy 的父节点 → 整条音效链无声

**现象**：`install()` 被 `Main._ready()` 调用时，root 正在
`add_child(Main) → _propagate_ready()` 里（`data.blocked > 0`），
Godot 直接拒绝并打印
`ERROR: Parent node is busy setting up children, add_child() failed`。

**为什么难发现**：`add_child()` 返回 void、没有异常可 catch，GDScript 侧完全看不出；
8 个播放器一个都没进树，但 `play()` 照样返回 **true**、门禁计数照样 +1 ——
**第一版 `audio_sfx_check` 只验返回值和计数，是绿的**。唯一的线索是引擎日志里 8 行
ERROR，而那不是 `CHECK_RESULT`，不会有人翻。

**修法**：`_ensure_voices()` 一律走 `add_child.call_deferred`；
`play()` 取播放器时要求 `is_inside_tree()`（没进树的干净地算「这一声没发出去」，
而不是对没进树的节点调 `play()` 再吃一条 ERROR）。

**门禁补强**：新增 `voice_pool_not_in_tree` / `voice_pool_root_child_count` ——
直接数 `root` 下到底有没有 8 个能播的节点，并先从 `root` 侧独立数一遍
（不只手信服务自己的判据）。

### 2. `ui_sound_enabled` 落盘为 `false` → 两条断言**空过**

**现象**：`audio_sfx_check` 先「关掉开关」再「打开开关」。
第一版代码是「读 `before` → 关 → 断言不响 → 还原 `before` → 断言响」。
而 `ui_sound` 是**落盘持久化**的（`PlayerProfile.save_profile()`），
磁盘上留着 `ui_sound_enabled = false`（某次收尾没走到还原），于是：

- 「关掉不发声」两条 **空过**（恒不发声的实现同样能绿）；
- 「开着要发声」那条红。

**这是一条既有门禁也有的暗坑**：`tools/ui_feedback_check.gd` 的
`_check_confirm_fires_once()` 同样没有建立前置，直接继承了磁盘上的值。
（同文件里的 `_check_no_haptics_on_desktop()` 反而是显式建前置的正确写法。）

**修法**（两个文件都改）：

1. **显式建立前置**：先 `set_presentation_toggle("ui_sound", true)` +
   `AudioServer.set_bus_mute(master, false)`，并断言 `ui_sound_allowed()` 为真，
   跑完再还原成 `before`；
2. **换顺序**：把「开着要发声」（主断言）放到「关掉不发声」（对照组）**前面** ——
   环境一偏，原来的顺序就只剩对照组了。

**顺带修的现场**：磁盘上的 `ui_sound_enabled` 被写成了 `false`（原值备份在同目录
`profile.json.before_917_repair`），已改回 `true`。这是开发机上的档案，不改回来的话
开发机自己也是静音的。

### 3. `CUE_SHOP_BUY` 登记了但**没有任何调用点**

`shop_buy.mp3` 在 cue 表里、文件也在、门禁全绿 —— 但买棋子那一声从头到尾没接上，
生产代码里一处调用都没有（只在门禁自己的重触发用例里出现过）。是人工 grep 调用点时
发现的，**本来应该是门禁的职责**。

**修法**：在 `PrepBoardController` 两条购买路径
（`_buy_or_merge_shop_to_board` / `_buy_or_merge_shop_to_bench`）的**汇合点**
各补一次（放在两个分支里各写一次就是同一声两条路径各漏一次的机会）。

**门禁补强**：新增 `cue_without_call_site` —— 对每个 `CUE_*` 常量要求生产代码
（`res://scenes` / `scripts` / `ui` / `effects`，**刻意不含 `tools/`**）里存在
`SfxService.<常量名>` 字面量。

两个细节决定了这条断言不是空过的：

- **要求带 `SfxService.` 前缀**：否则 `SfxService.gd` 里那些常量**定义**
  （`const CUE_SHOP_BUY := "shop_buy"`）会把自己满足掉 —— 定义处永远存在。
- **排除 `tools/`**：门禁自己会调 `play()` 来验静音门，算进来等于让门禁给自己的断言当证人。

`star4_*` 那 5 条只能由 `star4_cue_for(unit_id)` 间接派发（调用方给的是棋子 id），
常名不会出现在调用点，所以列入 `INDIRECT_CUES` 明示豁免，并**额外**钉一条
「派发入口 `star4_cue_for` 必须有生产调用点」——否则把 `STAR4_CUES` 映射整个删空也能全绿。

**变异测试**：临时加一个无调用点的 `const CUE_ZZZ_MUTATION_PROBE`，门禁如期报
`cue_without_call_site ... CUE_ZZZ_MUTATION_PROBE`；删掉后复绿。证明这条断言有效。

## 六、门禁

### 新增 `tools/audio_sfx_check.tscn`（96 项）

验五件会静默出错的事：① cue 登记了但文件不在；② 每条 cue 有没有生产调用点；
③ BGM 常量指向的文件不存在；④ 静音开关关掉了音还在响；⑤ 代币监视器响错方向 /
响两次 / 把「换了一本账」当成收支；另外单列一条**播放器必须在树里**。

不验什么：**不验好不好听、也不验真机上能不能听见**。headless 用 Dummy 音频驱动，
文件烧坏了也听不出来。音色与音量是 external，不在这里假装验过。

### 修了三条既有门禁的**前置条件**（不是改断言口径）

| 门禁 | 改动 |
|---|---|
| `ui_feedback_check` | `_check_confirm_fires_once()` 显式建「开关开 + 总线不静音」前置 |
| `modal_lifecycle_check` | `_ready()` 里预热 SfxService 播放器池，再开始量基线 |
| `audio_sfx_check`（新增） | 同上，出自同一批 |

`modal_lifecycle_check` 那条值得说明：它的断言是「弹窗开→关不留残留」。
9.17 起弹窗会发声，而 SfxService 的池是**首次 play() 时在 root 下建 8 个节点、
之后常驻**的，于是第一次发声把这份一次性初始化记成了泄漏
（实测 `nodes+7, root_children+8`）。

处理方式是**预热前置**，而不是「把 `GlorySfxVoice` 从统计里滤掉」那种做法 ——
后者是把断言改松，一旦真的漏了播放器也照样绿。预热只是把前置条件摆好，
池之外的任何新增节点仍然一条不漏。

## 十、补充修复：佣兵召唤音效全队同步（同日追加）

### 问题

要求是「我方队伍召唤佣兵时，**整个队伍**都能收到召唤音效」。改之前只有雇佣者本人听得见：

- 自己那一次：有声音（房主/单机/教程在成交处，客机在服务端回执落地处）。
- **队友那一次：一声不出** —— 队友的佣兵列表确实变了，但没有任何地方为它发声。

### 关键约束：不能加新的 `@rpc`

最直接的写法是加一条「佣兵召唤广播」RPC，但那会给线上协议**插入一个新的方法 ID**，
所有已发布客户端与服务器的方法编号整体位移。按本仓既有约定（
`scripts/multiplayer/NetworkConfig.gd` 的 `NETWORK_PROTOCOL_VERSION` 现在是 **29**，
注释里写明「加 `@rpc` 就会移动线上 RPC ID」），那就必须**同时升协议号并重新部署 ③ 服务端**，
否则新老客户端互相连不上。

而「队友多雇了一个佣兵」这件事，**服务端本来就已经同步过了**：

```
PrepBoardController._hire_mercenary_to_slot()
  -> NetworkService.team_send_prep_mercs()            # 房主
  -> NetworkService._rpc_team_prep_mercs_submit()     # 客机
    -> NetworkService._rpc_team_prep_mercs()          # 服务端转发
      -> team_prep_mercs[slot] = {"round": ..., "ids": [...]}   # 落进本地表
        -> emit team_prep_mercs_changed
          -> PrepUI._on_team_prep_mercs_changed()
            -> PrepUI._check_team_merc_alert()        # <- 音效补在这里
```

所以本轮**复用这条链路**，零协议改动、不需要重部署服务端。

### 两处改动

**① `scenes/prep/PrepBoardController.gd`**（`_hire_mercenary_to_slot()` 内，L183-186）

**② `scenes/prep/PrepUI.gd`**（`_check_team_merc_alert()` 重写）

两处关键变化：

var my_slot := NetworkService.team_local_slot if NetworkService.team_active else 0

1. **自己那格必须排除，否则房主双响。** `_team_merc_counts()` 把自己的座位也算进 `current`，

## 十一、补充修复：7 人羁绊激活音被「同帧换回合」吞掉（同日追加）

### 问题

反馈原文：「触发 7 棋子羁绊时没有声音（即同种族的 7 人羁绊）」。

复现后发现**不是一直不响**：同一个回合内把第 7 个同族棋子落到盘上，那一声是响的。
**只在「回合号也变了」的那一帧补上第 7 个时才不出声** —— 而联机下这恰恰是最常见的一步：
玩家常常在回合切换的同时把攒好的第 7 个棋子放上去。

### 根因：一条「防外部覆盖」的守卫，把玩家的正常落子一起挡了

9.17 首版用的是**原始人数差分 + 回合守卫**：

```gdscript
if _synergy_snapshot_round != GameState.round_index:
    _synergy_snapshot_round = GameState.round_index
    _synergy_counts_before = SynergyService.count_races_from_board()
    return                      # <- 换回合这一帧直接吞掉
# 之后才做人数差分，was < 档位 <= now 就播
```

守卫的立意没错：棋盘被**外部**整块覆盖时（重连、读档、服务端状态同步）不该凭空响。
错的是它拿**回合号**当「棋盘是外面送来的」的代理判断，而这两件事在本仓**同帧发生**：

```
Main.gd:337   GameState.round_index = int(payload.get("round_id", GameState.round_index))
Main.gd:2386  round_index = mini(round_index + 1, FINAL_ROUND)
Main.gd:2491  round_index = int(state_payload.get("round_index", ...))
```

③ 的服务端 state payload 把 `round_id` 与棋盘**放在同一个包里**下发，客户端在**同一次**
`_refresh_all()` 里既换了回合号、又换了棋子表。玩家自己落的那一手如果正好落在这一帧，
就被当成「外部覆盖」吃掉。更糟的是快照**已经被写成 7**，同一档整局不会再补 ——
面板明明写着「已解锁」，声音一声不响。

### 取证（探针 `_probe_synergy_roundguard`，真实实例化路径）

| 场景 | `play_count(CUE_SYNERGY_ACTIVATE)` |
|---|---|
| S1 同回合 6 神 → 7 神 | **1**（正常） |
| **S2 换回合 + 6 神 → 7 神（同一帧）** | **0 —— 复现** |
| S3 再同回合 6 神 → 7 神 | **1** |
| S4 进场时盘上已经是 7 神 | 0（**按设计**，见下） |

顺带排除了两个「不是原因」的方向：音频文件本身是合法的 1.000 s MP3（`_probe_audio_lengths`），
`SfxService.play()` 的返回值与 40 ms 重触发保护在同回合路径上都没问题。

### 改法：比「已解锁档位的集合」，不比人数

守卫整条删掉，改成对比**已解锁档位集合**（`PrepUI._synergy_unlocked_tiers()`）：

```gdscript
var _synergy_unlocked_before: Dictionary = {}
var _synergy_sampled := false

func _synergy_tier_key(race: String, threshold: int) -> String:
    return "%s@%d" % [race, threshold]

func _synergy_unlocked_tiers() -> Dictionary:
    var counts := SynergyService.count_races_from_board()
    var unlocked: Dictionary = {}
    for race in SynergyService.RACE_THRESHOLDS.keys():
        var race_name := str(race)
        var have := int(counts.get(race_name, 0))
        for threshold in SynergyService.RACE_THRESHOLDS[race]:
            if have >= int(threshold):
                unlocked[_synergy_tier_key(race_name, int(threshold))] = true
    return unlocked

func _check_synergy_activation() -> void:
    var unlocked := _synergy_unlocked_tiers()
    if not _synergy_sampled:
        _synergy_sampled = true          # 进场第一帧：只认账，不发声
        _synergy_unlocked_before = unlocked
        return
    var crossed := false
    for key in unlocked.keys():
        if not _synergy_unlocked_before.has(key):
            crossed = true
            break
    _synergy_unlocked_before = unlocked   # 判断之后无条件更新
    if crossed:
        SfxService.play(SfxService.CUE_SYNERGY_ACTIVATE)
```

四件事一次解决：

* **换回合那一帧不再特殊**（本次反馈的正题）：没有回合判断，同帧落子照样被看见。
* **进场不为既有战果发声**：`_synergy_sampled` 只认基线。刚进备战页盘上已有 7 神（读档 /
  重连 / 服务端下发）不响 —— 这是原来那条守卫唯一真正想挡的东西，换成集合口径后由首帧采样来挡。
* **档位之内的人数波动不是事件**：7 → 8 → 7 全程静默（原实现 7 → 6 → 7 会再响一遍）。
* **掉了再跨回来要响**：7 → 6（`god@7` 从集合里消失）→ 7（重新出现）→ 响一声。这是对的，
  玩家确实又做了一次这个操作。

`_refresh_all()` 结尾仍然是 `_check_synergy_activation()`，位置不变（放最后：
前面的 `_auto_combine_all()` 可能刚把棋子合成掉、改变棋盘构成，先采样会拿到中间态）。

### 新门禁 `tools/synergy_activation_sfx_check`（39 项）
