## 第 1 条 · 最终战血条颜色

**要求（用户原话）**：「恒定我方绿、敌方红」。

**根因链**（不是配色函数写错，是两个概念被一个开关绑死）：

```
最终战把战斗轴改成左右（BattleSimulator._apply_final_round_left_right_layout）
  ⇒ 位置绝不能翻（翻了画面会坏）⇒ _arena_flip_y 在决赛被强制 false
  ⇒ 而 _arena_flip_y 同时兼管「配色归属」⇒ 顺带把配色也关了
  ⇒ B 队玩家（我方 = 规范化 enemy 侧，位于右侧）看到自己全红
```

规范化棋局里 A 队（slot 0-2）恒为 `"player"` 侧。观众若坐在 B 队，画面上的「我方」是规范化的
enemy 侧，血条**必须翻色**，否则看到自己是红的。

**改法**：

- `BattleUI.gd`：拆出 `var _color_flip := false`（与 `_arena_flip_y` 并列，语义分开注释）。
- `BattleScreen.gd`：
  ```gdscript
  _arena_flip_y = str(replay.get("kind", "")) == "pvp" and my_team == 1 \
      and GameState.round_index != GameState.FINAL_ROUND
  # 颜色归属单独一个开关，不再跟着 _arena_flip_y 一起被决赛排除。
  _color_flip = str(replay.get("kind", "")) == "pvp" and my_team == 1
  ```
  （最终战的 replay `kind` 已被 `prepare_team_state` 从 `"final"` 改写为 `"pvp"`，所以这条判据对决赛也成立。）
- `BattleRenderer.gd`：`_display_team()` 改为读 `_color_flip`；判据抽成两个 `static` 纯函数
  `resolve_display_team(fighter_team, color_flip)` 与 `hp_color_for_display_team(display_team)`
  （重型 3D 场景不能 headless `new()`，只有 static 能被探针直调）。
  半场标签（`BattleArena.gd`）仍用 `_arena_flip_y` —— 那是**位置**语义，正确，不改。

**门禁 `tools/battle_team_color_check.gd`（PASS 24/0）** 六组判据：`resolve_display_team` 四组合、
色号历史值（绿 `(0.2,0.9,0.25)` / 红 `(1.0,0.18,0.12)`）、**决赛 B 队端到端**（两个开关必须解耦）、
结构（`_color_flip` 赋值不许含 `FINAL_ROUND`，反向保险 `_arena_flip_y` **必须**含）、
结构（`_display_team` 读 `_color_flip` 不读 `_arena_flip_y`）、字段存在。

**变异 3 处全红**：M1 `_display_team` 退回 `_arena_flip_y`（failures=2）/ M2 `_color_flip` 重加决赛排除
（failures=1）/ M3 static 里删掉翻转逻辑（failures=6）；全部按 sha256 还原 `MATCH`。

★ **踩到的判别力洞**：结构断言最初只切**第一行**（`split("\n")[0]`），而 M2 用**行尾 `\` 续行**把

**要求**：「实时更新所有数据，以此时棋子的真实状态展示」。

### ★ 第二轮订正（用户复报「攻速还是没更新」）

**现象**：修完上面这轮后用户截了一张图 —— 面板「攻速 0.95」纹丝不动，而**同一个面板的
「状态」栏明明写着「攻速提升 1.1秒」**。也就是 buff 确实在生效，面板没跟上。

**第一轮为什么不够**：第一轮只做到「优先读活字段、def 兜底」，解决的只是**被就地改写过
的裸值**。但战斗真正用的攻速**不是裸字段**（`BattleSimulator.gd:730`）：

```gdscript

    * StatusEffectService.attack_speed_multiplier(f)
    * _dynamic_attack_speed_multiplier(f), 0.25, 2.5)
```

`speed_bonus` / `slow` / `frenzy_stacks` / `blood_rampage` **全都只活在这个乘数里，不写回
`f.attack_speed`**。所以「读裸值」恒等于基准值 —— 截图里「攻速提升」在生效、面板却不动，

**探针实锤**（`work/_qa_929/probe_as_live.gd`，改前跑）：

**★ 口径铁律**：面板**直接调用战斗同一个函数**，不许自己再拼一遍公式。
拼一遍就会漏项 —— 漏的就是 `speed_bonus` / `frenzy` / `blood_rampage`，也就是这次复发的直接原因。

**改法（第二轮）**：

| 项 | 改前 | 改后 |

| 攻速 | `f.attack_speed` 裸值 | `clamp(base × StatusEffectService.attack_speed_multiplier() × BattleSimulator._dynamic_attack_speed_multiplier(), 0.25, 2.5)`，与 `BattleSimulator.gd:730` 同一式子 |

**用截图里的真实单位复核**（`probe_leo_live.gd`，炎阳王者 `merc_leo_sun`，

## 第 4 条 · 离线自测房间座位标签（本轮新增门禁）

**用户原文**：「离线自测房间的头像上面的文本异常显示，本应显示『房主』，现在显示的是『未准备』，
而假想敌A的框框里『假想敌』消失了，且假想敌A的字体和其他的假想敌B等不一致。如下图1。
修复为：座位上面的样子与在线自定义房间的一致，如下图2。」

**docx 图片归属（用 `word/_rels/document.xml.rels` + 正文顺序解析确认）**：
`media/image6.png` = 「如下图1」= **坏例（离线自测）**；`media/image7.png` = 「如下图2」= **好例（自定义房间）**。

### 三条现象 → 两个根因

**根因 A（②③：字号不一致 + 字消失）**
`Team3v3Lobby._refresh()` 根据座位状态改写 `_placed` 里两条标签的 `font_size / pos / size`，
**但 `_placed` 只是「期望值」，真正落到 Label 上的是 `_layout()`**。换座（`_on_slot_pressed`）与
加/减假想敌（`_toggle_dummy`）这两条路径**只调 `_refresh()`、不调 `_layout()`**，于是那个
**状态刚变过的座位**停在上一轮的字号与位置上。

**探针实证**（`work/_qa_929/probe_lobby_stale.gd`，离线、先落座 A 座 → 换到 C 座 → A 座设成假想敌）：

```
修前  AFTER_FILL_AI  s0('假想敌 A', ov=16)   ← 字号陈旧（应 23，与其余假想敌一致）
                     s1('假想敌 B', ov=23)
                     s2('玩家 C（我）', ov=16)
                     s3..s5('假想敌 N', ov=23)
修后  AFTER_FILL_AI  s0('假想敌 A', ov=23) ✓ s1..s5 全 23，s2 仍 16（player 组）
```

圈内状态标签同样：修前 `s0 pos=(518,295) size=(85,30) font=14`（停在 player 时代「框下方」），
修后 `s0 pos=(514,242) size=(98,34) font=16`（与 s1/s3/s4/s5 **完全同组 = 框内**）——
这就是玩家看到的「框框里『假想敌』消失」（字被留在框外）。

**截图侧独立佐证**（逐像素 diff `image6` vs `image7`）：A 座圈外名牌的字形框宽度/高度
**image6 = 45×25 vs image7 = 62×32**，比值 0.73 ≈ 字号 20/28 = 0.71 ⇒ 确实是字号差，不是错觉。

**根因 B（①：房主文案）**
`_leader_slot()` 离线**硬编码返回 `0`**，而离线房间里玩家可能在别的座位（换过座）。
于是「房主」被写给 0 号位，那位子若是假想敌，文案紧接着又被 `dummy` 分支的「假想敌」覆盖，
玩家自己的座位只能落到 `else` 分支显示「未准备」。

**探针实证**：修前 `s0='假想敌' s2='未准备'` → 修后 **`s2='房主'`** ✓。

### 改法

```gdscript
# ① 离线房间只有本机一个玩家 ⇒ 房主就是自己。
func _leader_slot() -> int:
	return NetworkService.team_leader_slot if _online() else _my_slot()
```

```gdscript
# ②③ 把「一条 _placed 记录落到节点上」抽成 _apply_placement()，
#     _layout() 全量用它，_refresh() 改完 _placed 就地也用它（_apply_tracked）。
func _layout() -> void:
	...
	for item in _placed:
		_apply_placement(item, scale, origin, viewport_size)

func _apply_placement(item, scale, origin, viewport_size) -> void:
	# 位置 / 尺寸 / 字号三项 + 整数像素吸附，全部集中在这里
	...

func _apply_tracked(item: Dictionary) -> void:
	# 给 _refresh() 用：按上一次 _layout() 记下的比例与原点落到节点
	if _layout_scale <= 0.0:
		return
	_apply_placement(item, _layout_scale, _layout_origin, get_viewport_rect().size)
```

`_refresh()` 里改完 `_placed` 立刻 `_apply_tracked(placement)`（名牌与圈内标签各一次）。
两条路径**共用同一份落点逻辑**，不会出现「只在某一条路径上对」的半修。

### 门禁 `tools/team_lobby_seat_label_check.gd`（**PASS 35/0**，新建）

五组用例：

1. **行为**：走真实入口（`_on_slot_pressed` / `_on_slot_ai`）复现玩家那条路径后，六个座位的
   圈外名牌字号必须**按状态分组一致**，且 dummy ≠ player（否则「按 state 调字号」等于没生效）。
   ★ 含**前提体检**：断言 A 座确实变成了假想敌，否则后面的「字号一致」断言会静默空过。
2. **行为**：A 座从 player 翻成 dummy 后，圈内标签的落点必须真的动到「框内」那一组。
   ★ 比的是**相对各自席位的偏移**（席位基点从活实例读 `SLOT_POS`，不复制坐标），
   用**像素距离 ≤1px** 判等 —— `is_equal_approx` 对两个独立 round 过的浮点位置过严，会假红。
3. **行为**：离线房间里「房主」必须落在玩家**自己**的座位上（含反向：别的座位不许出现房主）。
4. **结构**：`_layout()` 与 `_refresh()` 必须共用 `_apply_placement`；`_refresh()` 那段
   **限定作用域**到 `for placement in _placed:` 之后的窗口里数赋值与落点次数
   （整份文件里找会别处命中，判据失效）。
5. **行为**：只调 `_refresh()` 不调 `_layout()` 也必须生效（换座那条路径的真实形态）。
