## 逐条落点

### 第 1 条 图鉴宠物立绘重叠（点哪只只显示哪只）
- 根因：演示台 `_pet_stage` 的**唯一写入点** `BagScreen._render_pet_detail()` 只 `add_child`、**从不清台**；点宠物卡片走 `_select_pet → _refresh_pet_selection()`，那里只 `_clear_children(_pet_detail)`（右侧文案）**没清演示台** ⇒ 每点一只就往演示台**追加**一张立绘。新立绘 `PRESET_FULL_RECT` 铺满盖住旧的，旧立绘（蘑菇红白帽 / 老虎棕毛 / 松鼠尾巴）从四周露出来。
- 修法：`_render_pet_detail()` 在 `add_child(artwork)` 前加 `_clear_children(_pet_stage)` ⇒ 「渲染某只详情」＝「演示台只留这一只」。
- 顺带：演示台由 `CenterContainer` 改普通 `Control`（不再把子节点最小尺寸上报成自己的）、右侧档案面板定高 `PET_DETAIL_MIN_HEIGHT` + 内部滚动 ⇒ 长文案不再把页面末尾的宠物栏顶出屏幕（矮屏 960×540 实测）。
- ★ 上一轮门禁为什么没抓到：老 B 段只量 `stage.get_child(0)`，累积时 child(0) 仍在台内 ⇒ **假绿**；可视化夹具又把 `_selected_pet` 设在**进树之前**，只走一次 `_render()`，绕开了点击路径。已补 `stage_single_artwork` / `artwork_matches_selection` / 交替点选序列。

### 第 2 条 英文模式结算 / 历史里法阵守护者仍是中文
- 根因：战报里存的是守护者的**中文名**（`FinalSettlementData.build` 取的是 actor 的 `name`，即 `formation_allies.json` 的 `name`），英文界面上直接显示中文。
- 修法：`FinalSettlementPanel` 新增 `_ally_display_name()`，就地按「id / 中文名 / 英文名」任一命中反查同一张表，换成本语言名。**不改战报格式** ⇒ 历史里的旧记录同样能翻（历史详情复用的就是本面板）；表里查不到就**原样返回**（宁可不翻，也不显示成空白或一串 id）。
- 注意：`FinalSettlementPanel.gd` 还带了「返回队伍 / 详情面板」等同批改动，见该文件 diff。

### 第 3 条 霜印使（Icey）棋子模型头发应为白色
- 根因：`tools/model_refinement/crimson_refine.py` 里有一段**只对 Icey 生效**的整族「刷红发」（`recolour_hair` + `hair_mask`），重刷几何时把源贴图的白发染成了种族红。
- 修法：删掉 `if unit == "Icey":` 那段染色分支，重刷 `assets/models/units/crimson_refined/Icey/Icey_m0_albedo.png`（泛白发丝 91.6% / 正红 0.0%）。`Icey_m0.tres` 与仓侧逐字节相同，无需变更。
- ★ 门禁 `tools/icey_hair_check.gd` 读贴图**必须 `Image.load_from_file(源 PNG)`**，不能用 `load()`/`tex.get_image()` —— 后者读的是导入后的 `.ctex` 缓存，改源图根本不反映，变异会**假绿**。

### 第 4 条 棋子 轻点 / 长按 / 拖拽 三态分流
- 根因：棋盘格 / 待命格的 `pressed` 与 `attach_long_press` 挂在**同一个按钮**上，长按超时同时置 `long_press_consumed` **并**照常发 `pressed` ⇒ 一次长按既弹属性又把格子设成选中态，关框后残留选中，下一次轻点就把它挪走（用户报的「误挪动」）。
- 修法三步：①`PrepUI._on_board_activated/_on_bench_activated` 先 `_overlay.consume_long_press(btn)` 再转业务；②`PrepBoardController._on_board_pressed/_on_bench_pressed` 里「点 A 选中 → 点 B 挪过去」整段删除（挪动只剩拖拽一条路：`PrepDragButton.force_drag` → `PrepBoardCellButton._drop_data`，那条路本来就不经过这两个函数）；③射程预览改挂「长按查看属性」（`PrepUI._inspect_board_cell` 只写 `_board_hud._selected_board` 当**检视格**）+ `PrepScreen._process → _sync_board_inspect_after_overlay()` 在详情框关闭那一帧撤掉高亮。
- **保留**「商店卡选中 → 点格子买入」这条轻点链（针对商店卡、不是棋盘上的棋子）。
- ★ **返修（用户复测）**：长按弹过属性框后、手指**还没松**时随手一划过 28px，仍会 `force_drag` 把棋子挪走。修法：`PrepDragButton._maybe_launch_drag` 起拖前加 `if bool(get_meta("long_press_triggered", false)): return` —— 本次手势只要弹过详情框，后半程就只有「看完松手」一个结局；挪动一律要求**重新按下再滑动**。判据用 `long_press_triggered` 而**不是** `long_press_consumed`（后者会在松手那一下被消费掉，而那时手指还没动完）。

### 第 5 条 AI 佣兵 / 萝卜经济要与真人玩家一致
- 根因：AI 对手（dummy 座位）的经济走的是「按 `(seed, slot, round)` 播种子 + 估算胜场 / 击杀 / 未来收入」的历史模拟，与真人的持久经济不一致。
- 修法：`BotPlayer` 新增**有状态**的实时经济 `new_state` / `prepare_round` / `settle_round` / `view`；新增 `scripts/economy/LiveBotEconomy.gd` 驱动；`NetworkService.team_bot_states` 取代旧的预览路径（`BotPlayer.state_for` 先查它）。细节对齐真人：佣兵**打完一场即过期**、商店成本走 `EconomyLedger.unit_cost`（含宝藏折扣）、刷新价考虑「金钱套」、每枚棋子带 `uid` / `cost_basis`。
- `BattleReplayJob` 的 `NET_FIELDS` / `ROOM_INPUT_FIELDS` 增设 `team_bot_states` / `bot_states`，让回放边界也带上 AI 经济状态。
- **离线自测里照旧生效**（用户口径）：`PrepScreen` 的 `prepare_local_bots()` 只由「教学局」让开，**没有**跟第 6 条的倒计时共用守卫。

### 第 6 条 备战倒计时
- 实现：`scripts/rounds/PrepDeadline.gd`（PVE 35s / PVP 50s，`deploy` 幂等 + 不白送）+ `scenes/prep/PrepCountdown.gd`（写 `prep_countdown_seconds` meta + 最后 3 秒屏幕正中大号「3!/2!/1!」，`mouse_filter=IGNORE` **不挡棋盘**）+ `PrepUI._refresh_start_button_label()` 给「准备」按钮加「（xx s）」后缀。
- 到点**自动上阵**：待命区最左优先，否则买商店最左（`PrepScreen._auto_deploy_at_deadline()`）；全员就绪提前开局；超时判定 / 到点开回合 / AI 托管在 `NetworkService._tick_prep_deadlines()`（**服务端那半**）。
- ★ **口径：只对「离线自测」不生效**。判据统一 `NetworkService.is_offline_team_match()`（= `offline_selftest` 且非 `team_active`，与设定里「退出对局」同源；联网对局即使掉线也不为真 ⇒「掉线 → AI 托管」那条联网路径不受影响）。离线自测里：不倒计时、不自动上阵（`_auto_deploy_at_deadline()` 里加守卫，把「碰巧到不了」变成「结构上到不了」）。
- ★ **返修（用户复测：自定义房间也没倒计时了）**：根因**不是**离线守卫（`team_join`/`team_host` 在置 `team_active=true` 的同刻置 `offline_selftest=false`，两标记不可能同时为真 —— 四态探针实测），而是 `PrepCountdown` 把「服务端已确认 prep」当**前置条件**（`if not server_prep_confirmed(): _cue.hide(); return`）：**自定义房间的房主在专服上同样是 `is_host == false` 的客机**，服务器是旧包（`_build_room_state` 不发 `prep_seconds_left`）或阶段未到 prep 时，**整间房**都看不到倒计时。修法：服务端值由**前置条件降级为优先来源**，本地时钟兜底（`if server_prep_confirmed: left = server_left if server_left >= 0`）。

### 第 7 条 棋盘皮肤（冰雪）在排位 3v3 没生效
- 根因：摆放界面的皮肤图在 `_build` 那一刻按 `PrepSkin.path()` 定死，而皮肤是登录后**异步**从账号服务器拉的（`Bootstrap._fetch_loadout`）；冷启动后立刻进一场排位 / 组队对局时，界面可能在皮肤回来之前就建好了 ⇒ 那一整局都是默认青草地。
- 修法两道保险：①`PrepSkin.loaded`（本会话至少成功拉到过一次）+ `PlayerProfile._adopt_prep_skin()` 置位 ⇒ `PrepScreen._ready` 进对局补拉一次；②`PlayerProfile.prep_skin_changed` 接到 `PrepUI.reapply_prep_skin()`，皮肤一到就把已建好的棋盘底图 / 河面 / 待命区 / 萝卜 / 萤火虫色 / 河面波光**全换过来**（河面流光按皮肤可关，冰雪就关）。
