## §1 现象与根因

### 1.1 用户看到什么

一排近战单位挤在后方**原地不动**（截图里的民兵），不出手、不位移。前两轮的修复
「看起来生效过一阵」，但同一现象第三次出现。

### 1.2 定位（真实整场对局，30 场 / 76 单位）

新增只读诊断 `diag_stuck_battle_928`（复用 `ai_survival_curve_check` 的真实模拟台：
6 张 Bot 棋盘 + `prepare_team_state(0)` + `step_state` 循环，`ROUNDS=[4,10,15]`、`SEED_BASE=202609280000`）。
停滞定义：`存活 && 未眩晕 && dist > reach && 本 tick 位移 < 0.2px`。

第二轮口径下的读数（**本轮开始时实测**）：

```
units_stuck_ge_alert = 46 / 76        卡住 ≥0.6s 的单位
units_stuck_ge_100   = 22 / 76        卡住 ≥10s
max_stuck_run_ticks  = 282            最长连续 282 tick（28.2 秒）
offenders_by_switch_attempts = { 3: 41, 0: 2, 1: 3 }
```

**`41/46` 个卡住单位的 `_switch_attempts` 正好等于 3（= `MAX_SWITCH_ATTEMPTS`）。**
这就是根因的签名：**上限被当成整场预算，换满 3 次就永久停手**。

现场取证（同一诊断带出的单帧形状）：`blocked_dirs=8~16/16`、`touching=1~3`、
`bds=30/31/32`（**精确等于接触距离** `BODY_RADIUS_PX*2 = 30`）、`overlaps=0`、
`step=4~17px`、`moved=0.000` —— 实体没重叠，正前方被**同队友军**顶死在接触距离上。

### 1.3 三条互相叠加的缺口

| 缺口 | 表现 |
|---|---|
| ★★★ 上限是**整场**预算 | 换满 3 次 → 永久退回旧行为，站着等队友死（`attempts` 停在 3） |
| ★★ 避让只有**一个槽位**、且拿 `locked_target_uid` 当被避让者 | 两个够不到的目标互相覆盖（来回踢）；锁定为空/被嘲讽改写时记了个**不相干的人**（空转） |
| ★★★ 位移层绕行门槛过严 | 正对挡路者时切向残量「很小但非 0」⇒ 既不触发绕行、又几乎走不动（实测 0.34px/tick） |

## §2 做法

### 2.1 换目标上限：整场预算 → 每轮预算 + 冷却重开（`BattleSimulator.gd`）

```gdscript
const MAX_SWITCH_ATTEMPTS := 3
const SWITCH_COOLDOWN_TICKS := 30   # 换满一轮后的冷静期

if int(f.get("_switch_cooldown", 0)) > 0:
    f._switch_cooldown = int(f.get("_switch_cooldown", 0)) - 1
if int(f.get("_no_progress_ticks", 0)) >= NO_PROGRESS_TICKS \
        and int(f.get("_switch_cooldown", 0)) <= 0:
    if int(f.get("_switch_attempts", 0)) >= MAX_SWITCH_ATTEMPTS:
        f._switch_attempts = 0                    # 重开一轮
        f._switch_cooldown = SWITCH_COOLDOWN_TICKS
        f.erase("avoid_target_uids")              # 冷静期结束后避让也清掉
    else:
        ... 记账避让 + attempts += 1
```

**关键点**：上限仍然存在（防两个都够不到的目标每 6 tick 互踢、目标标记来回闪），
但它**不再是终点** —— 冷却结束清空避让、重开一轮，**绝不停手**。

### 2.2 避让：单槽 → 集合，并归因到实际失败者

```gdscript
# _step_team：记的是「这一 tick 实际没打到的那个目标」，不是 locked_target_uid
var failed := str(f.get("_progress_uid", ""))
if failed.is_empty():
    failed = str(f.get("locked_target_uid", ""))
if not failed.is_empty():
    var avoided: Array = f.get("avoid_target_uids", [])   # ★ 集合，累积
    if not avoided.has(failed):
        avoided.append(failed)
        f.avoid_target_uids = avoided
```

选敌侧（`BattleSimShared._team_select_target`）读**集合**并从候选池里剔掉：

```gdscript
if not avoided.is_empty() and pool.size() > 1:     # 剔完为空就保持原样
    ...without_avoided...
```

### 2.3 避让修剪：逐元素纯函数（替换 `avoid_should_clear`）

```gdscript
static func avoid_prune(avoided: Array, alive_uids: Array, blocked_uids: Array) -> Array:
    # 留在集合里的条件：目标**还活着** 且 **现在仍然挡路**。
    # alive/blocked 由调用方按同一套 `_ally_blocks` 几何算好传进来 ——
    # 这样本函数保持纯函数、探针能直调，而几何仍然只有一份实现。
```

调用点每个 tick 重算一次（只对集合里那几个目标算，不是全体）：

```gdscript
for o in opponents:
    if not avoided_now.has(str(o.get("uid", ""))):
        continue
    if alive: alive_uids.append(uid); if _ally_blocks(f, o, bodies): blocked_uids.append(uid)
var pruned := avoid_prune(avoided_now, alive_uids, blocked_uids)
if pruned.size() != avoided_now.size():
    f.avoid_target_uids = pruned
```

### 2.4 位移层绕行放宽（`_move_without_pushing`）

```gdscript
# 旧口径：if remaining.length_squared() < 0.000001 and length - travel > 0.001:  # 只试一侧
if remaining.length() < length * 0.2 and length - travel > 0.001:
    var tangent := Vector2(-normal.y, normal.x)
    var budget := length - travel
    var plus := _first_contact(position, radius, tangent, budget, f, bodies)
    var minus := _first_contact(position, radius, -tangent, budget, f, bodies)
    var side := 1.0 if str(f.get("uid", "")) < hit_uid else -1.0
    if float(plus.get("contact", budget)) > float(minus.get("contact", budget)) + 0.001:
        side = 1.0
    elif float(minus.get("contact", budget)) > float(plus.get("contact", budget)) + 0.001:
        side = -1.0
    remaining = tangent * budget * side
```

门槛改成**相对**（本次位移的 20%）而不是绝对值 `1e-6`；两侧都扫一遍、取走得远的
（旧口径按 uid 字符串比较定方向，可能选到**更短**的那一侧）。

★ 五个状态字段全放 **fighter 字典**，**没碰回放帧**
（`_replay_capture_frame` 仍是单次 13 列构造，属 `ReplayDigest.SIMULATION_TOP_FIELDS`）。

## §3 判据

`tools/battle_reach_target_check.tscn` → **PASS 45 / 0**（上一轮 23 → 本轮 45）。

### 3.1 行为

| 场景 | 断言 |
|---|---|
| A 预置锁定 + 友军墙 + 侧向可达目标 | `blocked_target_really_unreachable`（前提体检）/ `stuck_unit_switches_to_reachable` / `stuck_unit_ends_on_reachable` / `avoidance_recorded` |
| B 无阻挡对照 | `no_wall_attacks_nearest` / `no_wall_keeps_lock` / `no_wall_no_avoidance` / `no_wall_no_retry` |
| C 挡路者被拆 → 避让必须**当场**解除 | `avoidance_recorded_before_kill`（★ 前提体检）/ `avoid_released_at_kill_tick` / `avoid_released_after_wall_gone` / `avoid_release_not_via_round_reset` |
| D 只有一个够不到的目标 | `switch_budget_is_per_round` / `never_pinned_at_cap` |
| E 两个够不到的目标 | `avoidance_accumulates`（峰值 2）/ `avoid_pair_keeps_retrying` |
| F 顶着队友也要能挪动 | `wedge_blocker_really_head_on`（前提体检）/ `head_on_blocker_still_walks_around` / `free_path_keeps_full_step` |

**★ 场景 C 本轮重写（M3 假绿的复盘）**：上一版把焦点单位放在离墙 110px 处、
拆墙 tick 定在 10。焦点单位移速 18.15px/tick，**6 tick 就贴到墙上**，而
`NO_PROGRESS_TICKS = 6` —— 「攒够 6 tick 停滞」与「贴到墙上」几乎同时发生，
拆墙只要早一点点，**避让从未被记录过**，于是拆墙后的读数在**变异前后都为 0** ⇒
判据没有判别力（M3 变异因此漏过）。

现在的做法：把**位移这个变量完全冻住**（焦点单位与目标都 `move_speed_px = 0`，
墙仍然会朝目标走），只考「修剪」这一件事。焦点与目标的距离恒定 350px，
停滞判定在第 7 tick **必然**触发；拆墙 tick 10、全程 24 tick，远早于
「换满 3 次进冷却」（t≈21），因此这段时间里唯一能清空避让的路径只能是**修剪**。
并且加了 `avoidance_recorded_before_kill` 这条**前提体检** —— 一旦本场没建立起
避让记录，它会**先红**，而不是让后面的「释放」断言静默空过。

★ 「不是被冷却顺带擦掉的」这条，从「事后数 attempts」改成**直接读
`_switch_cooldown > 0`**（那条路径的签名），更贴机制、不受 tick 计数漂移影响。

### 3.2 纯函数（直调生产实现，不在门禁里复刻）

`no_progress_step` 4 条：`np_resets_on_target_change` / `np_counts_when_stalled` /

### 3.3 结构（先 `_strip_comments` 剥注释，再 `contains`）

★ **本脚本是踩过事故之后加固过的**：它把生产文件**就地改坏再还原**，第一次跑时
进程被外部 SIGTERM 打断、`finally` 没执行，其中一处变异**留在了生产文件里**
（缩进还被写坏 ⇒ 整个工程解析失败），而且之后两次运行读到的「原始 sha256」都是
**已被污染**的值，于是「还原成功 MATCH」变成了**自证式假绿**。现在有三道加固：
① 动手前先把文件复制成 `.r3bak`，**还原只认这份备份**；
② 启动时若发现残留 `.r3bak` ⇒ **直接拒绝运行**（过时备份是回退雷）；
③ 注册 SIGTERM/SIGINT 处理，被打断也先还原；并且**基线必须先绿**才允许开始变异。

## §5 真实对局读数受控 A/B（`python work/_qa_928/diag_ab_928.py`）

用**变异杠杆**把同一份只读诊断在四种代码状态各跑一遍（30 场 / 同一 fixture / 全部落盘），
每跑完一条臂立刻按 sha256 核对还原：

| 指标 | **B 最终** | A0 上限退回整场预算 | A1 关掉整条链 | A2 绕行退回旧阈值 |
|---|---|---|---|---|
| 停滞占比 | **42.0%** | 41.9% | 55.6% | 45.0% |
| 爬行占比（<2px/tick） | **44.3%** | 44.9% | 57.7% | 51.9% |
| 卡住 ≥0.6s | **35 / 78** | 33 / 78 | 55 / 76 | 39 / 75 |
| 卡住 ≥10s | **15 / 78** | 14 / 78 | 20 / 76 | 18 / 75 |
| 最长连续停滞 | 336 | 336 | 297 | 254 |
| 卡住者 `_switch_attempts` 分布 | {0:32, 1:1, 3:2} | **{3: 33}** | {0:55} | {0:33,3:2,1:2,2:2} |

**读出来的三件事**：

1. **根因被确定性复现**：A0（只把上限退回整场预算）下，**33 个卡住单位的
   `_switch_attempts` 全部等于 3** —— 就是「换满就永久放弃」的签名。最终代码里
   该签名只剩 **2** 个（那 2 个是冷却期内的正常过渡态）。
2. **整条链的收益**：A1（关掉整条触发链 = 9.27 行为）停滞 55.6% → 42.0%（**-13.6pp**）、
   爬行 57.7% → 44.3%、卡住单位 55/76 → 35/78。
3. **绕行改动的独立收益**：A2（只退回绕行旧阈值）45.0% → 42.0%、爬行 51.9% → 44.3%、
   卡住 39/75 → 35/78。两个聚合指标同向改善，因此保留该改动。

★ **诚实注记（不许含糊）**：
- A0 与 B 在**聚合指标上几乎看不出差别**（41.9% vs 42.0%）—— 说明聚合停滞
  **主要由几何/挤压造成**，上限只决定「卡住之后会不会**永久**放弃」。
  换句话说：上限不是停滞的原因，是**停滞无法自愈**的原因。
- 最长连续停滞在 B 与 A0 **同为 336**，且比 A2(254)、A1(297) **更差** ⇒
  **真实对局仍会卡**，本轮是**显著减少**，不是消除。
- `units_tracked` 各臂不同（75/76/78）—— 修好后有单位活得更久/走位不同，
  「被统计到的单位」集合本身变了，**分母不可逐位对比**。
