--------------------------------
现象：教程里刷新刷几次之后就点不动 —— 按钮在、标着免费，按下去毫无反应（不是扣钱，是无响应）。
根因：刷新费用在客户端被算了**三遍**，「唯一判定源」当时只改了**两处**，漏了第三处
  scenes/prep/PrepUI.gd::_on_refresh_shop_control_pressed()（刷新按钮的前置判定）。
  它留着旧的 all_free := TreasureService.has_set("money")（少了 GameState.tutorial_mode）
  -> 教程里 cost 按 escalating_unit_price(uses) 递增 -> 超过金币就**静默 return**
  （不播燃烧动画、不刷新）。"刷几次才失效"是因为 shop_refresh_cost 在 uses<=0 时短路返 0
  （第一次永远免费），之后 10 -> 20 -> 40 递增，金币吃干即"死"。
改法：第三处接**同一个函数** TutorialMode.shop_refresh_all_free()（不是照抄同一串条件）。
新增门禁：tools/shop_refresh_free_source_check.gd/.tscn（19 项）
  A 费用档位 6 / B 教程恒免费 2（刷 999 次仍 0）/ **C 调用点同源 7（唯一能抓本次事故的一组）**
  / D 服务端分层反向哨兵 3。
  ★ C 递归扫 res://scenes 下**每一处** shop_refresh_cost( 调用点，要求所属函数体内出现
    共享谓词 —— 写死文件清单等于提前豁免下一次同类错。
  ★ 范围只到客户端层：服务端 EconomyLedger._shop_refresh 的 free 来自 payload 的
    owned_treasures（权威分层，不是重复），教学不走服务端，改用 D 组反向钉住。
变异实证：work/_qa_922/mutate_shop_refresh_925.py
  退回旧写法 -> 立刻红 2 条并**指名到** PrepUI.gd:2105 的 func，
  MUTATION_VERDICT OK red=True green=True restored=True（二进制读写 + sha256 逐字节还原）。
  ★ 排查中两个坑：① _func_start 只认 "func " 不认 "static func" -> 对全 static func 的文件
    回溯到文件头 class_name 行，报出的"所在函数"是假的；② escalating_unit_price(999) =
    10*2^998 **int64 溢出**，判据别用超大数验递增侧（all_free=true 侧短路返 0，用多大都安全）。

怎么自己复跑
------------
  1. 把 01_代码 / 02_文档 里的文件按相对路径覆盖回工程（或直接对比 sha256）。
  2. 批跑：python work/_qa_922/run_gates.py
  3. 单跑新探针：
     <godot>_console.exe --headless --path <工程> work/_qa_922/probe_blood_link_boss_immune_925.tscn
     通过行：PROBE_DONE checks=46 fail=0
  4. 回归定位（会临时改源码再按 sha256 还原，请先自行备份）：
     python work/_qa_922/bisect_925_regression.py
  5. 单跑 §14 新门禁：
     <godot>_console.exe --headless --path <工程> tools/shop_refresh_free_source_check.tscn
     通过行：CHECK_RESULT name=shop_refresh_free_source status=PASS checked=19 failures=0
  6. §14 变异实证（临时改 PrepUI.gd 再按 sha256 还原，结尾打印 MUTATION_VERDICT）：
     python work/_qa_922/mutate_shop_refresh_925.py
